# lib/pdf/ — 결과보고서 PDF

`report.ts` 한 파일. **담당자가 배포한 결과보고서 양식(`KODYS_G1/G2_결과보고서_양식.docx`,
2026-09-28)을 Letter 한 장짜리 PDF로 그린다.** 정답본(`KODYS_G*_결과보고서.docx`)과 레이아웃·글자
크기·색이 1:1이 목표라, 표·여백·색·간격은 전부 그 docx에서 읽은 값을 pt로 옮겨 적었고 학년마다
다른 값은 `SurveyForm.report`(`lib/forms/g*.ts`)가 갖는다. 이 저장소의 **공식 출력물은 관리자
결과지 화면이 아니라 이 PDF**다. 호출부는 둘이다 — 관리자용 `GET /api/admin/sessions/[id]/sheet.pdf`
(한 장)와 교사 결과지용 `GET /api/results/[token]/sheets.pdf`(여러 장을 한 파일로). 두 곳이 같은
함수를 쓰므로 관리자와 선생님이 받는 문서는 같다(`tests/sheet-input-parity.test.ts`).

종전의 「원본 검사지 PDF에 점수만 얹는」 스탬핑(`stamp-sheet.ts`, `lib/forms/*-layout.ts`,
`scripts/extract-form-layout.mjs`)은 2026-09-28에 폐기했다 — 담당자가 내려받는 문서의 양식을
결과보고서로 바꿨기 때문이다. 필요하면 git 이력에서 찾는다.

## 무엇을 채우나

| 칸 | 값 | 근거 |
|---|---|---|
| 지역 / 학교 | 도 지역은 학교 목록(`public/schools/<지역>.json`)의 소재지 `addr`에서 시·군을 뗀 이름(춘천시 → 「춘천」), 특별·광역시·세종은 도시 이름(「부산」「세종」) + 학교명(`placeLabel`·`schoolLabel`). 학교 이름이 지역으로 시작하면(대구성지초등학교) 지역을 겹쳐 적지 않고, 도의 시·군 이름이 광역시 약칭과 같으면 시도를 붙이고(경기 광주 ○○초등학교), 그래도 다른 학교와 표기가 같아지면(전국 3쌍, 상수 `DUP_LABELS` — 목록과 어긋나면 테스트가 잡는다) 도는 시도·광역시는 구를 더 붙인다(강원 고성 동광초등학교·부산 해운대구 송정초등학교). 목록에 없으면 시도 약칭 | 사용자 확정(2026-09-29) — 담당자 예시가 「춘천 교동초등학교」 |
| 학년 / 학기 | `N학년 M학기`, 학기는 검사일 월로(`lib/format`의 `semesterOf`) | 사용자 확정(2026-09-28), **담당자 회신 아님**. 담당자가 「학기별로 문항·기준이 다르다」고 했으므로 학기별 양식이 생기면 그 양식이 정한다 |
| 이름 · 성별 · 생년월일 · 검사일 | 세션 값. 날짜는 `2019. 03. 15.`처럼 월·일 두 자리(`birthLabel`·`reportDateLabel`, KST) | 양식 표기 |
| 결과 요약 | 해독·읽기유창성·쓰기 = `scoreSession`의 과제별 판정(읽기유창성은 어절/초 기준 — 숫자는 찍지 않는다), 최종결과 = `finalVerdict` | 최종결과 「FAIL이 2개 이상이면 FAIL」은 담당자 확정(2026-09-29 정정) |
| 결과 해석 및 권고 | 최종결과가 PASS/FAIL일 때의 문장 두 개(`INTERPRETATION`) | 담당자 확정(2026-09-28) — docx에 넣어 둔 문장 그대로. G1·G2 같은 문장 |
| 추가 관찰 정보 | 검사자 체크리스트 코드(`CHECKLIST_AREAS`)에 맞춰 ☑/☐ | 담당자 확정(2026-09-28) 「선생님이 체크한 거 그대로」. 표기 문구는 양식 것이라 화면 label/hint와 다르다 |

최종 규칙은 2026-09-28 회신(「1개 이상」)이 2026-09-29에 「2개 이상」으로 정정된 것이다 — docx의 FAIL
문구(「2개 이상의 영역에서 … 미통과」)와 예시 표(PASS·PASS·FAIL → 최종 PASS)가 정정된 규칙과 맞는다.

## 지키는 규칙

- **채점하지 않은 과제의 판정 칸은 비운다.** 없는 값을 FAIL로 찍으면 "채점하지 않았다"가
  "미통과했다"로 둔갑한다. 최종결과·해석 문장도 세 과제가 다 채점돼야 채운다(관리자 화면·교사
  결과지의 「판정 보류」와 같은 규칙).
- **양식 사이의 서식 불일치를 정리하지 않는다.** G1은 해석 문단이 1.15배 줄 간격에 체크리스트
  머리글이 「관찰 내용」, G2는 단일 줄 간격에 「주요 관찰 지표」이고 안내문 마침표도 다르다 —
  담당자 파일이 실제로 그렇고 정답본과 1:1이 요구사항이다(사용자 확정 2026-09-28).
  「인지」 행 설명만 서식 없는(10pt·검정) 것도 같다.
- **「임시 기준 · 확정 전」 표시를 싣지 않는다.** 담당자 양식에 그런 칸이 없다. Pass 기준이
  임시값(`passMark`)인 동안 그 사실은 관리자 화면의 표시로만 드러난다(`lib/scoring.ts`
  `PROVISIONAL_CRITERIA` 주석).
- **같은 입력이면 같은 바이트가 나와야 한다.** pdf-lib는 생성 시각과 서브셋 글꼴 이름을 호출마다
  새로 만드므로 둘 다 고정했다(생성·수정 시각 = 검사 시각, `customName`). 임상 문서라 재현
  가능해야 하고, 두 출력을 비교하는 테스트가 초 경계에서 흔들리면 안 된다.

## 글꼴 — 저작권

양식이 쓰는 맑은 고딕(본문)·Segoe UI Symbol(☐ ☑)·Times New Roman(서식 없는 문단의 라틴 글자)은
전부 Microsoft 전용 글꼴이다. Windows·Office 사용권은 그 기기의 문서 안에서 쓰는 것까지이고,
글꼴 파일을 저장소에 넣어 서버(Vercel)에서 임베드하는 것은 재배포라 허용되지 않는다. 그래서:

- 글자는 **나눔고딕**(OFL, `assets/fonts/NanumGothic*.ttf`, 라이선스 `OFL.txt` 동봉)으로 그린다.
- **줄 높이·베이스라인은 Word 출력 실측값이다**(2026-09-29, 담당자 양식을 Word for Mac에서 PDF로 저장한
  것과 대조). Word는 맑은 고딕 줄을 글자 크기의 **1.72배**로 잡고(글꼴 표의 hhea 1.33배가 아니다 — 위에
  0.39em 여유를 둔다) 베이스라인을 줄 위에서 1.33em에 두며, 서식 없는 빈 문단은 문단 기호 글꼴(Times New
  Roman 10pt) 기준 11.75pt, 표 행은 테두리 굵기 0.5pt만큼 더 높다. 이 모델로 머리글·인적사항·요약·소제목·
  체크리스트·꼬리말의 행 경계선과 글자 베이스라인이 Word와 0.5pt 안에서 맞는다. 검증은 양식 docx를 Word로
  PDF 저장한 뒤 pdfplumber로 두 PDF의 행 경계선·글자 베이스라인을 뽑아 대조하는 방식으로 다시 할 수 있다.
- **줄바꿈은 맑은 고딕의 글자 진행 폭**으로 판단한다(한글 1em, ASCII·기호는 `MALGUN_ADV` 표, 실측
  2026-09-29). 나눔고딕 한글은 0.94em이라 이렇게 하지 않으면 미통과 해석 문단이 Word의 4줄 대신 3줄이 된다.
  진행 폭은 글꼴 프로그램이 아니라 숫자라 적어 둘 수 있다. 그 결과 줄은 Word와 같은 곳에서 나뉘고,
  글자가 조금 좁아 줄 오른쪽에 여유가 남는 것이 남은 차이다.
- 확인란 ☐ ☑은 글리프 대신 선으로 그린다(나눔고딕에 없다).

맑은 고딕과 같은 모양이 꼭 필요하면 담당자 조직이 서체 사용권을 확보한 뒤 글꼴 파일을 교체하면 된다
(`renderReport`의 `embedFont` 두 줄).

## 세부

- 좌표는 위에서 아래로 잰다(docx와 같은 방향). pdf-lib 원점은 좌하단이라 `Y()`가 뒤집는다.
- 줄바꿈은 한글은 글자 단위, 라틴 문자·숫자는 낱말 단위이며 문장 부호는 줄 머리에 두지 않는다
  (Word의 한국어 문서 동작). 학교명·이름이 길면 칸 안에서 줄이 늘어난다 — 잘라내지 않는다.
- 서버 전용이다. `node:fs`로 `assets/fonts`·`public/schools`를 읽으므로 클라이언트 컴포넌트에서
  import하지 말 것. 두 라우트가 서버리스 번들에 그 파일을 싣도록 `next.config.ts`의
  `outputFileTracingIncludes`에 등록돼 있다.

테스트: `tests/report.test.ts`(pdfjs로 글자를 뽑아 대조), `tests/sheet-input-parity.test.ts`.

## 빈 칸의 줄 높이

채점 전 과제의 빈 판정 칸과 최종결과가 없을 때의 빈 해석 상자도 **그 칸의 글꼴 크기**(12·14pt 굵게, 해석은 본문 크기 2줄)로
높이를 잡는다(`wrap`의 `lineOf`, 2026-10-01). Word는 빈 칸을 문단 기호 글꼴로 줄을 잡는데, 기본 10pt로 떨어뜨리면 채점 전
결과보고서만 아래가 위로 당겨져 한 반을 한 파일로 받았을 때 아이마다 세로 배치가 달라진다. `tests/report.test.ts`가
「추가 관찰 정보」 제목의 y를 채점 완료본과 대조한다.
