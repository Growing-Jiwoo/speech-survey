# lib/ — 순수 로직 · 서버 유틸

프레임워크 의존이 얇은 순수 함수/모듈 계층. **화면(components)·라우트(app/api)에 로직을 두지 않고
여기로 추출해 node 환경 vitest로 테스트한다**는 것이 이 저장소의 핵심 관례다(tests/ 참고).

## 도메인

| 파일 | 역할 |
|---|---|
| `items.ts` | `itemsFor(양식)` — 문항(채점 단위)과 **페이지 모델**(화면·녹음·제한시간 단위), 진행률 분모를 양식에서 만든다. 문항은 학년마다 다르므로 모듈 상수가 아니다 |
| `forms/` | 학년별 검사지 정의(문항·배점·제한시간·임시 Pass 기준)와 결과보고서 PDF의 학년별 서식(`report`). `formForGrade(학년)`으로 조회 — 새 학년은 `g*.ts` + 원본 검사지 PDF(문항 대조용) 추가로 끝난다. ⚠️ **클라이언트 코드(`'use client'` 화면과 그것이 값으로 import하는 lib)에서 값으로 import하지 말 것** — `/_next/static`의 JS 청크는 인증 없이 누구나 받으므로 문항 전체가 공개 파일이 된다. 화면은 양식을 서버 응답으로 받는다(검사 화면 `POST /api/sessions/form`, 관리자 결과지 상세 API의 `form`). `import type`은 번들에 남지 않으니 괜찮다. `npm run build`가 끝에 `scripts/check-client-bundle.ts`로 청크를 검사해 새면 빌드를 실패시킨다 |
| `survey-flow.ts` | 페이지 게이팅. 중단 규칙(①·②)과 낱말 해독 현장 채점이 전면 폐기됐다 — **근거가 규칙마다 다르다**: 현장 채점 제거는 담당자 확정(2026-08-13), 규칙 ①은 담당자 회신이 근거, 규칙 ②(쓰기 중단)는 **담당자 확정(2026-08-22)**이다 — 2026-08-13에는 사용자 확정이라 재확인 대상이었으나 담당자가 「즉시 중단 기능 제거」가 ②를 포함한다고 확정했다(파일 상단 주석 참고). 낱말 해독·문장 읽기유창성은 검사 화면이 수집만 하고 판정·채점은 관리자 결과지가 한다. 다만 쓰기(낱말 쓰기·문장 쓰기)는 예외로, 녹음이 없어 검사 중 검사자가 계속 입력한다(사용자 확정 2026-08-13, `WritingPage.tsx`·`SentenceWritingPage.tsx`). `visiblePages`(연습 실시 여부만 반영)·`canAdvance`(문항 완료 여부로 [다음] 활성화 판단 — 쓰기 방식이 스캔본이면 쓰기 페이지는 입력 없이 통과) |
| `scoring.ts` | 배점·합산·Pass/Fail·**최종결과**(`finalVerdict` — Fail이 2개 이상이면 Fail, 담당자 확정 2026-09-29)와 **과제별 채점 완료 여부**(`complete`). 배점은 전부 **어절 수**에서 유도한다(`itemMaxWords`) — 검사지 숫자를 옮겨 적지 않는다. **문장 읽기유창성 총점만 어절/초**다(정확 어절 합 ÷ 읽은 시간 합, 담당자 확정 2026-09-29) — 만점이 없어 `taskMax`에서 빠지고(`CountTaskKey`) 정확 어절 만점은 `sentenceWordsMax`가 갖는다. 반올림(`FLUENCY_DECIMALS`)·읽은 시간 입력 규칙(`parseReadSec`·`isValidReadSec` — 입력 칸과 저장 라우트가 공유, 상한 `readSecMax`는 녹음 길이라 오타 방지일 뿐)도 여기. 저장된 행을 채점 입력으로 바꾸는 `scoreInputFrom`, **미녹음 페이지를 오반응(X·0점)으로 고정하는** `withUnrecordedFixed`(관리자 화면·결과보고서 PDF·교사 결과지가 공유. **저장값이 있어도 덮는다** — 들을 녹음이 없어 채점자 값은 근거가 없다, 사용자 확정 2026-09-29. 문장의 읽은 시간은 제한 시간으로 `unrecordedTimes`, 20초·0어절은 담당자 확정 2026-09-29. 저장하지 않고 파생한다. 관리자 결과지가 잠글 칸은 `unrecordedItemCodes`)도 여기 |
| `schema.ts` | 세션 생성 입력의 zod 스키마 — **검증 규칙의 단일 소스**(서버 라우트가 사용). `sessionCreateSchema`는 `sessionCreateFromRosterSchema`(명단 모드, 이름·생년월일 필드 자체가 없다)와 `sessionCreateDirectSchema`(직접 입력, 기존 `SessionCreateInput` 타입)의 `z.union`(Task 13) — 명단 스키마를 먼저 시도하도록 순서를 둬 `fromRoster:true`에 신원 필드를 함께 보내도 그 필드를 조용히 벗기지만, 신원 위조 방지 자체는 순서에 기대지 않는다: `sessionCreateDirectSchema`가 `fromRoster: z.undefined().optional()`을 가져 `fromRoster:true`인 바디는 유니온을 뒤집어도 direct 스키마를 통과할 수 없다(코드리뷰 후속, 2026-08-18). 학급 코드 알파벳(`CODE_ALPHABET`)·길이(`CODE_LEN`)도 여기가 단일 소스 — 발급(`class-code.ts`)과 입력 검증이 공유. 학급 코드 공통 필드는 `classCodeFields`로 분리해 관리자 직접 발급(`classCodeCreateSchema`)과 교사 신청(`applySchema`)이 공유한다 — `.refine()`이 걸리면 `.extend()`가 안 되기 때문. 이메일은 이제 **직접 발급도 필수**다(사용자 확정 2026-09-22) — 결과지 링크가 `teacher_email`로만 가므로 이메일 없는 학급은 발급 경로와 무관하게 결과를 받을 방법이 없어져, 종전 「전화·이메일 둘 중 하나」와 `applySchema`의 대비가 사라졌다. `classCodeEmailSchema`(담임 이메일만 받는 관리자 수정 바디)와 `resultsRequestSchema`(교사 결과지 링크 요청, 코드만 받음)도 여기 |
| `class-code.ts` | `generateClassCode()` — 학급 코드 생성(서버 전용, `node:crypto`의 `randomInt`). 알파벳·길이는 `schema.ts`를 import — 여기서 다시 적지 않는다 |
| `validate.ts` | `schema.ts`를 감싼 클라이언트 폼용 boolean 타입가드 파사드 |
| `survey-state.ts` | 참여자 진행 상태의 localStorage 저장/복원. 쓰기 방식(`writingMode`)도 여기 — 검사에서 고른 값이 없으면 **이 기기에서 이 학급에 마지막으로 고른 방식**(`writingModePref`, 마이크 확인과 같은 기기 키라 `clearState`가 지우지 않는다. 다른 학급에는 넘어가지 않는다 — 컴퓨터실 PC를 여러 반이 쓴다)을 쓴다(`resolveWritingMode`, 사용자 확정 2026-09-30). 쓰기 페이지를 떠날 때 그 방식을 검사에 고정한다. 방식이 없는 옛 상태를 버리지 않게 스키마 버전은 올리지 않았다. 스키마 버전(`v`)으로 구버전 상태를 폐기한다. **아동 이름과 번호를 저장한다**(진행 화면·이어하기 안내용) — 공용 기기에 흔적이 남지 않도록 제출 완료·새 검사 시작·종료 화면에서 반드시 `clearState`로 파기할 것. 마이크 확인 통과 시각(`saveMicOk`/`recentMicOk`)은 학급 코드와 같은 **기기 키**라 `clearState`가 지우지 않는다 — 같은 PC·헤드셋으로 한 학급을 연달아 검사할 때 아이마다 마이크 확인을 시키지 않기 위한 것이고(사용자 확정 2026-09-22), 담는 값이 시각 하나뿐이라 아동 정보가 아니다. **끊긴 업로드**: 올리는 중인 녹음을 `pendingUploads`(페이지 → 시도 번호들)에 적고(`withPendingUpload`) 끝난 시도만 뺀다(`withoutPendingUpload`). 다시 열었을 때 이 탭에서 올리고 있지 않은 시도는 `settleLostUploads`가 「녹음 완료」 표시에서 거둔다. 업로드 결과는 화면이 사라진 뒤 도착할 수 있어 `updateSavedState`(세션 id로 저장 상태를 직접 고침)로 반영한다. `LAST_KEY`는 탭 가드(`hooks/useOtherTabGuard`)가 본다 **종료 화면용**: `markSubmitted`/`takeSubmitted`(검토 화면이 제출한 세션 id를 sessionStorage로 넘김)·`clearSessionState`(그 세션 키만, `LAST_KEY`는 그 세션일 때만 지움 — 2026-10-08) |
| `results.ts` | 교사 결과지 표의 순수 로직(DB·HTTP를 모른다) — 상태 판정·명단∪세션 병합·정렬·요약·파일명. 채점은 **관리자 결과지와 같은 함수 사슬**을 쓴다(`scoreInputFrom → withUnrecordedFixed → scoreSession → sheetPdfGate`) — 여기서 규칙을 새로 만들지 않는다. 쓰기가 채점 전이면 `verdict`를 **보류(null)**하고 `complete`로 그 사실을 넘긴다 — 미채점 0점으로 아동을 낙제시키지 않기 위함이다(사용자 확정 2026-09-22 「관리자와 동일」 A안. 담당자 회신이 아니다) `latestScored`(아이당 **받을 수 있는 것 중 최신** 세션)는 `latestSession`과 다르다 — 판정 표시는 최신 세션만 보지만(채점 중인 재검사가 옛 판정을 가리지 않게), 다운로드와 「채점 완료」 집계는 `latestScored`를 쓴다(중단된 재검사가 앞 차수 결과지를 가리면 안 된다. 전수 점검 2026-09-22). |
| `results-view.ts` | `results.ts`에서 떼어 낸 **화면용** 타입과 순수 헬퍼(`latestSession`·`latestScored`·`childVerdict`·`summarize`). 쓰기 스캔본(2026-09-30): 화면 상태 `sessionLabel`(스캔 대기 → 채점 중 → 채점 완료 — 받을 수 있는지를 뜻하는 `status`와 **따로 둔다**), 받을 때 경고 대상 `awaitsScanWriting`, 스캔본이 붙을 검사 `scanTargetSession`(가장 최근에 **제출된** 검사)·`scanTargets`(검사가 둘 이상인 아이는 `retest` — 확인 화면이 자동으로 붙이지 않는다). 대상 id를 주면 `sessionLabel`이 대상이 아닌 앞 차수의 스캔 대기를 **재검사로 대체**(`replaced`)로 가른다. `summarize`는 칸(채점 완료·채점 중·스캔 대기·미제출)과 별도로 **받을 수 있는 수**(`downloadable`)를 센다 — 스캔 대기인 아이도 읽기 채점이 끝났으면 받을 수 있어(A안) 두 수가 다를 수 있다. 교사 결과 화면(`ResultsView`)이 이것만 import한다 — `results.ts`는 채점 사슬 때문에 `forms/`를 값으로 import하므로 화면이 그것을 import하면 문항이 공개 JS에 실린다. `results.ts`가 다시 내보내므로 서버 쪽 호출부는 그대로 `results`에서 가져온다 |
| `adminStats.ts` | 관리자 목록의 KPI·학교별 집계·필터/정렬·URL(searchParams) 직렬화. KST 일자 키(`kstDateKey`) 기준 "오늘" 판정. 상태 필터 `scanReady`(`awaitsScanScoring` — 스캔본이 올라왔거나 종이로 채점을 시작했는데 쓰기 채점이 남음, 목록의 파란 「스캔본 채점」 배지와 같은 조건). 진행률은 여기서 계산하지 않고 행의 `progress`를 읽는다(아래 `session-progress.ts`) |
| `qr.ts` | QR 부호기(ISO 18004 — 바이트 모드, 버전 1~6, 오류 정정 M/Q, 마스크 벌점 선택). **외부 라이브러리 없이** 직접 구현했다 — 쓰기 기록지 한 장에 한 개, 짧은 글자열뿐이라 필요한 범위가 좁다. `tests/fixtures/qr-vectors.json`(segno)과 모듈 단위로 대조한다. `qrSvgPath`가 SVG 경로 하나로 그린다(인쇄 선명도) |
| `writing-sheet.ts` | 쓰기 기록지의 「기계용 이름표」 — QR 글자열 `SHEET-W:<반 표시>:<번호>`(학급 코드·이름·주소를 **싣지 않는다**, 사용자 확정 2026-09-30 · 검사 이름도 싣지 않는다 2026-10-01)와 판독(`parseSheetQr`), 반 표시(`classSheetTag` — 학급 id의 SHA-256 앞 8자리, 비밀이 아니다), 인쇄 목록(`sheetEntries` — 명단 학생 + 번호만 찍힌 기록지, 번호가 겹치면 이름 있는 쪽)·번호 범위. 쓰는 칸 모양(`SheetLayout`)은 종류와 개수만 — 문항을 싣지 않는다 |
| `scan-mapping.ts` | 올린 스캔본의 쪽마다 **누구 기록지인지** 정하는 순수 로직 — 검사 한 건의 쓰기 상태(`scanTargetState`: wait·uploaded·scored·screen·unsubmitted, 담당자가 쓰기를 하나라도 넣으면 scored라 선생님이 못 바꾼다), QR로 자동 연결(`proposeMapping` — 순서로 짝짓지 않는다, 한 아이에게 한 장, 다른 반·검사 없음·화면 입력·채점됨·제출 전·**빈 쪽**은 「올리지 않음」, **재검사한 아이는 선생님이 확인해 고른다** — QR에 차수가 없다, 사용자 확정 2026-10-01), [올리기] 가능 여부·빠진 아이(`mappingStatus`), 드롭다운 후보(`candidatesFor`) |
| `sheet-cache.ts` | 관리자 결과지 저장이 성공한 뒤 상세 캐시(react-query)를 **서버가 저장한 모양 그대로** 고친다(`patchDetail` — 낱말 O/X는 upsert, 문장 읽기 어절·시간은 문장 읽기 코드 안에서 교체, 쓰기는 보냈을 때만 쓰기 코드 안에서 교체). 안 고치면 목록을 다녀와 다시 연 결과지가 옛 캐시로 초기화되고 다음 자동 저장이 방금 저장한 채점을 덮는다. 다시 받지 않는 이유는 서명 URL이 바뀌어 듣던 녹음·보던 스캔본이 다시 불러와지기 때문. 서버 규칙과의 일치는 채점 라우트를 메모리 표로 그대로 돌려 대조하는 계약 테스트(`tests/sheet-cache-contract.test.ts`)가 지킨다 |
| `session-progress.ts` | 관리자 목록 행의 진행률(녹음·쓰기 몇 개가 들어왔나, 학년별 분모). 스캔본 방식의 빈 쓰기는 미완료로 세지 않는다(`scan` — 목록은 빨간 0/10 대신 스캔본이 올라왔거나 종이로 채점을 시작했으면 「스캔본 채점」, 아직이면 「스캔 대기」. 쓰기가 하나라도 들어가면 선생님은 더 올릴 수 없으니 기다리는 상태가 아니다). **서버 전용** — 학년별 문항 코드가 필요해 `forms/`를 import한다. `listSessions`가 행마다 계산해 `progress`로 싣는다(종전에는 목록 화면이 계산해 문항이 공개 JS에 실렸다) |
