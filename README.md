# 아동 읽기 선별검사 웹

아이가 낱말·문장을 소리 내어 읽으면 녹음 파일을 저장하고, 쓰기 과제(G1 낱말 쓰기 예/아니오,
G2 문장 쓰기 0·1·2)와 검사자 체크리스트를 받는 읽기 선별검사 도구. 쓰기는 아이마다 **화면에서 바로
표시**하거나 **기록지 스캔본으로 올려** 담당자가 채점하게 할 수 있다(아래 「쓰기 스캔본」).

- **STT(음성 인식)는 사용하지 않는다** — 녹음의 완료 여부만 추적한다.
- 참여자는 자기 녹음을 다시 듣지 않는다. 채점은 관리자 결과지(`/admin`)에서 녹음을 직접 청취해 수행한다.

## 화면 흐름

| 경로 | 대상 | 내용 |
|---|---|---|
| `/` | 아동(교사 보조) | 학급 코드 입력 → 신청 명단이 있으면 아동 드롭다운에서 선택(이름·성별·생년월일은 서버가 명단에서 복사), 명단이 없으면 번호·이름·성별·생년월일 직접 입력 → 확인 모달("이 정보가 맞나요?") → 세션 생성 · 학급 배너에 「검사 완료 N명」과 교사용 [결과지 받기 →] · [쓰기 기록지 인쇄 →](스캔본 방식 반의 기록지) · 스캔 대기가 있으면 「스캔 대기 N명」 |
| `/survey` | 아동 | 마이크 확인 → 연습 실시 여부 선택 → 문항 진행(녹음은 완료 즉시 표시하고 백그라운드 업로드) · 쓰기 단계에서 방식 선택(화면에서 바로 표시 / 스캔본으로 올리기) |
| `/review` | 아동 | 문항별 완료 여부 검토 → 최종 제출 |
| `/admin` | 관리자 | 로그인 → 세션 목록(검색·필터·정렬, 아동 번호 포함) → 결과지(녹음 청취·채점·세션 삭제 · 스캔본 방식 검사는 스캔본을 보며 쓰기 채점·연결 해제) → `/admin/codes` 진입 링크 |
| `/admin/codes` | 관리자 | 학급 코드 발급(학교·학년·반·담임교사명·연락처 입력 → 6자리 코드 생성) → 발급 목록(세션 0건 코드만 삭제 가능) + 신청 대기(pending) 목록 검토(명단 보기)·승인(→ active, 코드 메일 발송)·거절(= 삭제, 명단까지 cascade) |
| `/apply` | 공개(교사) | 교사가 학급 정보와 명단 파일을 올려 신청하면 대기 상태(pending) 학급 코드가 만들어지고, 관리자 승인 후 이메일로 코드가 전달된다 |
| `/results/[token]` | 교사 | 학급 결과지. 시작 화면 배너의 [결과지 받기 →]가 담임 메일로 보낸 링크(학급 스코프 토큰, 14일)로만 진입. 요약 한 줄 · 아이별 행(재검사 펼침) · [전체 PDF 다운로드]/[선택한 검사 다운로드] · 쓰기 스캔본 올리기. 판정은 관리자와 같은 양호·주의·위험, 읽기 채점이 끝난 검사를 내려받는다(쓰기 채점 전이면 받을 때 경고) |

학교·학년·반·담임·연락처는 **관리자 직접 발급**(`/admin/codes`)과 **교사 신청→승인**(`/apply` →
관리자 승인) 두 경로 중 하나로 채워진다 — 어느 경로든 **한 번만 입력**한다. 세션 생성 시 서버가
코드를 다시 조회해 그 학급 정보를 `sessions`에 복사한다(비정규화: 코드를 나중에 고쳐도 이미 만든
세션은 검사 당시 값을 유지). 아동 개인 신원(이름·성별·생년월일)은 여기 더해 **세 번째 소스**를
갖는다 — 교사 신청이 함께 올린 명단(`class_roster`)이 있으면 시작 화면이 드롭다운으로 번호만
받고 나머지는 서버가 명단에서 복사하며(명단 모드), 명단이 없거나 「명단에 없는 학생이에요」로
빠지면 기존처럼 화면에서 직접 입력받는다(직접 입력 모드). 진행 상태는 localStorage에 저장돼
새로고침·탭 닫힘 후에도 같은 문항에서 재개된다.

## 문항 구성 — 학년·학기별 검사지

검사지가 학년과 학기마다 다르다. **세션을 만들 때** 학년과 검사일의 학기(3~8월 1학기 · 9~2월 2학기, 담당자 확정
2026-10-20)로 양식을 골라 세션 행에 적고(`sessions.form_id`, migration 008 — lib/forms `formFor`), 그 뒤로는 그 양식이
문항·배점·판정 기준을 전부 정한다(`formOfSession`). 학기가 바뀌거나 양식이 늘어도 끝난 검사는 검사 당시 문항으로 다시
그려진다. `form_id`가 없는 세션(migration 008 이전)은 학년만으로 고르던 옛 규칙(`formForGrade`)으로 읽는다.

| | KODYS-G1 (초1) | KODYS-G2 (초2) |
|---|---|---|
| 낱말 해독 | 의미 7 + 무의미 7 = /14, **페이지당 20초** 녹음 | 같음 |
| 문장 읽기유창성 | 4문항, **문항당 20초**(2학기는 3·4번 **30초**) 녹음 · 총점 = 정확 어절 ÷ 읽은 시간(초) × 10 = **10초당 어절** · 정확 어절 1학기 /36 · 2학기 /48 | 4문항, 정확 어절 1학기 **/35** · 2학기 **/45** |
| 쓰기 | **낱말 쓰기** 10문항, 낱말당 1점 = /10 | **문장 쓰기** 5문항, **어절당 1점(0·1·2)** = /10 |
| 검사자 체크리스트 | 발달 영역 다중 선택(선택) | 같음 |
| 총 문항 | 29 | 24 |

| 양식 | 문항 원본 | 판정 기준 |
|---|---|---|
| `KODYS-G1` · `KODYS-G2` (1학기) | `assets/forms/kodys-g*.pdf` — **1학기 문항은 바뀔 예정**(담당자 2026-10-20) | 임시값(개발 판단) — 화면에 「임시 기준 · 확정 전」 |
| `KODYS-G1-S2` · `KODYS-G2-S2` (2학기) | 담당자 docx(2026-10-19) | 담당자 기준표(2026-10-19) |

3~6학년 검사지는 아직 받지 못해 **같은 학기의 1학년 양식**으로 폴백한다 — 결과지·인쇄물에 양식이 찍혀 어떤 양식으로
검사·채점했는지 드러나고, 1학년 기준으로 판정되므로 화면에 「임시 기준 · 확정 전」이 붙는다(lib/scoring `criteriaProvisional`).
그래서 **교사 신청(`/apply`)은 1·2학년만 받는다**(담당자 확정 2026-10-22, `lib/format.ts` `APPLY_GRADES`) — 3~6학년 학급은
관리자 직접 발급으로만 생긴다.
새 1학기 문항이 오면 기존 양식을 고치지 말고 **새 id로 추가**한다 — 기존 id로 검사한 세션이 그 문항을 계속 가리켜야 한다.

문항 정의는 코드 상수 `lib/forms/g*.ts`에 있고(DB 시드 아님), `lib/items.ts`의 `itemsFor(양식)`이
문항·페이지·집계 분모를 만든다. **검사지 PDF가 절대 기준이다** — 코드와 다르면 언제나 검사지가 옳다.

🔒 **실제 문항은 암호문으로만 커밋한다**(사용자 확정 2026-10-20 — 저장소를 포트폴리오로 공개해 두려고). `lib/forms/g*.ts`의
낱말·문장은 **실제와 모양이 같은 가짜 문항**이고, 실제 문항은 `lib/forms/sealed.ts`(AES-256-GCM 암호문)에 있다. 키
`FORMS_KEY`가 있으면 서버가 모듈을 읽을 때 풀어 갈아 끼운다(`lib/forms/index.ts`) — 키는 Vercel 환경 변수와 개발자
`.env.local`에만 있다. 키가 없으면 가짜 문항으로 돌고(공개 저장소를 받은 사람·테스트), **Vercel에서 키가 없으면 빌드가
실패한다**(아이가 가짜 낱말로 검사받지 않게). 검사지 원본 PDF도 저장소에 두지 않는다(`private/`, git 제외).

| 할 일 | 명령 |
|---|---|
| 실제 문항 고치기 | `npm run forms:unseal` → `private/forms.json` 수정(문항 `forms`와 검사지 대조값 `sheet` 둘 다) → `npm run forms:seal` → `npm test`(키가 있어야 `tests/forms-sealed.test.ts`가 글자 단위로 대조한다) |
| 새 PC에서 개발 | `.env.local`에 `FORMS_KEY`(저장소 주인에게 받는다). 검사지 PDF는 따로 받아 `private/forms/`에 |

**문항은 공개 JS에 싣지 않는다.** 화면(검사·검토·관리자)은 `lib/forms`를 import하지 않고 양식을 서버
응답으로 받는다 — 검사 화면은 세션 토큰을 보내 `POST /api/sessions/form`에서, 관리자 결과지는 상세 API의
`form`에서. `/_next/static`의 JS 청크는 인증 없이 누구나 받을 수 있기 때문이다. `npm run build`가 끝에
`scripts/check-client-bundle.ts`로 청크를 검사해, 문항이 새면 빌드(= Vercel 배포)를 실패시킨다.

⚠️ **제한 시간만은 예외다(담당자 확정 2026-09-21).** 검사지에는 낱말 30초·문장 40초로 인쇄돼
있지만 그것은 **한 화면에 다 제시할 때**의 값이다 — 낱말 14개를 한 번에, 문장 4개를 한 눈에
보여주고 재던 시간이다. 이 앱은 「한 페이지 = 한 과제 = 한 녹음」이라 낱말을 의미/무의미 두
페이지로, 문장을 문항당 한 페이지로 쪼개므로 **페이지당 20초로 재배분**했다. 같은 문항에 아이가
쓰는 총 시간은 오히려 늘어난다(낱말 30→40초, 문장 40→80초). 1학기 양식은 담당자의 「일단 다 20초」 그대로이고,
**2학기 양식은 문장 1·2번 20초, 3·4번 30초다**(담당자 확정 2026-10-20 — 3·4번이 두 문장짜리라 길다, 「학년 동일하게」).
제한 시간은 문장마다 `limits.sentenceSec[i]`로 두고, 녹음 자동 종료·녹음 없는 문장의 시간·읽은 시간 입력 상한이 모두 그
문장의 값을 따른다.
검사지 PDF의 30초·40초 인쇄 문구는 담당자가 새 파일을 주기로 했다. 내려받는 결과보고서 PDF에는
제한 시간이 찍히지 않으므로 출력물에는 영향이 없다. 화면과 채점 기준은 20초를 따른다.

⚠️ **문장 읽기유창성의 총점도 예외다(담당자 확정 2026-09-29, × 10은 2026-10-20).** 검사지는 「정확하게 읽은 어절 수로
채점」(총점 /36)이지만, 총점은 **정확하게 읽은 어절 수의 합 ÷ 읽은 시간(초)의 합 × 10**이다 — 단위 10초당 어절,
담당자 예시로 20어절을 10초에 읽으면 20.00(원문 「10초당 정확하게 읽은 어절 수! 20어절 ÷ 10초 * 10」). 시간은 관리자가 녹음을 듣고 문장마다 직접
넣는다(`sentence_times`) — 녹음 길이로 채우지 않는다(담당자: 녹음된 초는 정확하지 않다). 만점이 없는
비율이라 화면은 `/36`을 붙이지 않는다. 제한 시간(20초, 2학기 문장 3·4번 30초)을 넘겨 읽었을 때 어디까지 셀지도 앱이 정하지 않고 담당자가
듣고 판단한다 — 입력 상한(문장마다 제한 시간 + 5초 — 25초, 2학기 3·4번 35초)은 녹음 최대 길이라 오타만 막는다. 총점은 소수 둘째 자리까지(셋째에서
반올림, 판정도 그 값으로)다 — 담당자 확정(2026-09-29), cut-off를 같은 자리에서 본다. 2학기 기준은 1학년 주의 8.12 ·
위험 5.43, 2학년 주의 8.04 · 위험 7.10이다(담당자 확정 2026-10-19, 최종본 2026-10-20 — 1학년 주의는 처음 받은 8.04를 8.12로 정정).

⚠️ **판정은 양호·주의·위험 3단계다(담당자 확정 2026-10-19).** 기준표의 두 값 「영역별 Fail(Youden)」·「완전 Fail(−1SD)」
**이하**면 각각 주의·위험이고, 최종결과는 위험이 하나라도 있거나 주의가 2개 이상이면 위험, 주의가 1개면 주의다
(lib/scoring `verdictOf`·`finalVerdict`). 종전 「FAIL 2개 이상 → FAIL」(2026-09-29)은 위험 조건 안에 그대로 남는다.
2학기 문장 3·4번(15·18어절, 2학년은 11·17어절)은 제한 시간이 30초다(담당자 확정 2026-10-20, 위 「제한 시간」).

⚠️ **시행 절차는 담당자 회신이 인쇄 문구를 이긴다.** 검사지에 인쇄된 중단 규칙(3연속 오반응 시
중단 등)은 **적용하지 않는다** — 중단·현장 채점이 폐기됐고(현장 채점 제거는 담당자 확정
2026-08-13, 중단 규칙 ②는 담당자 확정 2026-08-22 — 「즉시 중단 기능 제거」가 ②를 포함한다는
확정), 아동이
힘들면 **녹음 버튼을 다시 누르거나 헤더의 [일시정지]를 눌러** 멈춘다(그때까지 녹음 저장 —
둘 다 같은 규칙). 일시정지는 녹음 중에도 눌린다(담당자 확정 2026-09-21: 신청 화면 안내가
「일시정지 버튼을 눌러 언제든 멈출 수 있습니다」라고 말하므로). 누르면 녹음을 먼저 끊고
화면을 덮는다 — 안 끊으면 아이가 그만둔 뒤의 침묵까지 그 시도에 담긴다. 녹음 중에 화면이 가려지거나(태블릿 홈 버튼·알림·잠금)
문항 화면에서 뒤로 가기(아이패드의 왼쪽 가장자리 쓸기·안드로이드 뒤로 버튼 포함)를 해도 일시정지와 같이 멈춘다 — 화면을
떠나는 길은 헤더의 [저장하고 나가기]다(사용자 확정 2026-10-21 — 태블릿 점검, 담당자 회신 아님). 뒤로 가기를 받을 칸은
화면을 처음 누를 때 쌓는다 — 브라우저는 누르기 전에 스크립트가 쌓은 기록을 뒤로 가기에서 건너뛴다(`app/survey/page.tsx`). **낱말 해독·문장 읽기유창성
채점은** 관리자 결과지에서 한다. 다만 **쓰기 채점(낱말 쓰기·문장 쓰기)은 예외다** — 쓰기는
녹음이 없어 검사자 입력이 유일한 채점 경로이므로 검사 중 검사자가 계속 입력하고
(`components/survey/WritingPage.tsx`, `SentenceWritingPage.tsx`), 관리자 결과지는 그 값을
읽기 전용으로 표시만 한다(사용자 확정 2026-08-13). 근거:
`docs/superpowers/specs/2026-08-13-admin-only-scoring-and-class-codes-design.md`.
단 쓰기를 **스캔본으로 올리기**로 고른 검사는 아이가 기록지에 쓰고 **담당자가 스캔본을 보고
채점한다** — 그 검사만 관리자 결과지에서 쓰기를 입력할 수 있다(아래 「쓰기 스캔본」).

## 미녹음의 표기

| 화면 | 상황 | 표기 |
|---|---|---|
| 검토(검사자) | 검사자가 [모르겠어요]로 넘김 | **「모르겠어요」**(amber) · **미완료 수에 넣지 않는다** |
| 검토(검사자) | 녹음도 없고 넘기지도 않음(새로고침으로 잃은 녹음 포함) | 「미녹음」(rec) · 미완료 수에 포함 |
| 검토(검사자) | 올리기에 실패해 [다시 저장]을 기다리는 녹음(이 탭) | 「저장 실패」(rec) · 미완료 수에 포함 — 번호를 눌러 그 화면에서 [다시 저장](2026-10-12) |
| 관리자 결과지·결과보고서 PDF | **둘 다** | 오반응(X·0점)으로 **고정 채점**(칸이 잠긴다) · 문장의 읽은 시간은 **제한 시간(20초)** |
| 관리자 결과지 | 그 가운데 **녹음을 시도했는데 서버에 올라오지 않은 것**(업로드 실패·끊긴 업로드) | 「미녹음」 배지 대신 **「저장 실패」** — 채점은 위와 같다. 결과보고서 PDF에는 구별해 넣지 않는다 |

「저장 실패」는 **표시만** 더한 것이다(사용자 확정 2026-10-08, 담당자 회신 아님). 검사 기기가 녹음을 시도한
페이지를 진행 상태에 적어(`attempted`) 제출 때 보내고, 제출 라우트가 그 가운데 녹음이 하나도 없는 것을
`sessions.upload_failed`(migration 007)에 적는다. 결과보고서 PDF는 담당자 양식이라 넣지 않았다 — 넣으려면
담당자에게 물을 것. 도입 전 검사·시도 기록이 없는 기기(기록이 지워진 경우)는 그냥 「미녹음」이다.

검토 화면의 두 갈래는 **담당자 확정(2026-09-21)** 이다 — 모름 3개를 넘겼는데 "아직 3개가
완료되지 않았어요"가 뜨면 의도적으로 넘긴 것과 빠뜨린 것을 구분할 수 없다는 지적이 근거다.
근거는 진행 상태의 `skipped`(localStorage)이고 **서버로 보내지 않는다** — 관리자 채점은 어느
쪽이든 오반응이라 점수가 같고, 결과지에 나눠 찍을지는 아직 묻지 않았다(`lib/survey-state.ts`).

관리자 쪽 미녹음 채점의 근거는 검사지 명문 "제한시간 내 읽지 못한 낱말은 0점으로 채점합니다"다
(사용자 확정 2026-08-12). 값은 저장 없이 파생된다 — `lib/scoring.ts`의 `withUnrecordedFixed`를 관리자 결과지·
결과보고서 PDF 라우트·교사 결과지가 함께 거치므로, 채점자가 [채점 저장]을 누르기 전에도 화면과 인쇄물이 같다.
**저장된 값이 있어도 덮는다**(사용자 확정 2026-09-29 — 그 전에는 채점자 값이 이겼다). 들을 녹음이 없어
채점자가 넣을 값은 근거 없는 추측일 수밖에 없고, 제출된 검사는 업로드가 잠겨 녹음이 나중에 생기지도 않는다.
그래서 관리자 결과지는 미녹음 행의 입력을 잠그고 계산에 쓰는 값(X · 20초 · 0어절)을 그 자리에 보여 준다.
잠금은 저장값이 아니라 **그 세션의 녹음 유무에서 매번 파생**한다 — 재검사는 새 세션이라 녹음한 문항은
잠기지 않는다. **제출된 세션에만** 적용한다 — 진행 중인 검사의 빈 녹음은 "안 읽었다"가 아니라
"아직 안 했다"이므로 0점으로 채우지 않는다.

녹음 없는 문장(「모르겠어요」·업로드 실패)은 **읽은 시간 = 제한 시간(20초), 정확 어절 0**이다 —
담당자 확정(2026-09-29). 계산에서 빼면 총점이 비율이라 못 읽은 문장이 점수를 깎지 않는다 — 1번만 5초에
7어절 읽고 나머지를 넘긴 아이가 1.40으로, 4문장을 30초에 다 읽은 아이(1.20)보다 높아진다. 제한 시간으로
치면 0.11. 이 시간도 **저장하지 않고 파생한다** — 관리자 결과지는 잠긴 칸에 보여 주기만 한다.

## 결과보고서 PDF (2026-09-28)

관리자 결과지의 [결과보고서 PDF 다운로드]와 교사 결과지의 [전체 PDF 다운로드]/[선택한 검사 다운로드]가 내려주는 **공식 출력물**이다.
담당자가 배포한 `KODYS_G1/G2_결과보고서_양식.docx`를 `lib/pdf/report.ts`가 Letter 한 장으로 그린다
(정답본 `KODYS_G*_결과보고서.docx`와 1:1이 목표 — 두 학년 양식 사이의 서식 불일치까지 그대로다).
종전의 「원본 검사지에 점수를 얹는」 출력은 폐기했다(스탬핑 모듈·좌표·추출 스크립트 삭제).

| 칸 | 값 | 근거 |
|---|---|---|
| 지역 / 학교 | 도는 학교 목록 소재지에서 시·군을 뗀 이름, 특별·광역시·세종은 도시 이름 + 학교명 (`춘천 교동초등학교`·`부산 성남초등학교`) | 사용자 확정(2026-09-29) — 담당자 예시가 「춘천 교동초등학교」 |
| 학년 / 학기 | 검사일 월로 학기 판정(3~8월 1학기, 9~2월 2학기) — 새 세션의 양식도 같은 규칙으로 고르므로 둘이 맞는다 | 담당자 확정(2026-10-20 「응응!」, 처음은 사용자 확정 2026-09-28) |
| 결과 요약 | 해독·읽기유창성·쓰기 양호/주의/위험 + 최종결과(초록·주황·빨강) | 3단계·최종 규칙은 담당자 확정(2026-10-19 docx). 양식은 종전 그대로 — 「이전에 줬던 템플릿으로 해도 돼」(2026-10-20). 주의의 주황은 양식에 없어 더한 색(사용자 확정 2026-10-20) |
| 결과 해석 및 권고 | 양호는 종전 PASS 문장, 주의·위험은 영역을 양호 → 주의 → 위험으로 묶어 나열하는 문장 | 담당자 확정(2026-10-19 docx) — docx 예시 세 개와 글자까지 같다(`tests/report.test.ts`). 나열 규칙도 docx 것(「영역별 양호, 주의, 위험으로 나열, 이후 문장은 동일」) — 묶음 안 영역 순서는 예시를 따름 |
| 추가 관찰 정보 | 검사자가 체크한 영역에 ☑ | 담당자 확정(2026-09-28) 「체크한 거 그대로」 |

채점이 끝나지 않은 과제는 판정 칸을 비우고, 최종결과·해석 문장도 세 과제가 다 끝나야 채운다
(미채점을 위험으로 찍지 않는다). 1학기 양식과 폴백 학년의 기준은 임시값이다 — 결과보고서는 담당자 양식을 그대로
따르므로 「임시 기준」 표시가 **없고**, 그런 검사의 판정은 관리자·교사 화면의 표시로만 임시임을 알 수 있다.

글꼴: 양식의 맑은 고딕·Segoe UI Symbol·Times New Roman은 Microsoft 전용이라 서버에 실을 수 없다.
글자는 나눔고딕(OFL, `assets/fonts`)으로 그리되 줄 높이·베이스라인은 Word 출력 실측값(맑은 고딕 1.72배)으로,
줄바꿈은 맑은 고딕 진행 폭 표로 계산해 세로 배치와 줄 나뉘는 위치를 Word와 0.5pt 안에서 맞췄다. 확인란은 선으로 그린다. 같은 입력이면 같은 바이트가 나온다(생성 시각을 검사 시각으로 고정).

## 교사 결과지 (2026-09-22)

```
/ 코드 입력 → 배너 [결과지 받기 →] → 등록된 담임 메일로 링크(14일) → /results/<토큰>
  → 요약 · 아이별 행(재검사 ▸ 펼침, 받을 수 있는 검사만 체크) → [전체 PDF 다운로드] / [선택 PDF]
```

**왜 매직링크인가.** 학급 코드는 아이 앞 공용 PC에 자동으로 채워져 있다 — 코드만으로 결과가
열리면 아이가 반 전체 판정을 본다. 버튼은 결과가 아니라 **등록된 메일함**으로 가는 문이라
아이 앞 화면에 둬도 안전하다. 이메일은 입력·수정 불가다 — 요청자가 주소를 정할 수 있으면
코드가 곧 열쇠가 된다.

**관리자는 채점만 한다.** 채점 완료 기준은 관리자 PDF 게이트(`sheetPdfGate`)와 같다 — 읽기 두
과제가 채점되면 완료이고, 쓰기만 비어도 허용한다(A안). **다만 쓰기가 채점 전이면 그 칸은 점수
대신 「채점 전」으로 나오고 판정은 보류된다** — 치르지도 않은 과제의 0점으로 아동을
낙제시키지 않기 위함이고, 관리자 결과지와 같은 표기다.

- **코드당 1분 1회** 요청(아이의 연타로 담임 메일함이 채워지지 않게). 메일 발송 실패는 502.
- **이메일 안전망 3중**: 관리자 직접 발급도 이메일 필수 · `/apply` 이메일 확인칸 ·
  `/admin/codes` 목록에서 이메일 수정.
- 문의처는 「담당자에게 문의」까지만 쓴다(사용자 확정) — 연락처 값을 앱에 두지 않는다.
- 전제: Resend 도메인 인증 + 프로덕션 `MAIL_TO_OVERRIDE` 해제 — **2026-10-12 완료**(`lidislab.com`).
  그 전엔 샌드박스라 결과지 메일이 교사에게 닿지 않았다.

이 절의 결정은 전부 **사용자 확정(2026-09-22)** 이다(담당자 회신이 아니다). 스펙:
`docs/superpowers/specs/2026-09-22-teacher-results-download-design.md`.

## 쓰기 스캔본 (2026-09-30)

```
시작 화면 [쓰기 기록지 인쇄 →] → 아이마다 한 장(번호·이름·QR 자동, 낱말은 인쇄하지 않는다)
검사 중 쓰기 단계: [화면에서 바로 표시] / [스캔본으로 올리기] ← 기본값은 이 기기에서 같은 학급의 마지막 선택
  (화면에 표시한 칸이 있으면 화면 방식 — 멈췄다 이어해도 표시한 값이 버려지지 않게)
  스캔본이면 선생님이 불러 주고 아이는 기록지에 쓴다 → 입력 없이 다음 → 제출(방식 확정)
반 전체 검사 뒤: 결과지 화면(/results/<토큰>) [쓰기 스캔본 올리기] — 반 전체를 한 파일로
  → 쪽마다 QR로 아이에게 자동 연결 · 못 읽은 쪽·재검사한 아이는 선생님이 고른다 · 빈 쪽은 올리지 않음
  → 모든 쪽이 정해지면 [올리기](짝짓기 전에 목록을 다시 받고, 서버도 그 아이의 최근 제출 검사인지 확인)
담당자: 관리자 결과지에서 스캔본을 보며 쓰기 O/X(G2 0·1·2) → 스캔 대기 → 채점 중 → 채점 완료
```

- 담당자 확정(2026-09-30 — 두 방식 중 고르는 과정만. 회신은 사용자 전달, 원문은 저장소에 없다). 화면·흐름 결정은 **사용자 확정(2026-09-30)** — 담당자에게
  시안을 공유했고 회신을 기다린다. 기록지는 **임시 양식**이다 — 담당자가 양식을 주면 번호·이름·QR만
  얹는 방식으로 바꾼다(`components/start/README.md`).
- **받아쓰기 문항은 학급 코드와 함께 미리 알린다** — 승인 안내(메일·평문·관리자 [안내 문구 복사])의 「쓰기를 기록지(스캔본)로
  하실 때」가 위 순서(기록지 인쇄 → 쓰기 단계 화면을 보고 불러 주기 → 결과지 화면에서 올리기) 뒤에 「받아쓰기는 아래 낱말(문장)로
  진행해 주세요」와 **승인한 날의 학기 양식 쓰기 문항**을 기록지 칸 번호 순서로 싣는다. 담당자 요청(2026-10-20 「스캔본 업로드로 할 경우
  문항을 미리 알고 계셔야 할 것 같음. 코드 전달 드릴 때 검사 문항을 알려 드리는 건 어떨지」) 그대로다 — 처음에는 메일이 퍼질 것을
  걱정해 순서만 넣었다가 요청과 달라 같은 날 문항을 넣었다(사용자 지시 2026-10-21). 문항은 승인 라우트가 서버에서 양식을 풀어 넣고
  같은 값을 응답으로 내린다(화면 코드는 양식을 import하지 않는다 — 공개 번들에 문항이 실린다). 안내 문구는 사용자 확정(2026-10-21 —
  `lib/format.ts` `scanGuideLines`·`writingNoticeLead`). 기록지 인쇄물에는 여전히 문항을 싣지 않는다.
- **QR에는 반 표시와 번호만** 싣는다(학급 코드·이름·주소 없음 — `lib/writing-sheet.ts`). 쪽 순서가 아니라
  QR로 짝짓는다 — 아이들이 낸 순서는 번호순이 아니고, 한 장만 빠져도 뒤가 전부 밀린다.
- **올릴 때 화질 경고는 없다.** 잘 스캔된 종이를 시스템이 잘못 경고하면 선생님만 번거롭다. 판독이
  어려우면 **담당자가 담임에게 직접 연락한다** — 앱 안의 「다시 올려 달라」 요청은 없다(선생님이 결과지를
  다시 열지 않으면 못 본다). 잘못 붙은 스캔본은 담당자가 「연결 해제」하면 스캔 대기로 돌아간다.
- 이미 올린 스캔본은 **담당자가 쓰기를 넣기 전까지만** 바꿀 수 있다(넣은 점수와 근거 그림이 어긋나지 않게).
- 받기는 A안 그대로다 — 스캔 대기·채점 중이어도 읽기 채점이 끝났으면 받을 수 있고, 쓰기·최종결과 칸이
  빈다. 그런 아이가 섞이면 받기 전에 「쓰기 채점 전 N명」 경고와 [완성된 N장만]을 준다.
- 선생님은 **화면의 목록을 보며** 불러 준다 — 아이가 화면을 보면 베낄 수 있지만 시스템으로 막지 않고, 아이가
  화면을 보지 않게 하는 것은 사용자가 선생님께 안내한다(사용자 확정 2026-10-01 — 담당자 회신 아님. 2026-08-07
  계획서부터 남았던 질문을 이것으로 닫는다).
- 다른 아이에게 기록지를 건네면 그 아이 기록으로 올라간다(QR은 종이에 찍힌 아이를 가리킨다) — 시스템은 가려낼 수
  없어 검사 화면이 「종이의 이름을 확인하고 건네 주세요」로 알린다. 아이가 이름을 직접 쓰는 칸은 담당자 양식을
  받을 때 함께 묻는다(담당자가 인쇄된 이름과 대조할 수 있다).

## 기술 구조

- **Next.js 16 (App Router) + React 19 + Tailwind 4** — 프런트·API 라우트 단일 앱
- **Supabase** — Postgres(RLS로 anon 전면 차단, 서버 라우트의 service role만 접근) + Storage(`recordings`·`writing-scans` 비공개 버킷, 관리자에게만 1시간 서명 URL 발급)
- **QR** — 기록지 QR은 직접 만든 부호기(`lib/qr.ts`), 올린 스캔본의 QR 판독은 jsQR, PDF 쪽 그리기는 pdfjs(6.x **legacy 빌드** — 오래된 브라우저에 없는 기능을 채워 넣는다) — 둘 다 파일을 고를 때만 브라우저에서 불러온다. pdfjs는 이 기능 때문에 실행 의존성이 됐다(예전에는 지금은 없는 검사지 좌표 추출 스크립트만 썼다). 흑백 스캔 PDF(CCITT G4·JBIG2)를 그리는 wasm 해독기는 `npm run dev`·`build`가 `public/pdfjs-wasm/`로 복사한다(`scripts/copy-pdfjs-wasm.mjs`)
- **인증**: 관리자는 argon2id 비밀번호 + HMAC 쿠키(8시간), 참여자는 세션 생성 시 발급되는 HMAC 세션 토큰(24시간, 해당 세션에만 쓰기 가능), 교사 결과지는 **학급 스코프 HMAC 토큰**(14일, 주체 내장 — 등록된 담임 메일로만 발송)
- **제출 후 잠금**: 최종 제출된 세션은 녹음 업로드·재제출이 차단된다(검사 증적 사후 변조 방지)
- **웹폰트는 저장소에 넣는다** — `next/font/google`은 **빌드마다** 구글에서 폰트를 받아, 그 요청
  한 번의 실패로 배포가 통째로 죽는다(실제로 Vercel에서 발생). `public/fonts/**`와
  `app/fonts.css`가 벤더링 결과물이고 `scripts/vendor-fonts.mjs`가 그것을 만든다.
  **`next/font/google`로 되돌리지 말 것.** 한자 전용 청크는 받지 않는다(이름은 `NAME_RE`가
  한글·라틴만 허용하고 학교명·검사 낱말도 전부 한글이라 한자를 렌더할 경로가 없다) — 10.1MB가
  6.1MB로 준다. 폰트·웨이트를 바꾸려면 스크립트의 `FAMILIES`를 고치고 다시 실행한다.

## 셋업

1. `npm install`
2. Supabase 프로젝트(리전: 서울/ap-northeast-2) 생성 → SQL Editor에서 `supabase/migrations/`의
   파일을 **번호 순서대로** 실행한다(`001_init.sql` → … → `008_session_form.sql`, 파일별 내용은
   [supabase/migrations/README.md](supabase/migrations/README.md)).
   001은 통합본으로, 구 001~015를 하나로 합친 것이다 — 구 이력은 git log 참고.
   - 학급 코드 발급 테이블(`class_codes`), 그를 참조하는 검사 세션(`sessions`), 녹음·낱말쓰기·
     낱말해독 O/X·문장 어절 점수 테이블, 관리자 로그인 무차별 대입 방어(`login_attempts` +
     `record_login_failure` RPC), RLS(정책 없음 = anon 전면 차단), 조회 인덱스, 녹음 스토리지
     버킷까지 한 파일에서 만든다.
   - 이미 데이터가 든 운영 DB가 있다면 **먼저 비우고**(또는 새 프로젝트를 만들고) 실행할 것 —
     `create table`이라 기존 테이블과 이름이 겹치면 실패한다.
3. `cp .env.local.example .env.local` 후 값 채우기
   - `ADMIN_PASSWORD_HASH`: `npm run hash-password -- '원하는비밀번호'` 실행 → **".env.local용" 라벨이 붙은 줄**을 그대로 복사해 붙여넣는다.
     - ⚠️ argon2id 해시(`$argon2id$v=19$...`)는 `$`를 필드 구분자로 쓰는데, Next.js는 `.env*` 파일의 `$VAR`를
       다른 환경변수 참조로 확장하려 시도한다. 이스케이프 없이 원본 해시를 그대로 넣으면 `$argon2id`, `$v` 등이
       존재하지 않는 변수로 오인되어 값이 사라지고 해시가 깨져(로그인 시 `Invalid hashed password: password hash string missing field`
       에러) **어떤 비밀번호를 입력해도 로그인이 실패한다.** `hash-password` 스크립트가 출력하는 두 줄 중
       `.env.local용`(이스케이프된 `\$argon2id\$v=19\$...`)을 반드시 사용할 것 — 원본 해시는 Vercel 등 대시보드
       전용(아래 배포 절 참고).
   - `SESSION_SECRET`: `openssl rand -hex 32`
   - `FORMS_KEY`: 실제 검사 문항 암호문을 푸는 키(64자리 16진수, 저장소 주인에게 받는다). 비우면 가짜 문항으로 돈다 —
     ⚠️ 키 없이 운영 DB에 붙여 검사를 만들지 말 것(가짜 낱말로 만든 기록이 실제 문항 자리 번호에 쌓인다).
   - `RESEND_API_KEY`·`MAIL_FROM`·`MAIL_TO_OVERRIDE`: 메일 발송용(선택 — 신청·승인 메일을 쓸 때만).
     운영 Resend 계정의 키를 받으면 `MAIL_FROM`은 `읽기검사 <noreply@lidislab.com>`(인증된 도메인)으로 두고,
     **`MAIL_TO_OVERRIDE`에 본인 주소를 넣어** 모든 수신자를 본인에게 돌려 둔다(로컬에서 실제 교사에게 나가는 것을 막는다).
     새 Resend 계정을 직접 만들었다면 도메인이 없으므로 `onboarding@resend.dev`에서 **가입 이메일로만** 발송된다 —
     이때는 `MAIL_TO_OVERRIDE`에 그 가입 주소를 넣는다.
   - `MAIL_REPLY_TO`: 메일의 답장 주소(Reply-To, 선택). 로컬은 비워 둔다 — 운영 값은 아래 배포 절.
   - `ADMIN_NOTIFY_EMAIL`: 교사가 `/apply`로 신청할 때 알림을 받을 관리자 메일 주소(선택 — 비워두면
     알림 메일을 시도하지 않을 뿐, 신청 접수 자체는 그대로 성공한다).
4. `npm run build:schools` — 전국 초등학교 원본 JSON을 지역별 경량 JSON(`public/schools/`)으로 생성.
   원본 폴더 경로가 다르면 `npm run build:schools -- <원본디렉터리>`로 지정.
   (생성물은 저장소에 이미 커밋돼 있으므로, 학교 데이터를 갱신할 때만 재실행하면 된다.)
5. `npm run dev` → http://localhost:3000 (아동) / http://localhost:3000/admin (관리자)

### 수동 E2E 체크리스트 (릴리스 전 실기기)

**전 화면·기능을 밟는 최신 목록은 [docs/qa/2026-10-12-full-e2e.md](docs/qa/2026-10-12-full-e2e.md)다** — 아래는
그 이전부터 남은 실기기 위주 요약이다. 둘이 다르면 그 문서가 맞다.

**2026-08-14~15에 브라우저 E2E를 실시했고, 정적 검증이 못 잡은 결함 두 건을 잡았다** —
삭제된 세션이 장애와 같은 500으로 뭉뚱그려지던 것(PR #35)과 세션 목록의 이중 스크롤(PR #38).
둘 다 소스만 봐서는 옳아 보였고 실행해야 드러났다.

⚠️ **다만 실기기(iOS Safari)는 아직 못 돌렸다.** E2E는 인앱 브라우저에서 진행했는데, 이 환경은
마이크가 막혀 **가짜 오디오 스텁**으로 대체했고 `scroll`·`ResizeObserver`·`IntersectionObserver`가
발화하지 않는다. 그래서 **무음 녹음처럼 조용히 실패하는 부류는 원리상 걸러지지 않았다.**
학교에서 아이패드를 쓴다면 첫 실검사 전에 아래 마이크·녹음 항목만이라도 실기기로 돌릴 것.

⚠️ **교사 신청·명단 드롭다운 흐름(PR A~C, ~2026-08-18)은 이 브라우저 E2E 대상이 아니었다** —
위 결함 두 건을 잡은 패스보다 나중에 만들어졌다. 아래 신청 흐름·명단 모드·미승인 코드 거부
항목은 아직 한 번도 실기기·실브라우저로 돌리지 않았다.

- [ ] 관리자: `/admin/codes`에서 코드 발급(학교 검색·학년·반·담임교사명·연락처 입력) → 6자리 코드 표시·복사 버튼 동작 → 발급 목록에 반영
- [ ] 관리자: 세션이 하나도 없는 코드는 삭제 버튼이 보이고 삭제되는지 (세션이 있는 코드는 삭제 안 되는지)
- [ ] 관리자: 전화번호에 하이픈을 넣어 발급 → 목록·저장값에 하이픈이 없는지
- [ ] 신청 흐름: `/apply`에서 학교·학년·반·담임·이메일 입력 + 명단 파일 업로드 → 신청 → `/admin/codes` 대기(pending) 목록에 뜨는지(인원 수만 보이고 실명은 [명단 보기]를 눌러야 뜨는지) → 승인 → 교사 이메일로 코드 안내 메일이 오는지 → 그 코드로 시작 화면에서 검사를 시작할 수 있는지
- [ ] **미승인(pending) 코드는 거부된다**: 방금 신청했지만 아직 승인하지 않은 코드를 시작 화면에 입력 → 미존재 코드와 **구분 없이** 거부되는지(다르게 안내되면 버그 — 코드 열거 방지 근거가 무너진다)
- [ ] 시작(`/`): 승인된 코드에 **명단이 있으면** 드롭다운으로 전환 → 아동 선택(검사한 번호는 표시만, 선택은 막지 않음) → 확인 모달에 **학급 정보(학교·학년·반·담임) + 선택한 아동 정보**가 올바르게 뜨는지 → [맞아요, 시작하기] → 세션 생성·시작
- [ ] 명단 모드에서 「명단에 없는 학생이에요」 → 직접 입력 폼(번호·이름·성별·생년월일)으로 전환 → 「명단에서 고르기」로 다시 드롭다운으로 돌아오는지(입력한 코드는 유지되는지)
- [ ] 명단이 없는 코드(관리자가 `/admin/codes`에서 직접 발급한 코드): 시작 화면이 기존과 같은 직접 입력 폼 그대로인지(드롭다운이 뜨지 않는지) → 코드 + 아동 번호·이름·성별·생년월일 입력 → [확인] → 확인 모달 → [맞아요, 시작하기] → 세션 생성·시작
- [ ] 같은 학급·번호로 두 번째 검사 시도 → 확인 모달이 "이미 검사했어요" **경고**(제목·문구·[네, 다시 검사할게요] 버튼)로 바뀌고, 그래도 진행은 막히지 않는지. 제출 전(진행 중)인 번호면 제목이 "진행 중인 검사가 있어요"이고 드롭다운 배지도 「진행 중」인지
- [ ] 명단 모드로 시작한 세션: 관리자 결과지에서 **저장된 아동 번호·이름·성별·생년월일이 명단과 정확히 일치**하는지(명단 모드의 존재 이유가 전사 오류 방지이므로, 여기서 어긋나면 그 목적 자체가 실패한 것)
- [ ] 마이크 확인 → 연습 여부 선택([연습부터 하기] / [연습 없이 바로 검사 시작])

## 배포 (Vercel)

0. **마이그레이션 먼저**: 새 `supabase/migrations/*.sql`이 있으면 **병합 전에** Supabase SQL Editor에서 번호 순(예: 006 → 007)으로
   실행한다. 코드가 먼저 나가면 시작 화면·목록·결과지가 없는 컬럼·표를 찾아 500이다(새 컬럼·표만 먼저 있는 것은 무해).
   표·관계를 새로 만든 파일은 끝에 `notify pgrst, 'reload schema'`를 두어 PostgREST가 바로 알게 한다 — 없으면 캐시가
   갱신될 때까지 수 분간 「Could not find a relationship …」 500이 난다(2026-10-01 운영에서 확인).
1. **저장소 병합**: 배포 브랜치(보통 `main`)에 변경을 병합한다. Vercel은 그 브랜치를 프로덕션으로 배포한다.
2. **Vercel 프로젝트 생성**: New Project → 이 GitHub 저장소 import. 프레임워크는 Next.js 자동 감지(빌드 설정 변경 불필요).
3. **환경변수 등록** (Settings → Environment Variables, Production):
   - `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` — Supabase 대시보드 값
   - `SESSION_SECRET` — `openssl rand -hex 32`로 새로 생성 (로컬과 다른 값 권장)
   - `FORMS_KEY` — 실제 검사 문항 암호문의 키. **로컬 `.env.local`과 같은 값**을 **Production과 Preview 모두**에 넣는다
     (Preview도 운영 DB를 본다 — 가짜 문항으로 만든 검사가 운영 기록에 섞이면 안 된다). 없으면 빌드가 실패한다(`lib/forms/index.ts`).
     키를 바꾸면 `npm run forms:unseal`(옛 키) → `.env.local`의 키 교체 → `npm run forms:seal` → 커밋, 그리고 Vercel 값도 같이 바꾼다.
   - `ADMIN_PASSWORD_HASH` — ⚠️ **로컬에서 쓰던 값이나 예시용 약한 비번 금지.** `npm run hash-password -- '강한랜덤비번'` 출력 중
     **"원본 해시"** 줄(이스케이프 없는 `$argon2id$v=19$...`)을 그대로 붙여넣는다. Vercel 대시보드는 셸/dotenv
     파싱을 거치지 않으므로 `$`를 이스케이프하면 안 된다(로컬 `.env.local`용 `\$` 이스케이프 버전과 다름 — 위 셋업 절 참고).
   - `RESEND_API_KEY`·`MAIL_FROM` — 메일을 쓸 경우. `MAIL_TO_OVERRIDE`는 **운영에서 반드시 비운다**
     (설정돼 있으면 교사에게 갈 메일이 전부 그 주소로 간다).
   - `MAIL_REPLY_TO` — 선생님이 메일에 [답장]하면 받을 **담당자 메일함**(Production만). 보내는 주소 `noreply@`에는
     받는 메일함이 없어, 비워 두면 답장이 반송된다. 주소를 코드에 두지 않는 것은 저장소가 공개라서다(`lib/mail.ts`).
   - `APP_URL` — 메일에 넣는 절대 URL(운영: `https://lidislab.com`). 비워두면 요청의 Host
     헤더로 origin을 만드는데, `POST /api/apply`(공개 신청 접수)는 그 URL을 관리자 알림 메일
     링크에 그대로 싣는다 — 위조된 Host가 그 메일에 실릴 수 있으므로 **운영에서는 반드시 설정**한다.
   - `ADMIN_NOTIFY_EMAIL` — 교사가 `/apply`로 신청할 때 알림을 받을 관리자 주소. 비워두면 신청
     접수는 그대로 성공하되 알림 메일만 시도하지 않는다.
   - (모든 변수가 서버 전용 — `NEXT_PUBLIC_` 접두사 붙이지 말 것. 붙이면 클라이언트에 노출된다.)
   - ⚠️ **Production과 Preview의 메일 설정을 나눈다**(정식 도메인 `lidislab.com`, 2026-10-12 전환).
     Production은 `MAIL_TO_OVERRIDE`를 **두지 않고** `ADMIN_NOTIFY_EMAIL`·`MAIL_REPLY_TO`에 담당자 주소를 넣는다. Preview는
     `MAIL_TO_OVERRIDE`·`ADMIN_NOTIFY_EMAIL` 둘 다 개발자 주소로 두어 시험 배포의 메일이 전부 개발자에게 가게 한다.
     Production에 `MAIL_TO_OVERRIDE`가 남으면 교사 메일이 전부 그 주소로 가고 교사는 코드를 받지 못한다.
     도메인 연결·Resend 인증·환경변수 표·확인 순서: [docs/superpowers/plans/2026-08-19-domain-switch-checklist.md](docs/superpowers/plans/2026-08-19-domain-switch-checklist.md)
   - 옛 주소 `speech-survey.vercel.app`은 `next.config.ts`의 `redirects()`가 `https://lidislab.com`으로 308한다(경로·쿼리
     그대로, 2026-10-13). Vercel 대시보드가 아니라 코드에 있는 설정이라, 정식 도메인을 또 바꾸면 그 상수도 함께 고친다.
4. **Deploy** → 자동 HTTPS 발급. 마이크 녹음은 HTTPS에서만 동작하므로 배포 후 정상 작동한다.
5. 배포 도메인을 확인하고 `/`(아동)·`/admin`(관리자) 흐름을 실기기로 점검한다.

- 환경변수는 로컬(`.env.local`)과 Vercel이 별개다 — 각자 `npm run hash-password`로 자신만의 로컬 비번을
  생성해 쓰고, Vercel은 그와 다른 별도의 강한 비번을 쓴다. 실제 비밀번호 값은 코드·문서 어디에도 적어두지 말 것.
- 관리자 비밀번호는 argon2id(`@node-rs/argon2`)로 검증한다. 로그인 라우트는 네이티브 바인딩 때문에
  `runtime='nodejs'`로 고정돼 있으며, Vercel 빌드는 플랫폼 프리빌트 바이너리를 자동 설치한다.
- `recordings` 라우트는 `maxDuration=60`(초). Vercel Hobby는 함수 실행시간 상한이 더 짧을 수 있으나,
  5MB 이하 업로드는 수 초 내라 실사용엔 무방하다.
- 세션 토큰(참여자)은 24시간 만료라, 배포로 `SESSION_SECRET`을 교체하면 진행 중이던 검사의
  업로드가 실패한다 — 검사 시간대를 피해서 시크릿을 회전할 것.
  **토큰/저장 형식을 바꾸는 배포도 동일하게 진행 중 세션을 무효화한다**(예: 토큰에 만료 추가,
  localStorage 스키마 버전 변경). 이런 변경이 포함된 릴리스는 반드시 검사 시간대를 피해 배포할 것.

## 운영 · 개인정보 (PII)

이 서비스는 **아동 실명·생년월일·성별·학교·반·번호, 담임 이름·연락처, 음성 녹음**, 그리고 쓰기를 스캔본으로
올린 검사는 **쓰기 기록지 이미지(아동 필적)**를 수집한다.
만 14세 미만 아동의 개인정보이므로 법정대리인 동의가 필수다(개인정보보호법 제22조의2).

- **동의 절차(구현됨)**: ① 검사 전 **학교의 개인정보 처리 방침·절차에 따라** 법정대리인 동의 회수
  (수단은 학교가 정한다 — 담당자 확정 2026-09-21. 앱이 양식을 제공하지 않으며 동의서 양식 파일
  `docs/consent/`는 2026-09-22에 삭제했다)
  → ② 시작 화면에서 4대 고지사항(제15조②) 표시 + 검사자가 "법정대리인 동의 확인" 필수 체크
  → ③ 확인 시각이 `sessions.guardian_consented_at`에 기록(감사 증적, `supabase/migrations/001_init.sql`)
  → ④ 아동에게는 마이크 확인 화면에서 쉬운 말로 고지(제22조의2 ③).
  동의 기록(서면이든 전자든 학교가 쓴 수단의 원본)은 운영 주체가 별도 보관한다. 고지 문구의 단일 소스는 `lib/consent.ts`.
- **저장 위치**: 아동·검사 데이터는 `sessions`(+ 녹음·낱말쓰기·스캔본 행, FK CASCADE)에 — 녹음 파일은 `recordings`,
  쓰기 기록지 스캔본은 `writing-scans` 비공개 버킷의 `{sessionId}/` 아래에 — , 담임 성명·전화·이메일은
  학급 코드 발급 시 `class_codes`에 영구 보관된다 — 아래 파기 절차는 두 테이블 모두를 대상으로 한다.
  교사가 `POST /api/apply`로 신청할 때는 학생 명단(실명·성별·생년월일)이 `class_roster`에 함께
  저장된다 — 인증 없는 공개 라우트가 만드는 행이라 다른 두 테이블보다 노출 표면이 넓다. 이 명단은
  자체 동의 확인 시각을 갖지 않는다(동의는 나중에 검사 시작 시점 `sessions.guardian_consented_at`로
  확인된다). `class_codes` 행이 삭제되면 `on delete cascade`로 그 학급의 `class_roster` 행도 함께
  지워진다 — 별도 파기 스텝이 필요 없다. **관리자 화면의 노출 범위는 일부러 좁다** —
  `/admin/codes`의 신청 대기 목록은 학급당 `roster_count`(인원 수)만 보여주고, 아동 실명·성별·
  생년월일은 관리자가 특정 신청의 [명단 보기]를 눌러야만(그때만 `GET /api/admin/codes/[id]/roster`
  호출) 화면에 뜬다 — 목록을 여는 것만으로 모든 학급의 실명이 흘러나오지 않는다.
  **다만 이것이 노출 경로 전부는 아니다.** 학급 코드 자체가 그 학급 명단의 접근 수단이다 —
  `POST /api/sessions/verify-code`는 인증 없는 공개 라우트이고(코드 소지 = 학급 접근이라는
  전제, 명단 드롭다운 도입 2026-08-18), 6자리 코드만 알면 누구든 그 학급 아동 전원의
  실명·성별·생년월일을 받아 볼 수 있다. 즉 **학급 코드가 곧 그 학급 명단의 비밀번호**다 —
  코드를 단체 대화방·공유 문서·화면 캡처에 올리지 말고, 코드가 유출된 학급은 코드를
  재발급(기존 코드 삭제 후 신규 발급)할 것.
- **거절 = 삭제**: 이 앱에는 별도의 "거절" 상태나 거절 메일이 없다(사용자 확정 2026-08-13) —
  관리자가 신청을 반려하는 유일한 방법은 pending 코드를 **삭제**하는 것이고, 삭제하면
  `class_roster`(아동 실명 명단)도 `on delete cascade`로 함께 지워진다. 삭제는 되돌릴 수 없으므로
  거절 판단은 신중히 할 것 — 삭제 확인 모달이 명단 인원 수와 되돌릴 수 없음을 명시한다.

  "목적 달성 시 지체 없이 파기"(일반 원칙)로 되어 있다. 운영 주체가 구체 기한(예: 결과 통보 후
  6개월)을 확정하면 → `lib/consent.ts`의 `RETENTION_LABEL`을 교체하고,

- **세션 삭제(파기)**: 관리자 결과지의 [세션 삭제] 버튼 — 스토리지 녹음 파일·쓰기 기록지 스캔본과 DB 행(녹음 메타·낱말쓰기·스캔본 행 포함, FK CASCADE)을 영구 삭제한다. 삭제 요청 대응에 사용.
- **일괄 파기(보존 기한 경과분)**: 보존 기한을 정한 뒤(예: 결과 통보 후 6개월) 주기적으로 SQL Editor에서 실행 —
  스토리지 객체는 행 삭제로 지워지지 않으므로, **먼저 관리자 화면에서 대상 세션을 삭제**하거나
  Storage에서 해당 `sessions.id` 프리픽스 폴더를 **두 버킷 모두**(`recordings`·`writing-scans`) 지운 뒤 행을 삭제할 것.
  ```sql
  -- 예: 제출 후 180일 지난 세션 조회(파기 대상 확인용)
  select id, child_name, submitted_at from sessions
  where submitted_at < now() - interval '180 days';
  ```
  세션 파기 후 사용하지 않는 학급 코드도 함께 삭제할 것 — `class_codes`에 담임 성명·전화·이메일이
  남아 있고, 세션이 남아 있는 동안은 `on delete restrict`로 코드 삭제가 거부된다(먼저 세션을
  지워야 코드를 지울 수 있는 순서 의존). 학급 코드를 지우면 `class_roster`(학생 명단)는
  `on delete cascade`로 함께 지워지므로 명단만 따로 지우는 절차는 없다.
- **로그아웃**: 관리자 대시보드 [로그아웃] — 공용 PC에서 자리를 떠날 때 반드시 사용(브라우저 캐시의 세션 목록도 함께 비운다).
- **로그인 방어**: IP당 5회 실패 시 10분 하드 잠금(대상형 429 — 화면에는 「10분 뒤에 다시 시도해 주세요」, 분은 `LOCK_MS`에서 계산). 전역 실패 누적은 하드 잠금 대신
  점증 지연(백오프, 상한 2초)만 적용해 IP 로테이션 공격에 마찰을 주되 정상 관리자 로그인을
  봉쇄하지 않는다(가용성 우선). `login_attempts`의 IP 기록도 개인정보성 데이터이므로 오래된 행은
  주기적으로 정리 권장:
  ```sql
  delete from login_attempts where updated_at < now() - interval '30 days';
  ```
- **방치된 신청 정리**: 승인·거절되지 않은 pending 신청에는 아동 실명 명단이 붙어 있다.
  신청 링크는 공문에 실려 사실상 공개되므로 장난 신청도 쌓인다. 주기적으로 SQL Editor에서
  실행할 것(자동 실행 아님):
  ```sql
  delete from class_codes where status = 'pending' and applied_at < now() - interval '30 days';
  ```
  `class_roster`는 `on delete cascade`로 함께 지워진다.
- **토큰 무효화**: 관리자 쿠키·참여자 세션 토큰은 서버 저장소가 없는 HMAC 서명 방식 —
  전체 즉시 무효화가 필요하면 `SESSION_SECRET`을 회전한다.
- Supabase Storage 무료 1GB — 수개월 운영 시 보존 기한 파기와 함께 용량도 점검할 것. 쓰기 기록지 스캔본은
  쪽당 0.3~1MB(JPEG, 긴 변 2000px)라 스캔본 방식 한 반(25명)이면 10~25MB가 더 든다.
