# app/admin/codes/ — 학급 코드 발급 화면 라우트

`/admin/codes` 한 화면. `page.tsx`는 `components/admin/CodeIssuer`를 Suspense로 감싼 껍데기이고,
발급 폼·목록·삭제는 전부 그 컴포넌트가 소유한다. 데이터는 `useClassCodesQuery`(react-query)가
`/api/admin/codes`에서 받아 온다.

이 화면이 시스템에서 갖는 위치: **학교·학년·반·담임·연락처를 입력받는 유일한 곳**이다.
검사 시작 화면(`/`)은 그 정보를 다시 묻지 않고 코드로 조회만 하며, 세션 생성 시 서버가 코드의
학급 정보를 `sessions`에 복사한다. 즉 여기서 잘못 발급한 학급 정보는 그 코드로 만든 모든
세션에 그대로 박힌다(비정규화 — 나중에 코드를 고쳐도 기존 세션은 검사 당시 값을 유지한다).

## 설계 의도

- 인증 코드가 없다 — `middleware.ts`가 `/admin` 전체를 보호한다(자세히는 [../README.md](../README.md)).
- 목록/필터/탭이 없는 화면이라 URL searchParams를 쓰지 않는다. `/admin`(필터·정렬 상태의 단일
  소스가 URL)과 다른 이유는 그것뿐이니, 필터를 추가하게 되면 그때 URL 동기화를 도입할 것.
- 폭을 `max-w-4xl`로 제한한다 — 세션 목록 표처럼 넓지 않아 창을 꽉 채우면 오히려 읽기 어렵다.
- 삭제 가능 여부(세션 0건인 코드만)는 화면의 편의 판단이고, **최종 방어는 DB의 FK
  `on delete restrict`**다. 라우트가 409로 되돌려준다 — 화면 조건만 고치는 것으로는 삭제되지 않는다.

## PII

담임 성명·전화·이메일이 폼과 목록에 모두 뜬다. 이 값들은 `class_codes`에 영구 보관되므로
세션을 파기해도 함께 사라지지 않는다 — 파기 절차는 루트 [README.md](../../../README.md) "운영 · 개인정보" 절 참고.
