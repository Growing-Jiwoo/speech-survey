# app/api/sessions/submit/ — 최종 제출

`route.ts`(`POST`) 한 파일. 쓰기 답과 검사자 체크리스트를 저장하고 `submitted_at`을 찍는다.
**검사가 기록으로 확정되는 지점**이다 — 이 시점 이후 같은 세션의 재제출과 녹음 업로드가 모두
거부된다(검사 증적 사후 변조 방지).

## 학년이 저장 위치를 가른다

쓰기 과제는 학년마다 과제의 종류 자체가 다르고, 그래서 **저장되는 테이블도 다르다.**
그 분기가 이 라우트에 있다.

| 학년(양식) | 과제 | 값의 뜻 | 저장 위치 |
|---|---|---|---|
| G1 | 낱말 쓰기(`ww..`) | 문항 만점이 1이라 0/1 | `writing_answers.can_write`(boolean) |
| G2 | 문장 쓰기(`sw..`) | 정확히 쓴 어절 수(0~어절 수) | `sentence_scores.words`(정수) |

값은 어느 쪽이든 **"정확히 쓴 어절 수"** 로 들어오고, 상한은 `itemMaxWords(문항)`가 어절 수에서
유도한다 — 검사지의 숫자를 여기에 옮겨 적지 않는다. 읽는 쪽에서 두 위치를 다시 합치는 것은
`lib/scoring.ts`의 `scoreInputFrom`이다.

## 설계 의도 · 제약

- **유효한 문항 코드는 세션의 학년이 정한다.** 그래서 토큰 검증 뒤 `sessionState`로 학년을 먼저
  읽고, `itemsFor(formForGrade(학년))`의 문항만 통과시킨다. 클라이언트가 보낸 코드를 믿으면
  다른 학년의 문항이 섞여 저장된다.
- **제출 여부를 두 번 본다.** `sessionState`로 한 번(409 조기 반환), `submitSession`의 반환값으로
  한 번 더. 두 요청이 겹쳤을 때 첫 검사만으로는 이중 제출을 막지 못하기 때문이다.
- 검증 순서: 본문 형식 → 체크리스트 코드 allowlist(`AREA_CODES`) → 세션 토큰 → 세션 상태 →
  문항·배점. 형식이 깨진 요청에 DB를 쓰지 않기 위한 배치다.
- 체크리스트는 중복을 제거해 저장한다(`[...new Set(...)]`).
- **녹음은 여기서 저장하지 않는다.** 녹음은 문항마다 즉시 올라가고(`/api/recordings`), 이 라우트는
  검사 중 검사자가 입력한 값(쓰기·체크리스트)만 일괄 저장한다.
- `runtime = 'nodejs'`.
