# app/api/apply/ — 교사 신청 접수

`route.ts`(`POST`) 한 파일. 교사가 공개 신청 폼(다음 태스크에서 붙는다)으로 학급 정보 +
학생 명단을 보내면, `pending` 상태 학급 코드와 명단을 만들고 관리자에게 알림 메일을 보낸다.
관리자가 이후 승인해야 `active`로 바뀌고(별도 라우트), 그때 코드가 교사에게 메일로 나간다.

## 응답에 코드를 넣지 않는다 — 의도적 제약

`insertApplication`이 돌려주는 코드를 응답 JSON에 절대 담지 않는다. **승인 메일이 코드를
받는 유일한 경로**여야, 관리자 승인이 형식이 아니라 실제 관문이 된다 — 신청 완료 화면에서
코드를 바로 보여주면 승인 없이도 코드를 손에 쥐게 되어 스펙이 무너진다. 나중에 "편의상"
코드를 응답에 실지 말 것.

## 설계 의도 · 제약

- **레이트리밋은 `admin/codes`보다 낮다(`APPLY_RATE_LIMIT` = 15분 20건).** 위협 모델이
  스팸 세션 생성이 아니라 **스팸 명단 행 생성**(아동 실명 포함)이고, 한 교사가 신청할 일은
  학기에 한 번뿐이다. `verify-code`처럼 학교 NAT의 동시 사용을 전제하지 않는다 — 신청은
  담임 한 명이 한 번 제출하는 흐름이라 낮게 잡아도 실사용을 막지 않는다.
- **unique 충돌은 `admin/codes`와 같은 관례로 흡수한다.** 최대 5회 재시도 후 502.
- **관리자 알림 메일 실패는 신청 실패로 이어지지 않는다.** `sendMail`은 던지지 않는
  결과형이라 실패해도 신청(코드+명단 insert)은 이미 끝난 상태 — 로그만 남기고 201을 낸다.
  관리자 화면의 pending 배지가 메일이 안 와도 신청을 발견할 수 있는 예비 채널이다.
  `ADMIN_NOTIFY_EMAIL`이 비어 있으면 메일 자체를 시도하지 않는다(개발 환경 배려).
- **DB 오류 메시지를 그대로 응답에 싣지 않는다.** `insertApplication`의 롤백 실패 경로는
  에러 메시지에 **살아있는 학급 코드**를 실어 로그에서 수동 삭제를 유도하는데(`lib/db.ts`
  주석 참고), 이 문구가 클라이언트로 새 나가면 안 된다 — `catch`는 항상 고정 문구만 반환하고
  원본은 `console.error`로만 남긴다.
- 명단 최소 1명·최대 99명·`childNo` 중복 금지는 `lib/schema.ts`의 `applySchema`가 단일
  소스로 강제한다 — 라우트·`insertApplication` 어느 쪽도 다시 세지 않는다.
- `runtime = 'nodejs'`.

## 공개 라우트 특유의 위험 — URL이 공문에 실린다

이 라우트는 인증 없이 누구나 호출할 수 있고, 그 URL이 학교 공문으로 뿌려진다. 그래서 다른
공개 라우트보다 노출 표면이 넓다.

- **레이트리밋은 인스턴스별(best-effort)이라 메일 발송량의 상한이 아니다.** `APPLY_RATE_LIMIT`
  (15분 20건)을 그대로 두면 한 IP가 하루 최대 1,920건까지 접수를 성공시킬 수 있고, 접수 성공마다
  관리자 알림 메일 한 통이 나가면 Resend 무료 한도(일 100통)를 한 시간 안에 태울 수 있다 —
  그러면 같은 키를 쓰는 **교사 승인 메일까지 막힌다**(이 라우트가 코드를 응답에 넣지 않으므로
  승인 메일이 교사에게 코드를 전달하는 유일한 경로다). 그래서 관리자 알림은 접수와 별도로
  `NOTIFY_COALESCE_MS`(10분)로 합쳐 보낸다 — 관리자는 건당 알림이 아니라 "대기 중 N건" 화면만
  있으면 충분하다는 전제다.
- **요청 본문 크기 제한은 앱 코드가 아니라 플랫폼(Vercel) 기본값(~4.5MB)이 최종 방어다.** 명단은
  최대 99행이라 정상 요청은 이 상한에 근접할 일이 없고, 라우트가 별도 크기 검사를 두지 않는다 —
  다만 이 상한이 사라지는 배포 환경으로 옮기면 재검토가 필요하다.
- **관리자 알림 메일의 `adminUrl`은 요청 Host 헤더로 만든다.** `APP_URL` 환경변수를 설정하면
  그 값을 우선한다(`.env.local.example` 참고) — 운영에서는 반드시 설정할 것. 설정하지 않으면
  위조된 Host 헤더가 그대로 메일 링크에 들어간다. `lib/mail.ts`는 `adminUrl`을 `escapeHtml`로
  이스케이프해 넣는다 — href 속성 밖으로 나가는 마크업 주입은 막지만, 링크 자체가 가리키는
  도메인까지 검증하지는 않는다.

## PII

요청 본문에 **학생 명단(실명·성별·생년월일) 전체**와 **담임 성명·전화·이메일**이 실린다.
학생 명단은 `class_roster`에, 담임 정보는 `class_codes`에 영구 저장된다(루트 README "운영 ·
개인정보" 절 참고) — 이 라우트는 인증이 없으므로 그 저장이 시작되는 지점이 인증 없는 공개
쓰기라는 점이 다른 두 테이블과 다르다. `class_roster`는 자체 동의 확인 시각을 갖지 않는다 —
동의는 나중에 검사 시작 시점에 `sessions.guardian_consented_at`로 확인된다. 학급 코드
(`class_codes`)를 삭제하면 그 명단도 `on delete cascade`로 함께 지워진다.

테스트: `tests/apply-route.test.ts`.
