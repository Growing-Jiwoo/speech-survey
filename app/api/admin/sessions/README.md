# app/api/admin/sessions/ — 관리자 세션 조회 · 채점 · 파기 · 인쇄

관리자 화면이 쓰는 다섯 라우트. 검사가 끝난 뒤의 모든 동작(목록 훑기 → 결과지 열기 → 채점 저장 →
결과보고서 PDF 인쇄 → 파기)이 여기를 지난다. 인증 코드는 없다 — `proxy.ts`가 `/api/admin/*`
전체를 보호한다.

| 파일 | 역할 |
|---|---|
| `route.ts` | `GET` 목록. 세션 + 녹음·채점 행을 조인해 한 번에 내려준다. 행마다 진행률(`progress`)과 최종결과(`final`: 양호·주의·위험, 채점이 남았으면 `unscored`)를 서버가 계산해 싣는다. 최종결과는 교사 결과지·결과보고서 PDF와 같은 판정이다(담당자 요청 2026-10-24) |
| `[id]/route.ts` | `GET` 결과지 데이터(세션 학년의 검사지 `form`, 채점의 판 `version`, 재검사 회차 `retest` 포함 — 회차는 목록과 같은 셈이고 못 읽으면 null로 결과지는 연다) / `PATCH` 아동 식별값 수정 / `DELETE` 세션 영구 삭제(PII 파기) |
| `[id]/scores/route.ts` | `PUT` 관리자 채점 저장(낱말 O/X · 문장 읽기유창성 어절 수·읽은 시간 · 스캔본 방식 검사의 쓰기). `times`는 **선택 필드** — 없으면 시간을 건드리지 않는다(시간 칸 이전 화면의 자동 저장이 지우지 않게), `{}`는 전부 지움. `writing`도 선택 필드이고 **스캔본 방식 검사만** 받는다(화면 방식이면 409). 쓰기를 실으면 본 스캔본의 올린 시각(`scanUploadedAt`)을 대조한다 — 그사이 바뀌었으면 409 `conflict: 'scan'`(옛 그림을 보고 넣은 점수가 새 그림과 짝지어 남지 않게. 화면은 저장 전 쓰기를 버리고 상세를 다시 받는다). **`baseVersion`(판)도 선택 필드**다(2026-10-12 점검 X8) — 있으면 지금 저장된 행의 판과 대조해 다르면 저장하지 않고 409 `conflict: 'scores'`와 지금 판·행(`version`·`rows`)을 준다. 오래 열어 둔 탭이 그사이 다른 탭이 저장한 칸을 지우거나 되돌리던 것을 막는다(병합은 화면 — `lib/sheet-save`). 없으면 종전대로 저장한다(배포 전에 열린 탭). 성공하면 저장 뒤 행의 새 판을 준다(`{ ok, version }`, 못 만들면 null). 대조 직후 **쓰기를 먼저**, 그다음 읽기를 저장한다 — 대조와 쓰기 저장 사이가 짧을수록 그사이 교체되는 창이 좁다. ⚠️ 판 대조와 저장은 한 트랜잭션이 아니다 — 두 탭이 같은 판으로 수십 ms 안에 저장하는 창은 남는다(막는 것은 몇 분·몇 시간 묵은 화면) |
| `[id]/scan/route.ts` | `DELETE` 쓰기 기록지 스캔본 「연결 해제」 — 스캔본(파일·행)과 그것을 보고 넣은 쓰기 채점을 함께 지워 스캔 대기로 되돌린다. 스캔본 방식 검사만(아니면 409) |
| `[id]/sheet.pdf/route.ts` | `GET` 결과보고서 PDF — 담당자 양식(2026-09-28)에 인적사항·판정·체크리스트를 채워 내려준다(`lib/pdf/report.ts`). 경로 이름은 종전 그대로다 |

## 설계 의도 · 제약

- **목록에 상한이 있다.** `listSessions`가 `MAX_LIST_ROWS`로 자르고, 상한에 닿으면 경고를
  남긴다(`lib/db.ts`). 화면은 행 가상화로 그 정도를 견디게 만들어 두었지만, 경고가 뜨기
  시작하면 서버 페이지네이션을 도입해야 한다는 신호다.
- **채점의 판은 상세 `GET`과 채점 `PUT`이 같은 함수로 만든다**(`lib/score-version` — 채점 네 표의 행에서). 어느 한쪽이 다른
  열·다른 표로 만들면 판이 늘 어긋나 모든 저장이 충돌(409)을 한 번씩 거친다. 판 컬럼이 따로 없어 마이그레이션이 필요 없다.
- **검사지 문항은 응답으로 나간다.** 결과지 상세 `GET`이 `form`을, 목록 `GET`이 행마다 `progress`를
  싣는다. 관리자 화면이 `lib/forms`를 import하면 문항이 **인증 없이 받을 수 있는** 공개 JS 청크에
  실리기 때문이다 — `/admin` 화면은 로그인을 요구해도 그 화면의 JS 파일은 누구나 받는다.
- **녹음·스캔본은 서명 URL로만 나간다.** `[id]` GET이 `audio_path`와 스캔본 경로를 서명 URL(1시간)로
  바꿔 내려주고 **스토리지 내부 경로는 응답에 담지 않는다.** service role 키가 클라이언트로 갈 일이 없어야
  하고, 경로가 노출되면 버킷 구조가 함께 드러난다. **녹음 서명이 실패해도 그 녹음만 `url: null`로 내린다**(2026-10-08 — 전에는 하나만 실패해도 500이라 삭제 버튼에도 닿지 못했다). 스캔본 서명이 실패해도 결과지는 열린다(`url: null`) —
  **파일이 없는 것**(`missing: true`, 정리가 끊긴 행)과 **일시 오류**(`missing: false`)를 가른다. 화면은 없을 때만
  연결 해제를 권한다(해제는 스캔본과 쓰기 채점을 지운다).
- **404와 500을 구분한다.** 삭제된 세션을 장애와 같은 500으로 뭉뚱그리면 운영자가 "재시도"와
  "장애 대응"을 가릴 수 없다. `sessionDetail`이 `session: null`을 돌려주도록 만들어 둔 것이
  이 구분을 위해서다(`.single()`이 아니라 `.maybeSingle()`).
- **수정은 화이트리스트가 곧 안전장치다.** `PATCH`는 `sessionEditSchema`가 정한 4개(번호·이름·
  성별·생년월일)만 받는다. 바디에 `grade`나 `form_id`가 실려 와도 zod가 걷어낸다 — 양식이 바뀌면
  저장된 점수가 **존재하지 않는 문항**을 가리키게 된다(점수는 양식의 자리 번호 코드로 쌓인다). 학급 코드를 통째로 잘못 골랐다면 아이가 다른 검사지로 검사받은 것이라 기록이 무효이며,
  수정이 아니라 삭제 후 재검사가 맞다.
- **첫 수정의 원본만 남긴다.** `original_identity`는 최초 1회만 채우고 이후 덮어쓰지 않는다 —
  알고 싶은 것은 "처음 들어온 값"이지 중간 단계가 아니다. "누가" 고쳤는지는 남기지 않는다
  (관리자가 단일 비밀번호라 특정 불가 — 흉내만 낸 감사 기록은 거짓 확신을 준다).
  ⚠️ 결과보고서 PDF에는 수정 흔적이 없다(담당자 양식 그대로) — **인쇄물만 보면 알 수 없다.**
- **채점 저장은 자기 소유 범위를 명시해 넘긴다.** `sentence_scores`에는 관리자 채점(`rs..`)과
  검사 중 수집된 문장 쓰기(`sw..`)가 섞여 있다. `scores` 라우트는 `sentenceCodes`(= `rs..`)를
  `saveScores`에 함께 넘겨 "이번에 안 보낸 행 삭제"의 범위를 제한한다 — 이 인자를 빼면 채점을
  저장할 때마다 아동의 문장 쓰기 점수가 지워진다. 스캔본 방식 검사의 쓰기(`writing`)는 반대로
  **쓰기 문항 코드 전부**가 소유 범위다(`saveWriting`) — 담당자가 비운 칸이 지워져야 「보낸 것이 전부」다.
- **쓰기를 고칠 수 있는 것은 스캔본 방식 검사뿐이다.** 화면에서 표시한 검사의 쓰기는 검사 중
  입력이 유일한 채점 경로라(사용자 확정 2026-08-13) `scores`가 `writing`을 409로 거부하고, `scan`
  DELETE도 409다 — 화면 방식의 쓰기를 지우면 되돌릴 길이 없다. 스캔본이 **없어도** 스캔본 방식이면
  쓰기를 받는다(판독이 어려워 담당자가 종이를 따로 받아 채점하는 길).
- **무엇이 유효한 문항 코드인지는 세션의 양식이 정한다.** `scores`·`scan`은 `sessionState`로, `sheet.pdf`는
  `sessionDetail`의 세션 행으로 양식(`form_id`, 없으면 학년 — migration 008 이전 세션)을 먼저 읽고 `formOfSession`의 문항으로
  검증·렌더한다. 클라이언트가 보낸 코드를 그대로 믿으면 다른 양식의 문항이 섞여 저장된다.
- **삭제는 스토리지 → DB 순서다.** `deleteSession`이 녹음 객체와 쓰기 기록지 스캔본(`writing-scans`
  버킷)을 지운 뒤 세션 행을 지우고,
  나머지 행은 FK CASCADE로 따라 사라진다(행만 지우면 스토리지에 고아 파일이 남는다).
  파기 사실은 `console.info`로 최소 기록만 남긴다 — 관리자 계정이 단일 비밀번호라 행위자
  특정은 애초에 불가능하다.

## 결과보고서 PDF에만 있는 규칙

- **미녹음 페이지는 오반응(X·0점)으로 고정해 인쇄한다**(저장값이 있어도 덮는다 — 화면이 그 칸을 잠근다). 다만 **제출된 세션에만** 적용한다 —
  진행 중인 검사의 빈 녹음은 "안 읽었다"가 아니라 "아직 안 했다"다. 화면 결과지와 같은
  `withUnrecordedFixed`(`lib/scoring.ts`)를 거치므로 화면과 인쇄물이 어긋나지 않는다.
- **파일명은 아동 번호를 두 자리로 앞세운다**(`03_이름_날짜.pdf`, 사용자 확정 2026-08-15).
  한 학급 30명을 한꺼번에 받으면 동명이인 파일이 덮어써지고, 이름 정렬이 출석 번호 순서와
  어긋나 인쇄물을 손으로 다시 줄 세워야 했다. 0을 채워야 문자열 정렬이 번호 순서와 같아진다.
  **재검사한 아이는 회차를 붙인다**(`03_이름_2차_날짜.pdf`, 2026-10-12 점검) — 1차·2차가 같은 이름이라 받으면 덮어써졌다.
  교사 결과지에서 한 장만 받을 때와 같은 함수(`lib/results` `sheetsFileName`)라 같은 검사는 어디서 받아도 이름이 같다.
  회차는 목록의 「N/M회차」와 같은 셈(`lib/adminStats` `retestOrdinals`)이고, 못 읽으면 회차 없이 낸다.
- 한글 파일명은 RFC 5987(`filename*=UTF-8''…`)로 넘긴다 — 없으면 브라우저가 이름을 깨뜨린다.
- 검사일은 KST 기준(`kstDateKey`)이다. UTC로 자르면 아침 검사가 하루 전으로 찍힌다.
- 아동 개인정보가 담긴 문서라 `cache-control: no-store`.

## PII

응답 전체가 아동 실명·생년월일·학교·반·번호와 담임 연락처, 그리고 녹음 재생 URL·쓰기 기록지 스캔본(아동 필적) URL이다.
`sheet.pdf`는 파일명에까지 아동 이름이 들어가므로 proxy 인증 뒤에서만 접근돼야 한다.

테스트: `tests/admin-routes.test.ts`, `tests/scores-route.test.ts`, `tests/report.test.ts`, `tests/sheet-cache-contract.test.ts`(채점 라우트를 실물로 돌려 캐시 보정·판 충돌 병합을 대조).
