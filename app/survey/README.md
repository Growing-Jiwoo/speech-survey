# app/survey/ — 검사 진행 화면(페이지 위저드)

`page.tsx` 한 파일. 검사지대로 **"한 페이지 = 한 과제 = 한 녹음"** 단위로 진행한다.
문항 UI는 `components/survey/*`가, 페이지 목록·진행 가능 판정은 `lib/`가 맡고, 이 파일은
**진행 상태의 로드/저장과 페이지 이동, 그리고 업로드 오케스트레이션**만 소유한다.

아동이 실제로 소리 내어 읽는 유일한 화면이며, 여기서 만들어진 녹음이 그대로 임상 기록이 된다.

## 상태의 단일 소스는 localStorage다

현재 페이지(`pageIdx`)·단계(`phase`)·답 캐시까지 전부 `lib/survey-state.ts`가 저장한다.
`patch()`가 setState와 저장을 **항상 함께** 하는 이유가 그것이다 — 하나라도 빠지면 새로고침 후
재개 위치가 어긋난다. localStorage는 마운트 후 1회만 읽는다(서버 프리렌더와 첫 페인트를 맞춰
하이드레이션 불일치를 피하려는 의도된 패턴이라 lint 예외 주석이 붙어 있다).

`?p=N` 딥링크(검토 화면에서 넘어온 경우)는 **1회만 소비하고 URL에서 제거한다.** 남겨 두면
이후 페이지를 옮긴 뒤 새로고침했을 때 stale `p`가 저장된 위치를 덮어쓴다.

## 녹음 저장은 낙관적이다 (2026-08-12)

녹음이 끝나면 화면에 **먼저** 완료로 표시하고 업로드는 뒤에서 돌린다. 업로드를 기다리며 화면을
잠갔더니 [다음] 버튼이 "모르겠어요"로 보인 채 몇 초씩 멈춰 검사 흐름이 끊겼다(사용자 보고).
실패하면 표시를 되돌리고(`undoSaved`) 재시도 배너를 낸다 — **되돌리지 않으면 검토 화면이
"녹음 완료"라 말하는데 서버에는 파일이 없다.** 진행 중인 업로드는 헤더의 `저장 중…`과
새로고침 경고(`beforeunload`)로만 드러난다. 연습 페이지의 녹음은 서버에 올리지 않는다.

**끊긴 업로드**(2026-10-01): 올리기 시작할 때 저장 상태에 `pendingUploads`(페이지 → 올리는 중인 시도 번호들)를 적고
끝나면 **그 시도만** 지운다(`lib/survey-state` `withPendingUpload`·`withoutPendingUpload`·`updateSavedState` — 컴포넌트가
사라진 뒤 끝나도 저장 상태는 고쳐진다). 시도 목록인 이유: 1회차가 느리게 올라가는 사이 다시 녹음하면 둘이 함께
올라가는데, 하나만 적으면 먼저 끝난 1회차가 2회차 표시까지 지운다(2026-10-07). 연습 녹음과 재시도 성공은 올리는
중이 아니므로 적지 않는다.
새로고침·탭 닫기를 「나가기」로 넘기면 파일은 사라지고 표시만 남으므로, 다시 열 때 이 탭에서 올리고 있지 않은
시도(`lib/upload-flight`에 없음 — 검토 화면도 같은 것을 본다)는 끊긴 것으로 보고 그 수만큼 「녹음 완료」 표시를 거두고 다시 녹음하라고 알린다
(`settleLostUploads`). 새로고침·탭 닫기는 올리던 요청을 끊고 그 끊김이 「실패」로 돌아오는데, 그것을 처리하면 「올리는 중」 표시가
지워져 다시 열 때 끊긴 업로드를 알아보지 못했다 — 연결 실패면 잠깐 기다려 **닫히는 중**(`lib/upload-flight` `pageUnloading`)이면
처리하지 않는다(2026-10-12, 실제 네트워크에서만 재현). **재시도 배너는 다시 보내면 될 수도 있는 실패(연결·5xx·429)에만** 띄운다 — 401(24시간 만료)·
409(이미 제출)는 진행 상태를 지우고 처음 화면으로, 400(한 화면 10번 상한)·413은 그 녹음만 저장할 수 없다고 알린다
(`lib/upload` `classifyUpload`). 4xx에 「다시 저장」을 보이면 선생님이 끝없이 누른다. 404(세션이 지워짐)도 401처럼
처음 화면으로 보내되 「이 검사 기록을 찾을 수 없어요」로 까닭을 달리 말하고(2026-10-12), 응답 없이 멈춘 업로드는 1분에 끊어
재시도로 분류한다(2026-10-08). 이어서 할 수 없는 검사(401·404·409)는 양식 조회에서 먼저 알게 되므로 **마이크 확인 전에** 그 화면을
보인다 — 아이에게 「안녕하세요」를 녹음시킨 뒤에야 알렸다(2026-10-12).

**저장 실패는 「모르겠어요」가 아니다**(2026-10-08 야간 점검 · **사용자 확정(2026-10-08), 담당자 회신 아님** — 아래 「모르겠어요」 담당자 확정 규칙의 범위를 좁힌 결정이다. 관리자 결과지는 이런 페이지를 「저장 실패」로 구별해 보인다, 루트 README 「미녹음의 표기」): 업로드가 실패해 재시도를 기다리는
화면에는 [모르겠어요]가 없고 [다음]만 있다 — 아이는 읽었고 저장만 안 됐다. 종전에 주 버튼이 「모르겠어요」로 바뀌어 있을 때 누른 쪽이
skipped로 남아 검토 화면이 「모르겠어요」로 보이고 미완료로 세지 않은 채 제출돼, 읽은 녹음이 X·0점이 됐다(운영에서 재현). 이제는 검토 화면에
「미녹음」(미완료)으로 남는다. 실패가 있으면 헤더도 「자동 저장됨」 대신 **「저장 실패 N개」**라 말한다. [다시 저장]도 정상
녹음과 같이 `lib/upload-flight`에 올리는 중으로 세고(검토 화면이 제출을 잠근다), 성공하면 저장 상태를 직접 고친다(그사이 화면을
떠났어도 「녹음 완료」가 남게).

**다시 보낼 녹음은 탭에 남는다**(2026-10-12 점검). 실패한 녹음(파일·시도 번호)은 이 화면의 상태가 아니라 `lib/upload-flight`
(`setFailedUpload`·`failedUploads`)에 둔다 — 화면 상태였을 때는 검토 왕복·[저장하고 나가기] → [이어서 하기]만 해도 경고 없이
사라지고 그 화면이 다시 「모르겠어요」가 됐다. 실패가 남아 있으면 새로고침·탭 닫기에 경고하고, 일시정지 화면도 「저장돼 있어요」
대신 남은 수를 말한다. 그래도 녹음을 잃었으면(경고를 넘김) **시도했는데 저장되지 않은 페이지**(`lib/survey-state` `unsavedPages`)로
보고 「…녹음이 저장되지 않았어요. 그 화면에서 다시 녹음해 주세요」를 띄우며, 그 페이지에는 [모르겠어요]를 두지 않는다.
검토 화면은 다시 보낼 녹음이 있는 행을 「저장 실패」로 보인다. 저장 실패 안내는 **읽기판 위**에 둔다(아래면 1024×768에서 밀려났다).
**시도 번호는 줄지 않는다**(`tries`·`nextAttemptNo`) — 저장된 수 + 1로 매기면 앞 시도가 실패해 수가 줄었을 때 다음 녹음이 이미
올라간 시도의 번호를 다시 받아 그 파일을 덮었다. 업로드가 끝날 때마다 저장 상태의 녹음 기록을 화면 상태로 다시 읽는다 — 화면을
다시 연 사이 끝난 업로드는 옛 화면만 고쳐, 새 화면이 지워진 「올리는 중」 표시를 되살려 이미 올라간 녹음을 거뒀다. 올리는 수도
`uploadsInFlight`로 센다(다시 연 화면이 0부터 세어 「자동 저장됨」이라 말했다).

## 화면이 지키는 규칙들

| 규칙 | 이유 |
|---|---|
| 진행률 분모에서 연습 페이지를 뺀다 | 연습을 건너뛴 검사와 숫자가 달라지면 안 된다 |
| 녹음 화면 아래는 **[이전] [모르겠어요] [다음]**이고, 녹음 전에는 [다음]이 꺼져 있다 | 녹음을 멈춘 뒤에도 [모르겠어요]를 누를 수 있게 — 담당자 요청(2026-10-22) 「읽다가 모르겠어요 라고 해서 녹음 멈춰도 모르겠어요를 누를 수 있게끔」. 종전(담당자 확정 2026-08-07)에는 별도 버튼 없이 녹음 전에만 [다음]의 라벨이 「모르겠어요」로 바뀌어, 읽다가 모른다고 해 녹음을 멈추면 누를 길이 없었다. 녹음 전 [다음]을 끄는 것은 08-07의 취지(오터치 한 번으로 화면이 조용히 넘어가지 않게) 그대로다. 녹음한 뒤 [모르겠어요]는 넘어가기만 한다 — 읽은 데까지는 그 녹음으로 채점하고, 검토 화면에도 「녹음 완료」다(`lib/survey-flow` `skippedAfter`). 연습·검토에서 온 화면·다시 녹음할 화면(위 「저장 실패는 「모르겠어요」가 아니다」, 사용자 확정 2026-10-08)에는 [모르겠어요]가 없다(`recordingNav`) |
| 섹션 진입 안내는 **진행 목록 기준** 첫 페이지에서 띄운다 | 양식의 고정 목록으로 판정하면 연습을 건너뛴 검사에서 낱말 해독 안내가 아예 안 나온다 |
| 녹음 중에는 [이전]·[저장하고 나가기]를 잠근다 | 그 시도의 소리가 유실된다. 업로드 중에는 잠그지 않는다 |
| 녹음 중에 화면을 떠나면(브라우저 뒤로가기 등) **그 시도는 버린다** | 트랙을 끄면 브라우저가 녹음을 마무리해, 잘린 녹음이 「마지막 시도」로 올라가는데 이 기기 기록에는 남지 않았다(관리자 화면은 마지막 시도를 기본으로 재생한다 — 2026-10-08, `hooks/useRecorder` `discardRef`) |
| 「← 검토 화면으로 돌아가기」는 주 버튼과 같은 조건일 때만 보인다 | 녹음 중에 떠나거나, 체크리스트를 비운 채·쓰기를 덜 채운 채 검토로 돌아가 그대로 제출되는 길이었다(2026-10-08) |
| 녹음 버튼 연타를 무시한다(시작 직후 멈춤·멈춘 직후 시작, 0.5초) · 마이크를 여는 중엔 버튼을 잠근다 | 두 번 누르면 녹음기가 둘 생겨 하나는 끌 수 없었고(마이크가 켜진 채), 0.2초짜리·무음 시도가 마지막 녹음이 됐다. 여는 중에 [일시정지]를 누르면 그 시작을 취소한다 |
| 낱말 쓰기 일괄 버튼은 **고르지 않은 칸만** 채운다(하나라도 고르면 「남은 칸 예/아니오」) | 하나씩 고른 뒤 잘못 누르면 확인 없이 전부 덮였고, 검토 화면은 개수만 보여 잡을 수 없었다(2026-10-08) |
| 화면 높이가 낮으면(800px 이하 — `short:` 변형, app/globals.css) 위아래 여백·읽기판·낱말 크기를 줄인다 | 1366×768 노트북·크롬북의 실제 창(650~680px)과 아이패드 가로 Safari(약 690px)에서 녹음 뒤의 「녹음이 완료됐어요.」·「목소리가 잘 안 담긴 것 같아요」가 화면 아래로 밀려 보이지 않았다(2026-10-12 점검). 쓰기 화면은 목록이 길어 스크롤되지만 [다음]이 꺼진 이유는 위에 있다 |
| 주 버튼·[모르겠어요]를 0.5초 안에 두 번 누르면 한 번으로 본다(직전 누름 기준) | [시작하기]·[본 검사 시작하기]·[다음]이 같은 자리라, 두 번 톡이 다음 녹음 화면을 「모르겠어요」로 넘겼다(아이패드 터치 포함, 2026-10-12). [모르겠어요]도 두 번 톡이면 다음 화면의 [모르겠어요]까지 눌린다. 화면이 바뀐 시각이 아니라 누른 시각으로 재 이어하기 직후의 첫 누름은 막지 않는다 |
| 녹음 시작 0.5초 안의 [일시정지]는 그 시도를 버린다 | 0.2초짜리 녹음이 마지막 시도가 되어 관리자가 기본으로 듣는 녹음이 됐다(2026-10-12, `hooks/useRecorder` `stopForPause`) |
| 페이지를 옮기면 가운데 밴드를 맨 위로 | 쓰기 화면을 끝까지 내린 채 [다음]을 누르면 다음 화면도 내려간 채 시작했다(`window`는 스크롤되지 않는다) |
| **[일시정지]는 녹음 중에도 눌린다** — 누르면 녹음을 먼저 끊고(그때까지 저장) 화면을 덮는다 | 신청 화면 안내 문구 「일시정지 버튼을 눌러 언제든 멈출 수 있습니다」는 담당자 확정(2026-09-21)이고, **녹음 중에도 눌리게 한 동작은 그 문구에 화면을 맞춘 사용자 확정(2026-09-22) — 담당자 회신이 아니다.** 종전엔 잠가 두어 아이가 힘들어하는 바로 그 순간(대개 녹음 중) 안내가 가리키는 버튼이 눌리지 않았다. 안 끊고 덮기만 하면 그만둔 뒤의 침묵이 제한 시간까지 녹음돼 저장된다. `ReadingPage`가 `stopRef`로 손잡이를 내주고 `pause()`가 먼저 부른다 |
| 검사자용 버튼은 헤더에 작게 둔다 | 아동이 누르는 큰 [이전/다음]과 떨어뜨려 오터치를 막는다 |
| 화면 자동 잠금 방지(Wake Lock) | 교사 설명이 길어져도 화면이 꺼지지 않게. 미지원·거부는 무시하고, 탭 복귀 시 재획득한다 |
| 일시정지 오버레이도 포커스 트랩을 쓴다 | 다이얼로그이므로 `ConfirmDialog`와 같은 규칙(초기 포커스·Tab 순환·Esc·복귀) |

## 여기 두지 말 것

- **진행 가능 여부 판정** — `lib/survey-flow.ts`의 `canAdvance`가 소유한다. 중단 규칙은 전면
  폐기됐다(즉시 중단 기능 제거는 담당자 확정 2026-08-13 · ①은 담당자 회신 · ②는 담당자 확정 2026-08-22 — `lib/survey-flow.ts` 상단). 검사지에 인쇄된 중단 문구를 보고 이 화면에 되살리지 말 것 —
  근거는 [CLAUDE.md](../../CLAUDE.md) 2절.
- **채점** — 낱말 해독·문장 읽기유창성은 수집만 하고 관리자 결과지에서 채점한다. 예외는
  쓰기(낱말/문장)뿐이며, 녹음이 없어 검사 중 검사자 입력이 유일한 채점 경로이기 때문이다.
  단 쓰기 방식을 **스캔본으로 올리기**로 고르면(2026-09-30) 이 화면은 입력 칸 대신 불러 줄 낱말·문장
  목록만 보이고 입력 없이 넘어간다 — 아이가 기록지에 쓰고 담당자가 스캔본으로 채점한다. 방식은
  `lib/survey-state`의 `resolveWritingMode`(고른 값 → 없으면 화면에 표시한 칸이 있을 때 화면 방식 → 그것도
  없으면 이 기기에서 같은 학급의 마지막 선택)가 정하고,
