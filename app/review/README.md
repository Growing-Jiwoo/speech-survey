# app/review/ — 제출 전 검토 화면

`page.tsx` 한 파일. 문항별 완료 여부를 한눈에 보여주고, 최종 제출(`POST /api/sessions/submit`)을
실제로 쏘는 화면이다. **검사가 기록으로 확정되기 직전의 마지막 지점**이라, 여기서 놓친 문항은
관리자 결과지에서 미녹음(=오반응 0점)으로 채워져 나간다.

## 미완료여도 제출을 막지 않는다

현장에서 아이가 거부하거나 건너뛴 문항이 있을 수 있고, 그 판단은 검사자의 몫이다. 그래서
미완료 개수는 본문과 확인 모달에서 **경고만** 하고, 확인 버튼 라벨이 "그래도 제출하기"로 바뀔 뿐
제출은 그대로 진행된다. 이 규칙을 "미완료면 제출 불가"로 바꾸지 말 것.

## 미완료 판정 규칙

| 대상 | 완료 조건 | 비고 |
|---|---|---|
| 녹음 페이지 | 저장된 시도 1회 이상 | 낙관적 표시다 — 아직 올리는 중일 수 있다(아래 「올리는 중인 녹음」). 실패하면 검사 화면이 저장 상태에서 거두고, 이 화면은 업로드가 끝날 때마다 저장 상태를 다시 읽어 따라간다 |
| 쓰기 과제 | 문항마다 값이 선택됨 | 문항 단위로 센다(페이지 단위 아님). **스캔본 방식이면 세지 않는다** — 담당자가 스캔본으로 채점할 칸이라 비는 것이 정상이다(쓰기 줄에 「스캔 예정」 배지). 제출할 때 쓰기 답을 보내지 않고 방식(`writingMode: 'scan'`)만 보낸다 |
| 검사자 체크리스트 | **비어 있으면 1개로 센다**(빨간 「선택 안 함」) | 진행 화면이 최소 1개를 강제하지만, 비운 채 검토로 돌아오는 길(헤더 링크)이 있었고 서버는 빈 목록도 받는다(2026-10-08) |
| 연습 페이지 | 세지 않는다 | 서버에 남기지 않으므로 완료 판정 대상이 아니다 |

목록에 나오는 페이지 자체도 `visiblePages`(연습 실시 여부 반영)가 정한다 — 연습을 건너뛴 검사와
한 검사의 번호가 어긋나지 않게 하기 위해 진행 화면과 같은 함수를 쓴다.

## 올리는 중인 녹음 (2026-10-07)

녹음은 끝나는 즉시 「녹음 완료」로 표시하고 뒤에서 올리므로, 마지막 녹음 직후 이 화면에 오면 아직 올라가는
중일 수 있다. 그때 제출하면 늦게 도착한 업로드를 녹음 라우트가 「이미 제출된 검사」(409)로 거부해 녹음이
조용히 사라지고 담당자 화면에서 X·0점으로 고정된다. 그래서:

- **올리는 중이면 제출을 막는다** — [제출]이 「녹음 저장 중…」으로 잠기고 남은 개수를 알린다(`lib/upload-flight`
  `uploadsInFlight` — 검사 화면과 같은 모듈 집합이라 화면을 옮겨도 이어진다). 끝날 때마다 알림을 받아(`subscribeUploads`)
  저장 상태를 다시 읽는다 — 실패한 녹음은 미녹음으로 바뀐다. 올리는 중 새로고침·탭 닫기는 검사 화면처럼 경고한다.
- **열 때 끊긴 업로드를 거둔다** — 검사 화면과 같은 `settleLostUploads`. 올리는 중에 이 화면에서 새로고침하면 파일은
  사라지고 「녹음 완료」만 남아 그대로 제출됐다. 거둔 페이지는 안내에 이름을 쓰고 미녹음으로 보인다.

## 제출이 거절될 때 (2026-10-08)

409(이미 제출 — 응답만 끊기고 서버는 받은 경우가 대부분)·401(24시간 만료)·404(지워짐)는 다시 눌러도 같은 답이라, 오류 문구
대신 **「이미 제출된 검사예요」 / 「이 검사는 더 이어갈 수 없어요」 화면과 [처음 화면으로]**를 보인다. 전에는 같은 오류만
반복되고 시작 화면이 그 아이를 「이어서 하기」로 다시 권했다. 제출에 성공하면 그 세션 id를 sessionStorage로 종료 화면에
넘기고(`markSubmitted` — 종료 화면은 그 세션만 치운다) `/done`으로 **replace** 한다(뒤로가기로 제출된 검토 화면에 오지 않게).
올리는 중 개수는 `useSyncExternalStore`로 읽는다 — 마운트와 구독 사이에 업로드가 끝나 알림을 놓치면 「녹음 저장 중…」에 갇혔다.

## 설계 의도

- **번호를 누르면 그 페이지로 되돌아간다** — `/survey?p=<순번>&from=review`. 진행 화면은 `p`를
  1회만 소비해 URL에서 지우고(`from`은 유지), 고치고 나면 순차 진행 대신 검토 화면으로 복귀한다.
- **문장만 전문을 보여준다.** 어느 문장이었는지가 곧 그 단계이기 때문이다. 낱말 페이지는 7개를
  이어 붙이면 어느 폭에서도 뒤가 잘려 아무것도 알려주지 못해 이름·개수만 쓴다.
- 데스크톱 2열 배치(좌=낱말 해독, 우=문장+쓰기, 체크리스트는 전폭 밴드)는 좌우 높이를 맞추기
  위한 것이고, 모바일에서는 같은 순서로 쌓여 문항 번호 순서가 유지된다.
- **제출 성공 시 `clearState()` 후 `/done`으로 보낸다.** 종료 화면이 한 번 더 지우지만, 파기의
  1차 책임은 여기다(제출된 세션의 토큰이 공용 기기에 남지 않도록).
- 화면 로직 중 계산에 해당하는 것(페이지 목록·라벨·완료 판정 재료)은 전부 `lib/`에서 온다 —
  `itemsFor`·`visiblePages`·`pageLabel`. 여기에 새 계산을 두지 말 것.

## 누구의 검사인지 (2026-10-01)

제목 위에 **N번 이름**을 쓴다. 진행 상태는 「마지막 세션」 하나로 이어지므로(`lib/survey-state` `LAST_KEY`) 같은 컴퓨터에서
탭을 두 개 쓰면 이 화면은 마지막에 저장된 아이를 읽는다 — 이름이 없으면 선생님은 A를 검토한다고 믿고 B를 제출할 수 있다.
다른 탭이 다른 아이를 시작하면 `hooks/useOtherTabGuard`가 이 탭을 막는다(검사 화면도 같다).
