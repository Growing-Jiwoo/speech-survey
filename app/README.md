# app/ — Next.js App Router (화면 · API)

페이지는 **흐름 제어와 상태 로드/저장만** 담당하고, 문항 UI·표 등은 `components/`,
로직은 `lib/`에 둔다.

## 참여자(아동) 흐름

```
/            시작 — ① 학급 코드 입력 → POST /api/sessions/verify-code(childNo 없이)
             ② 명단이 있으면 **명단 모드**: 드롭다운에서 아동 선택(「1번 유해림 (여)」, 검사한
                번호는 「· 검사함」 표시 — 그래도 고를 수 있다) → 확인 모달 → POST /api/sessions
                (`fromRoster:true` + 번호만. 이름·성별·생년월일은 서버가 명단에서 복사)
             ③ 명단이 비면(관리자 직접 발급 코드) **직접 입력 모드**: 번호·이름·성별·생년월일
                입력 → verify-code(childNo 포함) → 확인 모달 → POST /api/sessions(직접 입력 바디)
             명단 모드에서 「명단에 없는 학생이에요」를 누르면 ③으로 넘어가고(전학생·늦은 동의서),
             ③에 명단이 있으면 「명단에서 고르기」로 ②로 돌아온다(오탭 복구 — 새로고침만 남으면
             입력한 코드까지 날아간다)
/survey      검사 진행 — 마이크 확인 → 연습 실시 여부 선택 → 페이지 위저드
             (G1: 연습 1 + 낱말 2 + 문장 4 + 쓰기 1 + 체크리스트 1. 연습은 건너뛸 수 있다)
             ※ 화면·녹음·제한시간의 단위는 문항이 아니라 **페이지**다(lib/items.ts).
               채점 대상 녹음 페이지는 6이며, 문항 단위 수치(녹음 18)는 페이지 모델
               도입(2026-08-07) 이전 값이라 지금은 걸러내는 대상이다(lib/adminStats.ts).
/review      제출 전 검토 — 페이지별 완료 여부 확인, 번호 클릭 시 해당 페이지로 복귀(?p=N&from=review)
/done        종료 — 진행 상태(localStorage) 파기, "다음 학생 검사하기"로 /로 복귀
```

- 학교·학년·반·담임·연락처는 관리자가 `/admin/codes`에서 코드 발급 시 이미 입력했다(Task 8) —
  시작 화면은 코드로 그 정보를 조회해 확인 모달에 보여줄 뿐, 다시 입력받지 않는다.
- **명단 모드가 막는 것은 오타뿐이다** — 검사자가 아동마다 5칸을 타이핑하면 오타가 그대로 임상
  기록이 되므로(관리자 신원 수정 기능이 그래서 필요했다) 선택 1번으로 줄인다. 신원 위조를 막는
  장치는 아니다(근거는 `api/sessions/route.ts` 머리주석).
- 명단은 **드롭다운**으로만 보여준다 — 교실 공용 기기라 목록을 펼쳐 두면 지금 검사하지 않는
  아이들의 이름까지 계속 노출된다. 생년월일은 라벨에 넣지 않고 확인 모달에서만 보여준다.
- 두 모드가 **확인 모달을 공유**한다 — 중복 검사 경고 문구가 두 벌로 갈라지지 않게 하기 위함.
- 명단 모드 머리글에 **학교·학년·반·인원**을 띠로 띄운다 — 직접 입력 폼과 한눈에 구분돼 검사자가
  지금 어느 모드인지 헷갈리지 않는다. **담임 이름·연락처는 일부러 넣지 않는다**: 이 화면은 아동이
  보고 있고, 학급 확인에는 그 넷이면 충분하다(담임 정보는 시작 직전 확인 모달에서만 보여준다).
- 개인정보 고지·동의 카드는 **코드만 입력하는 첫 단계에서 감춘다** — 아동 개인정보를 아직 하나도
  다루지 않는 화면에 고지를 띄우면 무엇에 동의하는지가 흐려진다. **검사 대상 아동이 바뀔 수 있는
  전환마다 체크를 푼다** — 코드를 고쳐 명단 모드가 첫 단계로 되돌아갈 때, 그리고 명단 ↔ 직접
  입력을 왕복할 때 둘 다. 체크의 뜻이 "이 아동의 서면 동의서를 받았다"이므로, 남겨 두면 동의서를
  받지 않은 아동의 검사가 시작될 수 있다(프로덕션 검증 2026-08-19에 왕복 경로가 빠져 있던 것을 발견).
- 단계가 바뀌면 새로 나타난 첫 칸으로 **포커스를 옮기고**, 안내 문구를 `aria-live`로 읽어 준다 —
  누른 [확인]이 다음 단계에서 disabled로 다시 그려져 포커스가 body로 떨어지기 때문이다.
- 진행 상태는 `lib/survey-state.ts`(localStorage)에 저장돼 새로고침·탭 닫힘 후 재개된다.
- 이어하기 카드의 **[새로 시작]은 확인 모달을 거친다** — 진행 상태를 지우면 세션 토큰이
  사라져 그 검사를 이 기기에서 이어갈 수 없고(서버가 토큰을 다시 발급하는 경로가 없다),
  버튼이 [이어서 하기] 바로 옆이라 오탭이 쉽다. 이미 올라간 녹음은 서버에 남아 관리자가
  볼 수 있지만 아동은 처음부터 다시 검사해야 한다(리뷰 G-07).
- **학급 코드만 별도 키**(`saveClassCode`/`loadClassCode`)로 기억한다 — 세션 생성 **성공 직후에만**
  저장하고, `clearState()`가 지우지 않는다. 한 학급을 연달아 검사할 때 코드 재입력을 덜기 위함이며,
  아동 정보(이름·번호·성별·생년월일)는 어느 키로도 남기지 않는다(공용 기기 개인정보 잔류 방지).
- 녹음은 각 문항에서 **즉시 업로드**되고, 낱말쓰기·체크리스트는 최종 제출 시 저장된다.

## 교사 신청 흐름

```
/apply       공개 신청 — 학교·학년·반·담임·이메일(필수) + 학급 명단 파일 + 동의 3개
             → POST /api/apply → pending 학급 코드 생성 → 완료 안내(코드는 보여주지 않는다)
```

명단 표에 줄이 있는 동안은 탭 닫기·새로고침에 브라우저 기본 경고를 붙인다(`RosterEditor`) —
이 저장소에서 가장 긴 입력 세션인데 유일하게 보호가 없었다(리뷰 G-05). 학교·담임·이메일
4칸은 조건에 넣지 않는다: 사소한 상태에도 뜨는 경고는 무조건 무시하게 만든다.

명단 파일은 **브라우저에서만 파싱**해 번호·이름·성별·생년월일 네 칸만 보낸다 — 명렬표에
주민등록번호가 있어도 서버에 도달하지 않는다. 자세한 것은 [apply/README.md](apply/README.md).

## 관리자 흐름

```
/admin/login 로그인(argon2 검증 → HttpOnly 쿠키)
/admin       대시보드 — KPI·학교별 현황·세션 목록(필터/정렬 상태의 단일 소스는 URL)
/admin/[id]  결과지 — 녹음 청취(서명 URL)·낱말쓰기·체크리스트·세션 삭제(PII 파기)
```

인증은 `middleware.ts`가 `/admin`·`/api/admin/*` 전체를 보호한다(라우트는 인증 코드 없음).
