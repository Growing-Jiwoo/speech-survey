# components/admin/sheet/ — 결과지(채점 작업대) 부품

`components/admin/ResultSheet.tsx` **한 곳에서만** 쓰이는 부품 모음. 결과지를 한 파일에 두면
과제별 표기 규칙이 JSX 사이에 흩어져, "미채점을 어떻게 그리는가" 같은 규칙을 한 곳에서 확인할
수 없어 잘라냈다. 다른 화면에서 재사용하려고 만든 폴더가 아니다 — 공용으로 쓸 것은
`components/` 루트로 올린다.

| 파일 | 역할 | 채점 입력 |
|---|---|---|
| `ScoreBand.tsx` | 상단 총평 밴드 — 과제별 점수·Pass/Fail | 없음(표시) |
| `TaskSection.tsx` | 과제 한 덩어리의 껍데기(두꺼운 띠 + 제목 밴드 + 채점 기준 한 줄 + 오른쪽 `aside` — 스캔본 상태 배지) | 없음(레이아웃) |
| `WordScoreRows.tsx` | 낱말 해독 — 그룹(의미/무의미) sticky 플레이어 바 + 낱말 행. 녹음 없는 그룹은 X로 잠긴다 | **O/X** |
| `SentenceRows.tsx` | 문장 읽기유창성 — 문장·읽은 시간·어절 수 입력·플레이어를 한 행에(플레이어는 문장과 같은 칸 — 입력 칸(44px)과 한 줄로 묶으면 한 줄짜리 문장 밑에 빈 간격이 생긴다). 시간 칸은 친 글자를 칸이 들고 있다(`SecondsInput` 주석 — number 입력은 「4.」「0」을 지운다). 녹음 없는 문장은 입력 칸 대신 같은 크기의 점선 상자(`FixedCell`)에 계산값(제한 시간 · 0)을 보여 준다 — 행마다 값의 자리가 같아 세로로 훑어 읽힌다 | **읽은 시간(초) · 어절 수** |
| `WritingChips.tsx` | 낱말 쓰기(G1) — 낱말+O/X 칩 흐름 | 읽기 전용 |
| `SentenceWriteRows.tsx` | 문장 쓰기(G2) — 검사지처럼 어절을 나눠 표시 | 읽기 전용 |
| `ScanViewer.tsx` | 쓰기 기록지 스캔본 보기(확대·축소·회전·새 창). 스캔본 방식 검사에서만. 그림이 안 열리면 새 링크를 받는다(`onExpired`) | 없음(표시) |
| `ScanWritingRows.tsx` | 스캔본 방식 검사의 쓰기 — 낱말(G1) O/X, 문장(G2) 어절 수 0~N. 번호 = 기록지 칸 번호 | **O/X · 어절 수** |
| `Subtotal.tsx` | 소계 행(의미/무의미/총점, 문장은 정확 어절/읽은 시간/총점). 칸의 척도는 만점(`/ 14`)이나 단위(`2.12 어절/초`) 중 하나 — 섞이지 않게 유니온 | 없음(표시) |
| `PageAudio.tsx` | 페이지 녹음 재생 — 시도 전환(기본은 **마지막 차수**, 사용자 확정 2026-09-22 — 일시정지가 녹음 중에도 눌리게 된 뒤 잘린 1차가 흔해져서)·미녹음·제한시간 초과 배지 | 없음 |

**채점 입력을 받는 것은 낱말 해독과 문장 읽기유창성, 그리고 스캔본 방식 검사의 쓰기다.** 화면 방식
검사의 쓰기(칩·문장 쓰기 행)는 검사 중 검사자가 이미 기록한 값이라 여기서 다시 채점하지 않는다 —
읽기 전용인 것은 스타일 결정이 아니라 채점 소유권의 결과다(사용자 확정 2026-08-13). 스캔본 방식은
소유권이 담당자에게 있어(사용자 확정 2026-09-30) 입력 부품을 **따로**(`ScanWritingRows`) 둔다 —
읽기 전용 컴포넌트에 입력 UI를 붙이지 말 것. 저장 라우트도 같은 경계를 지킨다(화면 방식 검사의 쓰기는 409).

## 이 폴더 전체가 지키는 표기 규칙

- **미채점(`undefined`)과 0점을 절대 같게 그리지 않는다.** 없는 데이터를 0으로 세어 보이면
  "채점하지 않았다"가 "0점을 받았다"로 둔갑한다 — 이 화면이 가장 경계하는 오독이다.
  각 부품이 같은 규칙을 자기 방식으로 구현한다: `ScoreBand`는 "채점 전"이라고 **글자로** 쓰고,
  `Subtotal`은 숫자 자리를 비운 채 척도(만점 또는 단위)만 알리며(부분 점수도 흐리게 + "현재" 접두),
  칩·문장 쓰기 행은 `—`를 쓴다. 큰 `—`를 값 자리에 세우지 않는 것도 규칙이다 — 값이 있는 것처럼
  읽힌다.
- **색은 판정에만 쓴다.** O/X는 정오 판정이라 정반응 mint·오반응 rec-deep으로 칠하지만,
  점수 표기(0·1·2)는 색을 쓰지 않는다 — 0점은 두 어절을 다 틀린 것이지 문항을 "틀린" 것이
  아니어서, 경고색을 칠하면 없는 판정을 얹게 된다.
- **채점이 끝나지 않은 과제는 판정을 내지 않는다.** 완료 여부는 `lib/scoring.ts`의 `complete`가
  판정하고, 부품은 그 값을 받아 판정 배지를 감춘다.

셋째 규칙은 **결과보고서 PDF(`lib/pdf/report.ts`)와 같다** — 인쇄물도 미채점 과제의 판정 칸을 비운다.
한쪽만 고치면 화면과 공식 출력물이 어긋난다(앞의 두 규칙은 점수를 찍지 않는 결과보고서에는 해당이 없다).

## 상태·데이터

부품은 **채점 값** 상태를 갖지 않는다(보기 상태만 예외: `PageAudio`의 시도 선택 인덱스, `ScanViewer`의 확대·회전·깨짐, `SentenceRows`의 입력 중 글자, `WordScoreRows`의 막대 높이). 채점 값·저장·"저장 안 한 변경"
판정은 전부 `ResultSheet`가 소유하고, 부품은 값과 콜백만 받는다. 점수 계산은 `lib/scoring.ts`,
문항 목록은 `lib/items.ts` + `lib/forms/`에서 온다 — 배점 숫자를 부품에 적지 말 것.

## 화면 밖의 사실

- **공식 출력물은 이 화면이 아니라 결과보고서 PDF다.** 화면 인쇄(@page)는 작업 중 참고용이며
  `PageAudio`는 인쇄에서 통째로 숨는다(`print:hidden`).
- `AudioPlayer`(wavesurfer)는 지연 로드된다 — 재생기가 실제로 필요할 때만 청크를 받는다.
- `WordScoreRows`의 플레이어 바가 sticky인 이유는 "들으면서 찍기"가 이 화면의 핵심 동선이기
  때문이다. 그룹 래퍼가 relative라 다음 그룹에 닿으면 자연스럽게 교대한다.
