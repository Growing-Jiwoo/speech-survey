# components/admin/sheet/ — 결과지(채점 작업대) 부품

`components/admin/ResultSheet.tsx` **한 곳에서만** 쓰이는 부품 모음. 결과지를 한 파일에 두면
과제별 표기 규칙이 JSX 사이에 흩어져, "미채점을 어떻게 그리는가" 같은 규칙을 한 곳에서 확인할
수 없어 잘라냈다. 다른 화면에서 재사용하려고 만든 폴더가 아니다 — 공용으로 쓸 것은
`components/` 루트로 올린다.

| 파일 | 역할 | 채점 입력 |
|---|---|---|
| `ScoreBand.tsx` | 상단 총평 밴드 — 과제별 점수·Pass/Fail | 없음(표시) |
| `TaskSection.tsx` | 과제 한 덩어리의 껍데기(두꺼운 띠 + 제목 밴드 + 채점 기준 한 줄) | 없음(레이아웃) |
| `WordScoreRows.tsx` | 낱말 해독 — 그룹(의미/무의미) sticky 플레이어 바 + 낱말 행 | **O/X** |
| `SentenceRows.tsx` | 문장 읽기유창성 — 문장·어절 수 입력·플레이어를 한 행에 | **어절 수** |
| `WritingChips.tsx` | 낱말 쓰기(G1) — 낱말+O/X 칩 흐름 | 읽기 전용 |
| `SentenceWriteRows.tsx` | 문장 쓰기(G2) — 검사지처럼 어절을 나눠 표시 | 읽기 전용 |
| `Subtotal.tsx` | 소계 행(의미/무의미/총점) | 없음(표시) |
| `PageAudio.tsx` | 페이지 녹음 재생 — 시도 전환·미녹음·제한시간 초과 배지 | 없음 |

**채점 입력을 받는 것은 낱말 해독과 문장 읽기유창성 둘뿐이다.** 쓰기(칩·문장 쓰기 행)는 검사 중
검사자가 이미 기록한 값이라 여기서 다시 채점하지 않는다 — 읽기 전용인 것은 스타일 결정이 아니라
채점 소유권의 결과다(사용자 확정 2026-08-13). 읽기 전용 컴포넌트에 입력 UI를 붙이지 말 것.

## 이 폴더 전체가 지키는 표기 규칙

- **미채점(`undefined`)과 0점을 절대 같게 그리지 않는다.** 없는 데이터를 0으로 세어 보이면
  "채점하지 않았다"가 "0점을 받았다"로 둔갑한다 — 이 화면이 가장 경계하는 오독이다.
  각 부품이 같은 규칙을 자기 방식으로 구현한다: `ScoreBand`는 "채점 전"이라고 **글자로** 쓰고,
  `Subtotal`은 숫자 자리를 비운 채 만점만 알리며(부분 점수도 흐리게 + "현재" 접두),
  칩·문장 쓰기 행은 `—`를 쓴다. 큰 `—`를 값 자리에 세우지 않는 것도 규칙이다 — 값이 있는 것처럼
  읽힌다.
- **색은 판정에만 쓴다.** O/X는 정오 판정이라 정반응 mint·오반응 rec-deep으로 칠하지만,
  점수 표기(0·1·2)는 색을 쓰지 않는다 — 0점은 두 어절을 다 틀린 것이지 문항을 "틀린" 것이
  아니어서, 경고색을 칠하면 없는 판정을 얹게 된다.
- **채점이 끝나지 않은 과제는 판정을 내지 않는다.** 완료 여부는 `lib/scoring.ts`의 `complete`가
  판정하고, 부품은 그 값을 받아 판정 배지를 감춘다.

이 세 규칙은 **검사지 PDF(`lib/pdf/stamp-sheet.ts`)와 같다** — 인쇄물도 미채점 칸을 비우고,
문장 쓰기의 「0 1 2」 동그라미에 색을 쓰지 않는다. 한쪽만 고치면 화면과 공식 출력물이 어긋난다.

## 상태·데이터

부품은 상태를 갖지 않는다(예외: `PageAudio`의 시도 선택 인덱스). 채점 값·저장·"저장 안 한 변경"
판정은 전부 `ResultSheet`가 소유하고, 부품은 값과 콜백만 받는다. 점수 계산은 `lib/scoring.ts`,
문항 목록은 `lib/items.ts` + `lib/forms/`에서 온다 — 배점 숫자를 부품에 적지 말 것.

## 화면 밖의 사실

- **공식 출력물은 이 화면이 아니라 검사지 PDF다.** 화면 인쇄(@page)는 작업 중 참고용이며
  `PageAudio`는 인쇄에서 통째로 숨는다(`print:hidden`).
- `AudioPlayer`(wavesurfer)는 지연 로드된다 — 재생기가 실제로 필요할 때만 청크를 받는다.
- `WordScoreRows`의 플레이어 바가 sticky인 이유는 "들으면서 찍기"가 이 화면의 핵심 동선이기
  때문이다. 그룹 래퍼가 relative라 다음 그룹에 닿으면 자연스럽게 교대한다.
