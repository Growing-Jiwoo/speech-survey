# components/apply/ — 교사 신청 화면 컴포넌트

`/apply`(공개)에서만 쓰는 컴포넌트. 화면 오케스트레이션은 `app/apply/page.tsx`에 있다.

| 파일 | 역할 |
|---|---|
| `RosterEditor.tsx` | 명단 파일 업로드(.xlsx/.csv) → 고정 4칸 표(번호·이름·성별·생년월일) → 칸 수정. 파싱은 `lib/xlsx`+`lib/roster`, 확정 명단만 `onChange`로 올린다 |

## 파일은 브라우저에서만 읽는다

명렬표에는 주민등록번호가 들어 있을 수 있다. 파일을 서버로 올리지 않고 여기서 파싱해
**네 칸만** 서버로 보내면 그 값은 애초에 서버에 도달하지 않는다(`lib/xlsx.ts` 주석).

## 열 역할 지정 UI를 만들지 말 것

`lib/roster`가 알려진 머리글 이름으로만 열을 찾고, 못 찾으면 양식을 안내한다. 값 모양으로
추론하면 "반 번호 2"를 성별로 오인한다(프로토타입에서 확인).

## 성별 칸은 앱 `Select`(`size="grid"`)

타이핑 경로를 없애려면 드롭다운이어야 하는데, **네이티브 `select`는 쓰지 않는다.** 같은 폼의
학교·학년·반이 이미 앱 `Select`라, 한 화면에서 같은 역할의 칸이 OS 기본 모양과 앱 모양으로
갈리면 그 칸만 남의 것처럼 보인다(사용자 지적 2026-08-22). `size="grid"`가 옆 input과
높이(40px)·모서리(8px)·글자(14px)를 맞추고, 오류일 때 테두리만 붉어진다 — 배경까지 붉히면
같은 줄에서 성별 칸만 분홍이 된다(`cellCls`의 `bg-well`이 `badCls`의 `bg-rec/5`를 이겨
input들은 실제로 well로 그려진다).

## 못 읽은 칸도 교사에게 되돌려 준다

`lib/roster`가 못 읽은 칸을 **원문째** 실어 주므로(`RosterCells`), 한 칸이 틀린 줄도 나머지
세 칸은 파일 값 그대로 표에 남는다. 이걸 빈칸으로 지우면 교사는 "파일에 없던 값"과 "우리가
못 읽은 값"을 구분할 수 없고, 화면은 어느 쪽이든 "채워 주세요"라고 말한다 — 생년월일은
파일을 다시 열어 보지만 **성별은 기억으로 채우게 되고**, 그 오기는 임상 기록에 남는다.
줄 순서도 파일 그대로다(교사가 엑셀을 옆에 띄워 놓고 대조한다).

## 명단 유효성은 이 폴더가 소유한다

`onChange(roster | null)` 한 줄이 부모와의 계약 전부다 — 한 칸이라도 틀리거나, **번호가
겹치거나**, 표가 비면 `null`이고, 부모는 그것으로 제출 버튼을 잠근다. 번호 중복까지 여기서
막는 이유: 서버(`applySchema`)도 막지만 그 400은 어느 줄이 겹쳤는지 말해 주지 않는다. 통보는 **표를 바꾸는 함수(`commit`)에서**
하고 `useEffect`로 하지 않는다(부모가 매 렌더 새 `onChange`를 넘길 때의 루프 회피).

생년월일 칸은 값이 `normBirth`로 읽힐 때만 `type="date"`다. `type="date"`는 형식이 어긋난
값을 표시하지 못해, 파일에서 온 잘못된 값을 조용히 지워 버린다.
