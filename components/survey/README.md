# components/survey/ — 참여자(아동) 검사 화면 컴포넌트

만 6-7세 아동이 교사 보조 하에 사용하는 화면. **큰 터치 타깃, 즉각적 피드백, 오터치 방지,
평가 신호(칭찬/실망) 비노출**이 설계 원칙이다. `app/survey/page.tsx`가 **페이지 종류**에 따라
아래 컴포넌트를 골라 렌더한다(화면·녹음의 단위는 문항이 아니라 페이지다 — `lib/items.ts`의 `itemsFor(양식).pages`).
페이지 목록은 **세션의 학년**이 정한 검사지에서 나온다 — 쓰기 과제 화면이 학년마다 다르다.
그 검사지는 화면이 `lib/forms`에서 읽지 않고 **서버가 내려준다**(`hooks/useSurveyForm` → `POST /api/sessions/form`) —
문항을 공개 JS 청크에 싣지 않기 위해서다. 마이크 확인 화면은 양식이 필요 없어 그동안 받아 두므로 첫 검사에서는 기다림이 보이지 않는다.

**넓은 배치는 `tab`(700px — `app/globals.css`의 `--breakpoint-tab`)부터다** — 이 폴더와 `app/survey/page.tsx`가 모두 같은 기준을 쓴다.
종전 `lg`(1024px)에서는 세로로 놓은 태블릿(iPad mini 744 ~ 834px)이 휴대폰 배치로 떨어져 낱말이 26px였고, 검사 도중 태블릿을 돌리면
자극 크기가 바뀌었다(2026-10-21 태블릿 점검). `md`(768px)는 iPad mini 세로를 놓쳐 쓰지 않는다. 낱말은 휴대폰 26px · 태블릿 폭(700~1023px)
**세로·가로 모두 38px** · 그 이상 44px(높이 800px 이하면 38px)다 — 가로 태블릿은 높이가 낮아 38px이라 세로도 38px로 맞췄다(`ReadingPage` 주석).
낱말은 검사지처럼 4칸 격자(본 검사 4+3)에 놓고, 한 줄이 안 차는 연습 페이지(3개)만 **같은 칸 너비로 가운데에** 모은다 — 왼쪽부터 채우면
오른쪽 한 칸이 비어 한쪽으로 쏠려 보였다(사용자 확정 2026-10-21, 담당자 회신 아님).
문장은 휴대폰 22px(접힘)이고, 넓은 배치에서는 **그 양식의 가장 긴 줄이 한 줄에 드는 크기**(최대 26px, 네 문장이 같은 크기)다 — 26px로
고정했을 때 2학년 2학기 4번 둘째 줄이 PC 화면 칸(800px)보다 길어 마지막 어절만 셋째 줄로 넘어갔다(담당자 테스트 2026-10-22 「한 문장이
한 줄에는 들어오면 좋겠는데」). 줄 폭은 글꼴 실측값으로 계산하고(`lib/items` `sentenceFitEm`) 글자 크기는 칸 폭(cqi)에서 정한다(`ReadingPage` 주석). 크기 규칙은 사용자 확정(2026-10-22, 담당자 회신 아님).

## 녹음 저장은 낙관적이다 (2026-08-12)

`ReadingPage`는 업로드하지 않는다 — 녹음이 끝나면 `onRecorded(rec)`로 상위(`app/survey/page.tsx`)에
넘기고, 상위가 **완료로 먼저 표시한 뒤 백그라운드로 업로드**한다. 실패하면 그 표시를 되돌리고
`RetryBanner`를 낸다. 업로드를 기다리는 동안 화면을 잠갔더니 [다음] 버튼이 "모르겠어요"로 보이고
몇 초씩 멈춰 검사 흐름이 끊겼다(사용자 보고) — 그래서 이 화면에는 "저장 중" 대기 UI가 없다.
진행 중인 업로드는 헤더의 `저장 중…` 표시와 새로고침 경고(beforeunload)로만 드러난다.
