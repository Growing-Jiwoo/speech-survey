# components/results/ — 교사 결과지 화면

`/results/[token]`(학급 스코프 토큰)에서 교사가 본인 학급 결과지를 받는 화면. 스펙:
`docs/superpowers/specs/2026-09-22-teacher-results-download-design.md`.

| 파일 | 역할 |
|---|---|
| `ScanUpload.tsx` | 「쓰기 스캔본 올리기」 입구 카드와 확인 창(2026-09-30). 반 전체를 한 파일로(PDF·사진 여러 장도) 고르면 쪽마다 QR을 읽어 **누구 기록지인지 자동으로** 붙이고(`lib/scan-pages` → `lib/scan-mapping`), 못 읽은 쪽은 쪽 그림의 이름을 보고 선생님이 고른다. **모든 쪽이 정해져야**(아이 또는 「올리지 않음」) [올리기]가 켜진다. 한 쪽씩 올린다(`POST /api/results/<token>/scans`, 동시 3장, 한 장 90초 제한 — 넘으면 실패로 넘겨 [실패한 N쪽 다시 올리기]). 화질 경고는 없다(사용자 확정 2026-09-30). 입구 카드는 올릴 수 있는 아이(스캔 대기·이미 올림)가 있을 때만 보인다(부품은 스캔본 방식 검사가 있는 반이면 늘 붙어 있다 — 확인하는 사이 다시 받은 목록에서 대상이 사라져도 창이 닫히지 않게). 확인 창은 **바깥을 누르거나 Esc를 눌러도 닫히지 않는다**([취소]로만) — 쪽마다 고른 것이 한 번에 사라진다(Esc는 크게 보기만 닫는다). 쪽이 많으면 「N쪽 남음 ↓」이 다음 남은 쪽으로 옮겨 준다. 카드 밖에 파일을 떨어뜨려도 브라우저가 파일을 열어 화면을 떠나지 않게 막는다.<br>**짝짓기 전에 결과 목록을 다시 받는다**(`refreshTargets`, 쪽 읽기와 함께 돈다) — 열어 둔 지 오래된 탭은 그사이 제출·재검사된 아이를 모른다. 짝지을 때 쓴 목록(`snap`)으로 창 전체(이름·후보·올릴 검사)를 그린다. **재검사한 아이는 자동으로 붙이지 않는다**(「재검사를 했어요. M월 D일 검사 때 쓴 기록지가 맞으면 골라 주세요」 — 몇 차 기록지인지 종이만 보고는 모른다, 사용자 확정 2026-10-01). **빈 쪽**(QR 없는 거의 흰 쪽 — 양면 스캔의 뒷면)은 「올리지 않음」으로 둔다. 실패는 **다시 보낼 만한 것만**(연결·시간 초과·5xx·429) [실패한 N쪽 다시 올리기]로 모은다 — 나머지 4xx(채점 시작·대상 바뀜 등)는 다시 보내도 같아 쪽마다 까닭만 보인다. 「스캔 파일은 지워 주세요」는 다시 올릴 쪽이 남지 않았을 때만 알린다. ⚠️ 창의 제목 포커스 효과는 `useFocusTrap` **뒤에** 둔다(hooks/README) |
| `ResultsView.tsx` | `GET /api/results/<token>`을 읽어 요약 한 줄·아이별 행(재검사 펼침·체크박스)·[전체 PDF]/[선택 PDF]를 그린다. 401은 만료 화면(→ `/`), 그 외는 재시도. 다운로드는 `fetch → blob → a[download]`로 받아 로딩 표시를 낸다(앵커 직행은 무반응으로 보여 여러 번 누른다) 두 다운로드 버튼은 **확인 모달만 연다** — 받을 아이 명단(재검사가 있으면 차수까지)을 보여 주고 거기서 한 번 더 눌러야 요청이 나간다. 25장 병합은 서버가 몇 초를 쓰는 일이라 잘못 눌린 클릭 하나로 시작되면 안 된다(사용자 확정 2026-09-22, 담당자 회신 아님). 만드는 동안은 버튼 글자를 바꾸는 대신 **화면 전체를 덮는 공용 로딩 오버레이**를 쓴다 — 글자만 바뀌면 눌린 줄 모르고 다시 누른다 |

- 표의 계산(상태·판정·정렬·요약)은 전부 `lib/results.ts`가 한다 — 이 파일은 그린다. 다만 import는
  **`lib/results-view.ts`에서만** 한다 — `lib/results.ts`는 채점 사슬 때문에 `lib/forms`를 값으로 import해서,
  화면이 그것을 import하면 검사지 문항이 공개 JS에 실린다(빌드의 `scripts/check-client-bundle.ts`가 잡는다).
- 판정은 관리자 화면과 같은 **Pass/Fail**(사용자 확정 2026-09-22). 받을 수 있는 검사(`status === 'scored'`)만 체크 가능.
- **상태 칸은 `status`가 아니라 `sessionLabel`**(`lib/results-view`)을 그린다(사용자 확정 2026-09-30). 스캔본 방식은
  **스캔 대기 → 채점 중 → 채점 완료**로 바뀌고 채점 완료는 세 과제가 다 채점된 때다. 화면 방식은 종전 그대로다.
  받기는 두 방식 모두 A안 그대로라, 스캔 대기인 아이도 읽기 채점이 끝났으면 상자가 있다. 그래서 요약의
  「채점 완료 N명」과 [전체 PDF 다운로드 (N명)]의 숫자가 다를 수 있다(`summarize`의 `scored`·`downloadable`).
- 스캔본으로 채점된 쓰기 점수에는 작은 **「스캔」 배지**가 붙는다 — 선생님이 화면에서 표시한 점수와 구별된다
  (담당자가 스캔본 없이 종이로 채점한 경우에도 붙는다 — 방식으로 가른다).
- **재검사로 대체.** 스캔 대기인데 그 아이의 대상 검사(가장 최근에 제출된 검사)가 아닌 앞 차수는 「재검사로 대체」로
  그린다(`sessionLabel(s, 대상 id)`) — 올리면 기록지가 최근 검사로 가므로 그 검사에는 올릴 수 없다. 반대로 접힌 행의
  최신 검사가 중단된 재검사라 대상(앞 차수)의 스캔 대기가 가려지면 접힌 행에 「N차 스캔 대기」를 함께 단다 —
  요약의 「스캔 대기 N명」이 누구인지 찾을 수 있게.
- **다시 받기가 실패해도 결과가 이미 보이면 화면을 오류로 바꾸지 않는다**(위에 띠로만). 창으로 돌아올 때의 자동
  다시 받기(파일 선택 창이 닫힐 때도 돈다)가 한 번 실패했다고 화면이 바뀌면 스캔본 확인 창이 통째로 닫힌다.
  오류 화면은 보여 줄 결과가 없을 때만이다.
- **받을 때 「쓰기 채점 전 N명」 경고.** 받을 것 중 스캔본 쓰기가 아직 채점되지 않은 아이가 있으면 확인 창에
  명단과 함께 경고를 띄우고 버튼을 [취소] [완성된 N장만] [M장 모두 받기]로 바꾼다(완성된 것이 0장이면 둘째
  버튼은 없다). [완성된 N장만]은 그 아이들을 뺀 세션 id를 `?ids=`로 보낸다. 화면 방식의 빈 쓰기(A안)는 나중에
  채워지지 않으므로 여기 들지 않는다 — 종전대로 경고 없이 나간다.
- **기본 선택은 비어 있다.** 자동으로 채워 두면 고른 적 없는 교사가 「선택한 2장」을 보고 자기가 고른 줄 안다
  (사용자 지적 2026-09-22). 반 전체를 받는 길은 [전체 PDF 다운로드]가 따로 맡는다.
- 재검사 차수는 **배지**로 그린다(표·확인 모달 모두) — 어느 검사인지 가르는 값이라 회색 글자로는 안 띈다.
- 아이 행의 체크박스는 **그 아이의 채점 완료 차수 전부**를 맡는다(일부만 고르면 `indeterminate` 막대).
  종전에는 「최신 차수 하나」의 체크박스여서, 펼치면 같은 검사에 체크박스가 둘이 되고 2차만 골랐을 때
  이름 행이 꺼진 채라 상위처럼 보이는 칸이 거짓말을 했다(사용자 지적 2026-09-22).
- **받을 수 없는 행에는 체크박스를 그리지 않는다** — 아이 행이든 차수 행이든 같다. 잠긴 회색 상자는
  눌러도 반응이 없어 고장처럼 보이고, 「상자가 있으면 받을 수 있다」는 규칙 하나로 읽히게 하려는 것이다
  (사용자 확정 2026-09-23). 왜 못 받는지는 같은 줄의 상태 배지가 말한다.
- 녹음·요약표 CSV·행별 PDF는 **의도적으로 없다**(스펙 「화면에 없는 것」).

## 「채점 전」 — 되돌리기 가장 쉬운 결정

`complete[k] === false`인 과제는 점수 대신 **`채점 전`(mute 배지)**으로 그린다. 편의로 되돌리지 말 것:

- (화면 방식) 쓰기는 검사 중 검사자가 넣는 값이라 관리자가 나중에 채울 수 없다. 그래서 쓰기가 비어도
  `scored`로 보고 결과지를 내보내는데(A안), 그 대가로 `scores.writing`에 **0이 들어온다.**
  그 0은 「0점을 받았다」가 아니라 **「아직 채점 전」**이다 — `0/10`으로 찍으면 치르지도 않은
  과제에서 낙제한 아동으로 읽힌다. 임상적 오독이다.
- 같은 이유로 `verdict`는 세 과제가 모두 채점돼야 값을 갖는다(아니면 판정 칸이 `-`). 흔하다.
- 근거: **사용자 확정(2026-09-22) A안 「관리자와 동일」 — 담당자 회신이 아니라 개발 판단이다.**
  관리자 결과지(`components/admin/ResultSheet.tsx`)가 이미 그렇게 하고, 두 화면이 같은 아이를
  다르게 말하면 그 자체가 사고다.
- 그래서 표 아래 **범례**(`components/admin/BadgeLegend.tsx` — 폴더만 admin일 뿐 범용)를 상시 둔다.
  항목은 (스캔본 방식 검사가 있을 때만) `스캔 대기` · (대체된 검사가 있을 때만) `재검사로 대체` · `채점 전` · `Pass`/`Fail` · (`provisional`일 때만) `임시 기준 · 확정 전`이고,
  문구는 관리자 화면과 같은 말을 하되 관리자 전용 조작(채점 저장·미녹음 칸 잠금)은 뺀다.
