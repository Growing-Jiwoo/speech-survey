# docs/handoff-checklist/ — 담당자 확인 사항

담당자(임상 쪽)에게 **정해 주시거나 보내 주셔야 할 것**을 한 장으로 묶어 전달하는 문서다. 담당자는 이 PDF만
읽고 무엇을 보내고 무엇을 확인할지 알 수 있어야 한다 — 이 대화·저장소 맥락을 모르는 사람이 읽는다고 가정한다.

| 파일 | 무엇 |
|---|---|
| `선별검사_담당자_확인사항_초안.pdf` | 전달본(A4 1쪽, 2026-10-22 둘째 판). `checklist.html`을 뽑은 것 |
| `checklist.html` | PDF 원본. 판면은 `../manuals/src/style.css`를 함께 쓴다 |
| `checklist.md` | 같은 내용의 글 원본(문구 검토·윤문용). **HTML과 내용을 맞춰 둔다** |

## 넣지 않는 것

배경·경위(누가 언제 무엇을 말했는지)는 넣지 않는다 — 항목마다 **지금 상태**와 **필요한 것**만 쓴다(사용자 확정 2026-10-12).
보존 기한·검사 일정·도메인·요금제·「저장 실패」 표시는 담당자에게 묻지 않기로 해서 뺐다(사용자 확정 2026-10-12).
IRB 심의는 받지 않는다(사용자 확정 2026-10-12).
쓰기 기록지 양식·연습 문항·안내 동의 문구·결과보고서 표기는 2026-10-12판 PDF의 회신(담당자, 2026-10-22 사용자 전달)으로 닫혀 뺐다 —
고칠 곳으로 짚은 것(기록지 「받아쓰기」, 「채점에만 사용됩니다」, 승인 메일 「-다」체)은 반영했고 나머지는 그대로 쓴다.
코드 쪽 근거는 각 주석의 「담당자 확정(인계 확인 사항 PDF 2026-10-12판 회신 N번)」이다.
기준표 전 결과보고서 전달 여부는 넣지 않았다 — 아직 쓰는 학교가 없어 1번의 기준표가 먼저 온다는 전제다.
학교 검사를 기준표보다 먼저 시작하게 되면 그때 다시 물을 것(`docs/qa/2026-10-07-full-e2e.md` 「담당자에게 물을 것」 4번).

## 항목이 코드와 맞물리는 곳

담당자 회신이 오면 아래를 고치고, 이 문서의 해당 항목을 지운다.

| 항목 | 코드 |
|---|---|
| 1. 학년·학기별 문항과 판정 기준 | `lib/forms/g*.ts`(`cutoff`·`provisional`·문항 — 새 양식은 새 id로 추가), 3~6학년 폴백(`formFor`). 1·2학년 2학기는 2026-10-20 반영 |

1번의 2학기 확인 두 가지(읽기유창성 주의 기준 · 문장당 제한 시간)는 2026-10-20 회신으로 닫혔다(1학년 8.12 · 2학년 8.04, 3·4번 30초 — `lib/forms/g1s2.ts`·`g2s2.ts`). 코드가 바뀌면 이 문서도 고친다.

## 다시 뽑는 법

크롬 헤드리스 인쇄(`Page.printToPDF`, `preferCSSPageSize`, 배경 인쇄)로 뽑는다. 꼬리말은 설명서와 같은 꼴 —
7.5px, 좌우 16mm, 왼쪽 「읽기 선별검사 · 담당자 확인 사항 · 2026년 10월 판」, 오른쪽 쪽번호(`docs/manuals/README.md` 참고).
카드는 쪽 중간에서 끊기지 않게 두었다(`break-inside:avoid`). 내용을 늘린 뒤에는 쪽마다 제목만 남고 내용이 넘어가지 않았는지 확인할 것.
그림을 다시 넣게 되면 쪽 수를 줄이려고 작게 줄이지 않는다 — 담당자가 그림 속 문구를 읽어야 한다(본문 글자 7pt 아래 금지).

그림(신청 화면·승인 메일·시작 화면 고지·마이크 안내)은 2번 항목과 함께 2026-10-22에 뺐다 — 다시 넣어야 하면 git 이력의
이 README(2026-10-22 첫째 판)에 찍는 방법이 있다. 승인 메일 그림에는 반드시 **`FORMS_KEY` 없이** 만든 가짜 받아쓰기 낱말을 쓴다(저장소 공개).

꼬리말 글자색은 `#6E7994`다. 다시 뽑을 때는 고치기 전 HTML로 먼저 뽑아 커밋된 PDF와 글자·색·그림 위치가 같은지 확인하고 고친다.
