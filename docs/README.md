# docs/ — 설계 문서 아카이브

`superpowers/` 아래에 기능 단위의 설계·구현 계획 문서가 날짜순으로 쌓여 있다
(superpowers 워크플로: brainstorming → specs 설계 → plans 구현 계획 → 구현).

- `superpowers/specs/` — 기능 설계 문서(요구사항·의사결정·트레이드오프)
- `superpowers/plans/` — 구현 계획(작업 단위 분해)

설계 문서가 아닌 것도 있다. 이것은 **스냅샷이 아니라 현행 문서**라 코드가 바뀌면 함께 고친다.

- `manuals/` — 사용 설명서 2종(관리자·선생님)과 그 원본. [manuals/README.md](manuals/README.md)
- `handoff-checklist/` — 담당자에게 정해 받거나 받아야 할 것(PDF와 원본). 회신이 오면 해당 항목을 지운다.
  [handoff-checklist/README.md](handoff-checklist/README.md)
- `qa/` — 배포 전 E2E 체크리스트. 기능이 바뀌면 케이스도 함께 고친다.
  [2026-09-22-teacher-results-e2e.md](qa/2026-09-22-teacher-results-e2e.md) — 교사 결과지와 그것이 건드린 기존 기능
  [2026-10-07-full-e2e.md](qa/2026-10-07-full-e2e.md) — 배포 직전 전수 점검(전 화면·기능·특수 상황 170여 항목)과 그 결과(기록)
  [2026-10-12-full-e2e.md](qa/2026-10-12-full-e2e.md) — **현행 전수 점검 목록.** 10/7 판을 main `7a2a465` 코드와 한 줄씩 다시
  대조해 고친 것(배포 직후 운영 스모크·메일 절·결함 의심 표 포함). 다음 릴리스 때 결과 칸만 비우고 그대로 다시 돌린다

(보호자 동의서 양식 `consent/`는 2026-09-22에 삭제했다 — 담당자 확정(2026-09-21)대로 보호자 동의
수단은 학교의 개인정보 처리 절차에 맡기고 앱은 양식을 제공하지 않는다. 앱은 「법정대리인 동의를
받은 학생만 명단에 등록했다」는 교사 확인만 기록한다.)

**이 문서들은 작성 시점의 스냅샷**이다 — 현재 동작과 다를 수 있으므로 코드가 항상 우선한다.
새 기능의 맥락(왜 이렇게 만들었는지)을 찾을 때 참고.
