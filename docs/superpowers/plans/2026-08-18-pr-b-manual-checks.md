# PR B 수동 확인 목록 (로그인 뒤 화면)

관리자 비밀번호는 argon2id 해시로만 존재해 어떤 에이전트도 로그인할 수 없었다 —
`/admin/codes`의 승인·명단·배너 UI는 전부 **코드 읽기로만** 검증됐고 한 번도 실행된 적이 없다.
아래는 한 번의 로그인 세션에서 순서대로 돌리는 체크리스트다.

⚠️ **주의**: 코드 **`SGT2E4`**(서울가곡초등학교 1학년 3반, 담임 김선생)는 PR A 수동 검증 때
만든 **테스트 데이터**로, 현재 pending 상태로 남아 있다. 이 목록의 확인이 끝나면 **삭제**할 것.
**승인은 절대 누르지 말 것** — 실제로 `jiwookim@iportfolio.co.kr`로 승인 메일이 나간다.
승인·발송 실패·삭제 같은 파괴적 단계는 `/apply`로 새로 만든 임시 신청으로 대신한다.

## 1. 명단은 클릭 전까지 요청되지 않는다

- devtools Network 탭 열고 `/admin/codes` 로드 → `…/roster`로 가는 요청이 **0건**인지 확인
- 대기 목록의 아무 행에서 [명단 보기] 클릭 → `GET /api/admin/codes/[id]/roster` 요청이 **정확히 1건**
- 응답·표에 번호·이름·성별·생년월일이 **번호 오름차순**으로 표시되는지
- [명단 닫기] → 다시 [명단 보기] → react-query `staleTime`(5분, `app/providers.tsx`) 안이면
  **네트워크 요청이 다시 뜨지 않고** 캐시된 값이 그대로 보이는지

## 2. 승인 결과 배너 세 가지 — 전부 실물로는 처음 본다

`/apply`로 새 임시 신청을 만들어 쓴다(SGT2E4는 쓰지 않는다).

- 새 pending 행에서 [승인] → 배너 **"승인 완료 · 선생님께 코드 메일을 보냈어요"**,
  복사 버튼 **없음**
- 같은 학급을 다시 승인(또는 새로고침 후 재승인 시도) → 배너
  **"이미 승인된 학급이에요 · 메일 발송 여부는 알 수 없어요"** **+ [안내 문구 복사] 버튼 있음**
- 메일 실패 경로: `RESEND_API_KEY`를 일시적으로 깨뜨린 뒤(또는 teacher_email 없는 신청으로는
  재현되지 않으니 키를 무효화) 새 pending 행을 승인 → 배너
  **"승인은 됐지만 메일 발송에 실패했어요"** **+ [안내 문구 복사] 버튼 있음**
  (확인 후 `RESEND_API_KEY`는 반드시 원래 값으로 되돌릴 것)

## 3. [안내 문구 복사]

- 복사 버튼 클릭 → 아무 텍스트 입력창에 붙여넣기
- **교사 이름 · 학교 · 학급 코드 · 검사 주소**가 모두 들어 있는지(`lib/format.ts`의
  `approvalNoticeText` — 동의서 회수 안내 문구도 포함되는 게 정상)
- **검사 주소가 승인 응답의 `surveyUrl`과 같은지**, 즉 지금 브라우저에서 보고 있는 host가 아니라
  **`APP_URL`(설정돼 있다면)과 일치하는지** 확인 — 다르면 버그

## 4. 승인 배너의 안내(announce) + 포커스

- 스크린리더 사용 또는 Tab 키만으로 확인: 승인 직후 방금 눌렀던 [승인] 버튼이 딸린 행이
  목록 갱신으로 사라지는데, 그때 포커스가 `<body>`로 떨어지지 않고 새로 뜬 배너
  (`role="status"`)로 옮겨가는지, 스크린리더가 그 내용을 읽어주는지

## 5. Pending [삭제] 확인 모달

- 대기 행의 [삭제] 클릭 → 모달이 **명단 인원 수**("학생 명단 N명도 함께 삭제되며")와
  **되돌릴 수 없음**을 명시하는지
- 확인 → 삭제 후 해당 학급의 `class_roster` 행이 함께 사라졌는지(DB 또는 재조회로 확인)

## 6. 직접 발급(active) 경로는 그대로인지

- `/admin/codes`에서 학교·학년·반·담임·연락처 입력해 코드 발급
- **발급 완료 패널**이 뜨고(코드 표시 + 복사 버튼), 발급 목록에 그 행이 **세션 0건**으로 나타나며
  [삭제] 버튼이 동작하는지
- 이 과정이 pending(대기) 섹션에 아무 영향을 주지 않는지

## 7. 로그아웃 시 명단 캐시가 비는지

- 아무 대기 행의 명단을 펼쳐 이름이 보이게 한 뒤 로그아웃 → 다시 로그인
- `/admin/codes` 진입 시 명단 패널이 **접힌 상태로 시작**하고, 다시 펼치면 **재요청**하는지
  (로그아웃 시 `queryClient.clear()`가 `adminKeys.roster` 캐시를 지우는지 — `AdminDashboard.logout`)
