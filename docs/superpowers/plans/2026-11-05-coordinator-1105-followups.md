## A. 명단 빼기·되살리기·직접 입력 자동 추가 — `feat/roster-transfer`

출처: 빼기는 답장에서 약속(2026-11-05). 담임·관리자 **둘 다** 뺄 수 있게, 되살리기, 직접 입력 시 명단 자동 추가는
**사용자 확정(2026-11-05) — 담당자 회신 아님.**

- **DB(migration 009):** `class_roster.removed_at timestamptz`(null = 명단에 있음) · `class_roster.consented_at timestamptz`
  (null = 신청 때 함께 올라온 아이 — 동의 확인은 `class_codes.applied_at`). 지우지 않고 표시만 한다 → 되살리기는 표시를 지우는 것.
- **명단을 읽는 곳은 뺀 아이를 제외한다:** 시작 화면 드롭다운·「명단 N명」(`rosterWithTested`), 명단 모드 세션 생성(`/api/sessions`),
  쓰기 기록지 인쇄(같은 응답). 검사 기록(`sessions`)은 손대지 않는다.
- **교사 결과지(`/results/<토큰>`):** 아이 줄마다 [명단에서 빼기](확인 창 「검사 기록은 남아요」). 뺀 아이는 표·요약·[전체 PDF]에서
  빠지고 아래 「명단에서 뺀 학생 N명」에 모여 [되살리기]가 있다. 뺀 아이의 검사 결과를 받으려면 되살린다(개발 판단 — 바꿀 수 있음).
  라우트: `POST /api/results/<토큰>/roster` `{ childNo, removed: boolean }`(학급 스코프 토큰이 권한).
- **관리자 학급 코드 화면:** 승인된 학급에도 [명단 보기(N명)] → 번호·이름·성별 + [빼기]/[되살리기]. 라우트:
  `GET /api/admin/codes/<id>/roster`가 `removed`를 함께 싣고, `PATCH` 같은 경로 `{ childNo, removed }`.
- **직접 입력 자동 추가(시작 화면):** 명단이 있는 학급에서 「명단에 없는 학생이에요」로 입력하면 확인 창에 체크 한 칸 —
  「이 학생을 명단에 추가해요(법정대리인 동의를 받은 학생이에요)」(기본 꺼짐, 동의 체크를 미리 켜 두지 않는다). 켜고 시작하면
  세션을 만들면서 명단에 넣고 `consented_at`을 적는다(세션의 동의 기록도 그 시각). 끄면 지금처럼 검사만 한다.
  - 그 번호가 명단에 **있으면** 추가하지 않는다(지금의 「N번은 명단의 ○○ 학생 번호예요」 경고 그대로, 체크 칸을 숨긴다).
  - 그 번호가 **뺀 아이** 자리면 그 줄을 새 아이 값으로 덮어 되살린다(번호는 학급 안에서 unique).
  - 명단이 없는 학급(관리자 직접 발급)은 체크 칸이 없다.
- 승인 안내 3채널에 「전학 간 학생은 결과지 화면에서 명단에서 뺄 수 있어요」 한 줄.

## B. 신청 순번 — `feat/apply-seq`

출처: 답장 3번(2026-11-05). 6자리 학급 코드는 반 명단을 여는 열쇠라 엑셀·아동 코드에 쓰지 않는다(개발 판단).

- **DB(migration 010):** `class_codes.apply_seq int unique not null` — 기존 행은 `coalesce(applied_at, created_at)` 순으로 1부터,
  새 행은 시퀀스로. 관리자 직접 발급 학급도 순번을 받는다.
- 관리자 학급 코드 화면(신청 대기·발급 목록)에 `#017`처럼 보인다.
- 아동 코드 `lib/child-code.ts` `childCode(applySeq, childNo)` → `017-03`(3자리·2자리, 넘치면 그대로 늘린다). **저장하지 않고**
  엑셀(D)을 만들 때 계산한다.

## C. 학기 구분 — `feat/semester-split`

출처: 답장 2번(2026-11-05). 실제로 필요한 것은 1학기에 참여한 반이 2학기를 맞는 2027년 9월이다.

- **학기 열쇠** = 검사 시작일(KST)의 학년도(3월~다음 해 2월)와 학기(`semesterOf` — 양식 고르는 규칙과 같다). `lib/format`에
  `termOf(iso) → { year, semester }`·`termLabel`.
- **교사 결과지:** 재검사 차수는 **같은 학기 안에서만** 센다. 같은 아이의 다른 학기 검사는 2차가 아니다. 학기 고르기(지금 학기 기본,
  검사가 있는 학기만 보인다) → 그 학기 검사로 표·요약·받기. 대표 검사·「N차 미제출」도 학기 안에서.
- **관리자 목록:** 「학기」 칸(예 `2026-2학기`)과 학기 필터.
- **시작 화면:** 「검사 완료 N명」·드롭다운 「검사함」 배지·중복 검사 경고는 **지금 학기** 검사만 센다. 스캔 대기도 지금 학기.
- **쓰기 스캔본:** 올리는 기록지가 붙을 검사(`scanUploadTarget`·`latestSubmittedSessionId`)는 지금 학기 안에서 찾는다.

## D. 엑셀 내보내기 — `feat/excel-export`(B 위에 쌓음)

담당자 확정(2026-11-06): 아동 코드만(이름·생년월일 없음) · 문항별 O/X · 문장 읽기유창성은 문장별 정확 어절 수·초·원점수 ·
재검사는 마지막 검사만(담당자가 채점 전에 나머지를 지운다). 관리자 화면 [전체 데이터 받기] → `GET /api/admin/export.xlsx`.

- 행: 학급·번호·학기마다 마지막 제출 검사 하나. 칸: 아동 코드 · 학년 · 학기 · 성별 · 검사일 · 양식 · 문항별 값 · 과제 총점·판정 · 체크리스트.
- 문항이 양식(학년×학기)마다 달라 **양식마다 시트 하나**, 머리글은 실제 낱말 대신 문항 번호(개발 판단).
- 값은 관리자 결과지·결과보고서와 같은 채점 사슬(미녹음 고정값 포함). 2학년 문장 쓰기는 0·1·2라 숫자로 싣는다.
- xlsx는 외부 라이브러리 없이 쓴다(`lib/xlsx.ts`가 읽기를 그렇게 하는 것과 같은 방침).

## 하지 않는 것

- 쓰기 스캔본 통일 — 교사연수 결과를 보고 정한다.
- 학년을 넘는 아동 연결(이름·생년월일 대조) — 담당자가 묻지 않았다.

## 공통

커밋 전 `npm run typecheck && npm run lint && npm test && npm run build`. 코드를 고치면 그 폴더 README·주석을 같은 커밋에서.
마이그레이션은 **코드 배포보다 먼저** 운영 DB SQL Editor에서 실행(재실행 안전하게 쓴다). 실제 문항 낱말을 어디에도 적지 않는다.
