# KODYS-G2 (초등 2학년 검사지) 대응 Implementation Plan

**Goal:** 초등 2학년이 **G2 검사지 그대로** 검사받고 채점되고 인쇄된다. 지금은 학년을 2로 골라도 G1 문항이 나온다.

**원본:** `assets/forms/kodys-g2.pdf` (담당자 배포 `초등 2학년 선별검사 양식（가안）.pdf`). **가안이다** — 확정본이 오면 파일 교체 + 좌표 재추출.

---

## G1과 무엇이 다른가

| 과제 | G1 | G2 |
|---|---|---|
| 낱말 해독 | 의미 7 + 무의미 7 = /14, 30초 | **같음** (낱말만 다름) |
| 문장 읽기유창성 | 4문항 7·7·8·14 = /36, 40초 | 4문항 7·8·9·11 = **/35**, 40초 |
| 쓰기 | **낱말 쓰기** — 낱말 10개, 낱말당 1점 = /10 | **문장 쓰기** — 문장 5개, **어절당 1점(0·1·2)** = /10 |
| 쓰기 중단 규칙 | 의미 낱말 **첫 3개 연속** 오반응 | **첫 문장** 오반응 |
| 검사자 체크리스트 | 5개 영역 | **같음** |

**핵심은 쓰기 과제가 다른 종류의 과제라는 것이다.** G1은 문항당 O/X(boolean), G2는 문항당 0~2점(정수). 화면·저장·채점·인쇄가 모두 갈린다.

부수적으로 **앱 전체가 아직 단일 양식**이다(`lib/items.ts`의 `const FORM = DEFAULT_FORM`). 학년별 문항을 내려면 이 상수를 세션의 학년으로 바꿔야 한다 — 이번 작업의 절반은 그 배선이다.

---

## 검사지에서 확인해야 할 것 (담당자 회신 필요)

작업은 아래 해석으로 진행하고, 회신이 오면 상수 하나만 바꾸면 되도록 한 곳에 모아 둔다.

1. **낱말 해독 중단 규칙 문구가 G1 그대로다** — "…문장 읽기유창성 과제와 **낱말 쓰기** 과제를 실시하지 않습니다." G2에 낱말 쓰기 과제는 없다. 문장 쓰기를 가리키는 것으로 읽고 구현한다.
2. **"첫 문장 오반응"의 정의** — 문항 배점이 0·1·2인데 무엇을 오반응으로 볼지 검사지에 없다. **0점(두 어절 모두 오답)을 오반응으로** 본다(`lib/survey-flow.ts`의 `SENTENCE_WRITE_WRONG_AT`). 1점도 오반응이라면 이 상수만 바꾼다.
3. **Pass 기준** — G1과 마찬가지로 임시값. 만점이 달라졌으므로(문장 36→35) G1 비율을 그대로 옮겨 둔다. `PROVISIONAL_CRITERIA` 배지가 화면·인쇄물에 계속 붙는다.

## 설계

### 1) 양식이 쓰기 과제의 종류를 들고 있는다

```ts
// lib/forms/index.ts
export type WritingTask =
  | { kind: 'word';     meaning: string[]; nonsense: string[] }  // 낱말당 1점
  | { kind: 'sentence'; sentences: string[] }                    // 어절당 1점
```

`SurveyForm.writeMeaning`/`writeNonsense` → `SurveyForm.writing`으로 대체. 판별 유니온이라 새 과제 종류를 빠뜨리면 컴파일이 깨진다.

### 2) 문항·페이지를 양식별로 만든다

`lib/items.ts`의 모듈 상수(`ITEMS`·`PAGES`·`ITEM_TOTALS`…)를 `itemsFor(form)` 하나로 모은다(양식 객체 기준 메모이즈).
호출부는 `itemsFor(formForGrade(grade))`. 진행 화면은 `SurveyState.grade`로 양식을 고른다(`SCHEMA_V` 4→5).

문항 코드 네임스페이스: 읽기 `rw`·`rs`, 낱말 쓰기 `ww`, **문장 쓰기 `sw`**, 연습 `pw`, 페이지 `p_`.

### 3) 저장 — 새 테이블을 만들지 않는다

문장 쓰기 점수는 `(item_code, words int)` 모양이라 **기존 `sentence_scores`를 그대로 쓴다**(`sw01`~`sw05`). 마이그레이션 추가 없음.

단 하나 손봐야 할 곳: `saveScores`의 "이번에 안 보낸 문장 점수 삭제"가 `sw*`까지 지운다. 관리자 채점이 소유하는 코드(`rs*`)로만 삭제 범위를 좁힌다. **테스트로 고정한다.**

### 4) 채점

`scoreSession(form, input)`. `TASK_MAX`·`READ_MAX`·`PASS_MARK`가 양식에서 나온다.
과제 키 `wordWriting` → `writing`(두 과제 종류의 공통 이름).

### 5) 인쇄 — 인쇄된 "0 1 2" 중 획득 점수에 동그라미

`SheetLayout.writing`도 판별 유니온으로 나눈다. 좌표는 손으로 재지 않는다:
`scripts/extract-form-layout.mjs`를 양식 인자를 받도록 일반화하고, 숫자 중심은 600dpi 렌더에서 실측한 값을 쓴다(체크리스트 네모와 같은 방식).

## 검증

```bash
npx tsc --noEmit && npm run lint && TZ=UTC npx vitest run && npm run build
```

PDF 육안 확인은 `pdftoppm -r 400`으로 스탬핑 결과를 띄워 원본과 겹쳐 본다.

**검사지가 절대 기준이다.** `tests/forms.test.ts`의 `SHEET_G2`는 낱말 14개·문장 4개·쓰기 문장 5개를 글자 단위로 고정한다. 무의미 낱말(`고춘 삭핌 찬축 닺고 구말 앍아 딻아`)은 뜻이 없어 오타가 눈에 띄지 않는다 — 이 배열을 코드에 맞춰 고치지 말 것.
