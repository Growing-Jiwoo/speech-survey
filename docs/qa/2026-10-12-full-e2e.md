# 전수 점검 체크리스트 (2026-10-12판)

실제 학교 배포 직전, 앱의 **모든 화면·기능·특수 상황**을 한 번씩 밟는 목록이다. 직전 판
[2026-10-07-full-e2e.md](2026-10-07-full-e2e.md)를 main `7a2a465`(PR #111까지) 코드와 한 줄씩 다시 대조해 썼다 —
10/7 이후 바뀐 것(#90~#96 수정, #100 문구 윤문, #101 신청 안내, #110 정식 도메인·메일 링크 새 탭)과 그때 빠졌던
분기·오류 문구·경계값을 채웠다. **10/7 판의 결과 기록은 그 파일에 그대로 남긴다.** 이 판은 결과 칸이 비어 있다 —
다음 릴리스 때도 결과 칸만 비우고 다시 돌린다.

화면 문구는 **코드에서 글자 그대로 옮겼다**(「」 안). 다르게 보이면 문서가 아니라 화면을 의심하고, 코드를 고쳤다면
같은 커밋에서 이 문서도 고친다(CLAUDE.md §3).

## 환경과 원칙

- **운영**(`https://lidislab.com`, 그날의 main 해시를 여기 적는다, Vercel 함수 리전 icn1)에서 실제로 누른다.
  옛 주소 `speech-survey.vercel.app`도 같은 앱이 열리지만(리다이렉트 없음 — 도메인 전환 문서의 설계) 점검은 정식
  도메인으로 하고, 옛 주소는 Z·A38에서만 본다.
- **점검 당일 운영에 실제 학급이 있는지 먼저 확인한다.** 있으면 운영에서는 읽기만 하는 확인과 스모크(Z)만 하고,
  나머지는 로컬·Preview에서 한다. 시험 데이터는 학급 **TEST24**(대구가창초 1-2)의 번호 **90~99**와 새로 만든 시험
  학급만 쓴다.
- ⚠️ **운영 메일은 이제 실제로 나간다**(10/12부터 Production에 `MAIL_TO_OVERRIDE` 없음). 운영에서
  - `/apply` 신청 → **담당자**(`ADMIN_NOTIFY_EMAIL`) 메일함으로 알림이 간다.
  - [승인]·[결과지 받기] → 그 학급에 **등록된 담임 주소**로 간다.

  그래서 메일 흐름은 ⓐ 로컬(`.env.local`의 `MAIL_TO_OVERRIDE` = 점검자 본인, `APP_URL` 비움 → 링크가 localhost) 또는
  ⓑ Preview 배포(override·알림 모두 개발자)에서 돌리고, **점검자가 직접 받은 메일**로 문구·발신자·링크·새 탭 열림까지
  본다. 운영에서 누를 때는 **담임 이메일이 점검자 본인인 시험 학급**으로만 누른다(U 절).
- 결과지 토큰: 로컬에서 서명한 토큰은 운영에서 401(키가 다름 — 정상). Preview와 운영은 키·DB가 같아 Preview에서
  받은 링크도 운영에서 열린다.
- CSP처럼 운영 빌드에서만 달라지는 것은 로컬 `npm run build && npm start`(운영과 같은 nonce·strict-dynamic)나 운영에서 본다.
- 마이크는 **합성 신호**(`getUserMedia`를 발진기로 대체), 인쇄는 `window.print`를 가로채 **인쇄 직전까지**. 단 「실기기」
  표시 행은 진짜 기기·마이크·프린터로 한다.
- 네트워크 실패는 DevTools(Offline·요청 차단·느린 프로필) 또는 콘솔에서 `fetch`를 바꿔 낸다(H 절 끝의 「재현 도구」).
  콘솔 대체는 CSP와 무관해 운영에서도 쓸 수 있고 새로고침하면 풀린다.
- **운영에서 하지 않는 것**: 로그인 잠금 시험(C6 — 그 IP 전체가 10분 잠긴다) · 시험용이 아닌 데이터의 영구 삭제(세션·코드·
  스캔본 연결 해제는 확인 창까지) · `/apply` 신청(담당자에게 메일이 간다 — 로컬·Preview에서).
- 실메일은 **점검자 본인 주소로 가는 것만** 보낸다.
