## 원본과 다시 만드는 법

`src/`에 HTML·CSS·화면 캡처가 들어 있다. PDF는 **크롬 헤드리스 인쇄**로 만들었다
(A4, 여백 18/16/16mm, 머리말 없음, 꼬리말에 「읽기 선별검사 · 문서명 · 2026년 10월 판」과
쪽번호). **판 표기는 표지와 꼬리말 두 곳에 있다** — 내용을 고쳐 다시 뽑을 때 둘을 함께 올릴 것.

```
src/
  style.css      두 문서가 공유하는 판면
  manual.html    관리자용
  teacher.html   선생님용
  shots/         실제 화면 캡처 32장(2배 해상도) — 설명서에 실제로 쓰는 것만 둔다
```

캡처는 **로컬 개발 서버를 띄우고 실제로 검사를 한 건 끝까지 진행하며** 찍은 것이다
(가짜 마이크 입력으로 마이크 확인을 통과시켰다). 화면이 바뀌면 그 화면만 다시 찍어
같은 파일명으로 덮으면 된다.

  개발 서버는 운영 DB를 보므로 학급 코드 목록에 실제 주소가 뜬다. 화면 글자만 바꾸고 데이터는 건드리지 않는다.

## 그림 규칙 — 자르지 말 것

**화면 캡처를 잘라서 지면에 맞추지 않는다.** 앱 화면은 세로로 긴 형태(마이크 확인 0.77 ·
낱말 읽기 1.16)라, 넓은 단에 맞추려고 높이를 지정하고 `object-position`으로 밀면
그림마다 규칙이 달라져 억지스러워진다(실제로 그렇게 만들었다가 전면 수정했다).

지켜야 할 것은 셋이다.

1. **자연 비율 그대로 둔다.** `height`·`object-position`·`overflow:hidden`을 새로 쓰지 않는다.
2. 세로로 긴 화면은 **62mm 그림단(`.figcol`)**에 넣고 본문을 옆에 흘린다.
   가로로 넓은 화면(관리자 화면 대부분, 1.7~4.7)은 본문 폭에 그대로 놓는다.
3. 캡처가 지면에 안 맞으면 **CSS가 아니라 캡처를 고친다** — 뷰포트를 조절해 다시 찍는다.
   시작 화면(0.50 → 0.75)과 신청 화면(0.39 → 0.89)이 그렇게 고친 것이다.

여러 장을 나란히 비교하는 **띠(`.strip`)**에만 틀 높이를 맞춘다. 이것은 자르는 것이 아니라
`object-fit:contain` 레터박스이며, 캡션 줄이 어긋나는 것을 막기 위함이다.

**쪽을 억지로 채우지 않는다.** 절 끝에 여백이 남는 것은 정상이다. 채우려고 상자를 옮기기
시작하면 위의 규칙이 다시 무너진다.

## 함께 고칠 것

고칠 것 — 문서가 뒤처지면 인수받은 담당자가 화면과 다른 설명을 읽게 된다.

## 설명서에 넣지 않는 것

설명서는 **화면 사용법만** 다룬다(사용자 확정 2026-09-28, 2026-10-08에 다시 확정 — 「글이 많아 이해가 어렵고, 개발·설계자만 알면 될 내용이 들어 있다」).
각 장은 **한 줄 설명 + 순서대로 누르는 단계 + 캡처**로만 쓴다. 넣지 않는 것: 왜 그렇게 만들었는지(설계 근거), 내부 동작(QR에 담긴 값·저장 방식·캐시),
규칙이 정해진 경위(담당자·사용자 확정 이력), 법 조항·파기 절차·용량 같은 운영 이야기, 「녹음이 외부로 나가나요」 같은 시스템 설명.
경고 상자는 **되돌릴 수 없는 동작**(삭제·제출·새로 시작)과 꼭 지킬 것에만 둔다. 운영 주체가 정할 것(Pass 기준 · 보존 기한 ·
3~6학년 검사지 · 도메인과 발신 메일)과 넘겨받을 계정(GitHub·Vercel·Supabase·Resend)은 관리자용 8장에
있었으나 뺐다. 설명서에 다시 넣지 말 것. **아직 정해지지 않은 것**(담당자 확인 대기, 물어볼 거리, 「임시 기준 · 확정 전」
같은 확정 전 사정)도 넣지 않는다 — 이미 정해진 규칙과 지금 앱이 하는 동작만 적는다(사용자 확정 2026-10-08).
(문의처는 사용자 확정 2026-09-22로 종결됐다 — 「담당자에게 문의」로만 안내하고 연락처 값은
앱에 두지 않는다. `lib/mail.ts` 참고.)
