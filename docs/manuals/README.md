## 원본과 다시 만드는 법

`src/`에 HTML·CSS·화면 캡처가 들어 있다. PDF는 **크롬 헤드리스 인쇄**로 만들었다
(A4, 여백 18/16/16mm, 머리말 없음, 꼬리말에 문서명과 쪽번호).

```
src/
  style.css      세 문서가 공유하는 판면. 아동용만 별도 판면(child.html 안에 인라인)
  manual.html    관리자용
  teacher.html   검사 진행자용
  child.html     아동용 — 글자가 크고 문장이 짧다(읽기가 어려운 아이가 대상)
  shots/         실제 화면 캡처 42장(2배 해상도)
```

캡처는 **로컬 개발 서버를 띄우고 실제로 검사를 한 건 끝까지 진행하며** 찍은 것이다
(가짜 마이크 입력으로 마이크 확인을 통과시켰다). 화면이 바뀌면 그 화면만 다시 찍어
같은 파일명으로 덮으면 된다.

## 그림 규칙 — 자르지 말 것

**화면 캡처를 잘라서 지면에 맞추지 않는다.** 앱 화면은 세로로 긴 형태(마이크 확인 0.77 ·
낱말 읽기 1.16)라, 넓은 단에 맞추려고 높이를 지정하고 `object-position`으로 밀면
그림마다 규칙이 달라져 억지스러워진다(실제로 그렇게 만들었다가 전면 수정했다).

지켜야 할 것은 셋이다.

1. **자연 비율 그대로 둔다.** `height`·`object-position`·`overflow:hidden`을 새로 쓰지 않는다.
2. 세로로 긴 화면은 **62mm 그림단(`.figcol`)**에 넣고 본문을 옆에 흘린다.
   가로로 넓은 화면(관리자 화면 대부분, 1.7~4.7)은 본문 폭에 그대로 놓는다.
3. 캡처가 지면에 안 맞으면 **CSS가 아니라 캡처를 고친다** — 뷰포트를 조절해 다시 찍는다.
   시작 화면(0.50 → 0.75)과 신청 화면(0.39 → 0.89)이 그렇게 고친 것이다.

여러 장을 나란히 비교하는 **띠(`.strip`)**에만 틀 높이를 맞춘다. 이것은 자르는 것이 아니라
`object-fit:contain` 레터박스이며, 캡션 줄이 어긋나는 것을 막기 위함이다.

**쪽을 억지로 채우지 않는다.** 절 끝에 여백이 남는 것은 정상이다. 채우려고 상자를 옮기기
시작하면 위의 규칙이 다시 무너진다.

## 함께 고칠 것

설명서는 앱 문구·정책을 그대로 옮겨 적은 곳이 많다. 아래가 바뀌면 **설명서도 같은 커밋에서**
고칠 것 — 문서가 뒤처지면 인수받은 담당자가 화면과 다른 설명을 읽게 된다.

| 코드가 바뀌면 | 설명서에서 고칠 곳 |
|---|---|
| `lib/scoring.ts`의 `PROVISIONAL_CRITERIA`·`passMark` | 관리자용 4장 「Pass 기준은 아직 임시 숫자입니다」 |
| `lib/consent.ts`의 `RETENTION_LABEL`·`SURVEY_NOTICE` | 관리자용 6장·8장, 검사 진행자용 1장 |
| `lib/forms/`에 3~6학년 검사지 추가 | 관리자용 5장·8장 ③, 「1학년 양식으로 나갑니다」 삭제 |
| `MAIL_TO_OVERRIDE` 해제(도메인 인증) | 관리자용 8장 ④ |
| 배포 주소 변경 | **세 문서 전부** — 표지·본문의 `speech-survey.vercel.app` |

지금 쓰는 주소는 Vercel 기본 주소다. 정식 도메인을 사면 세 문서의 주소를 모두 바꿔야 한다.

## 아직 정해지지 않은 것

관리자용 8장에 **운영 주체가 결정해야 할 네 가지**를 모아 두었다 — Pass 기준 · 보존 기한 ·
3~6학년 검사지 · 도메인과 발신 메일. 인수인계 때 이 절을 먼저 짚을 것.
(문의처는 사용자 확정 2026-09-22로 종결됐다 — 「담당자에게 문의」로만 안내하고 연락처 값은
앱에 두지 않는다. `lib/mail.ts` 참고.)
