## 원본과 다시 만드는 법

`src/`에 HTML·CSS·화면 캡처가 들어 있다. PDF는 **크롬 헤드리스 인쇄**로 만들었다
(A4, 여백 18/16/16mm, 머리말 없음, 꼬리말에 「읽기 선별검사 · 문서명 · 2026년 9월 판」과
쪽번호). **판 표기는 표지와 꼬리말 두 곳에 있다** — 내용을 고쳐 다시 뽑을 때 둘을 함께 올릴 것.

```
src/
  style.css      두 문서가 공유하는 판면
  manual.html    관리자용
  teacher.html   선생님용
  shots/         실제 화면 캡처 45장(2배 해상도)
```

캡처는 **로컬 개발 서버를 띄우고 실제로 검사를 한 건 끝까지 진행하며** 찍은 것이다
(가짜 마이크 입력으로 마이크 확인을 통과시켰다). 화면이 바뀌면 그 화면만 다시 찍어
같은 파일명으로 덮으면 된다.

2026-09-28에 12장을 다시 찍으며 지킨 것(다음에 찍을 때도 같게):
- **실제 메일 주소·전화번호는 예시 값으로 바꿔 찍는다**(`teacher1@school.example.kr`, `01000000000`) —
  개발 서버는 운영 DB를 보므로 학급 코드 목록에 실제 주소가 뜬다. 화면 글자만 바꾸고 데이터는 건드리지 않는다.
- Next 개발 표시기(왼쪽 아래 「N」)를 지우고, 자동 포커스 테두리를 풀고, `scrollbar-gutter`를 끈 상태로 찍는다 —
  안 끄면 모달이 뜬 화면 오른쪽에 흰 띠가 남는다.
- 검사 화면은 **이미 있는 테스트 세션**을 로컬 키로 열어 찍고, 녹음 중 화면은 멈추지 않고 닫는다 —
  멈추면 녹음이 업로드돼 운영 DB에 기록이 생긴다.

## 그림 규칙 — 자르지 말 것

**화면 캡처를 잘라서 지면에 맞추지 않는다.** 앱 화면은 세로로 긴 형태(마이크 확인 0.77 ·
낱말 읽기 1.16)라, 넓은 단에 맞추려고 높이를 지정하고 `object-position`으로 밀면
그림마다 규칙이 달라져 억지스러워진다(실제로 그렇게 만들었다가 전면 수정했다).

지켜야 할 것은 셋이다.

1. **자연 비율 그대로 둔다.** `height`·`object-position`·`overflow:hidden`을 새로 쓰지 않는다.
2. 세로로 긴 화면은 **62mm 그림단(`.figcol`)**에 넣고 본문을 옆에 흘린다.
   가로로 넓은 화면(관리자 화면 대부분, 1.7~4.7)은 본문 폭에 그대로 놓는다.
3. 캡처가 지면에 안 맞으면 **CSS가 아니라 캡처를 고친다** — 뷰포트를 조절해 다시 찍는다.
   시작 화면(0.50 → 0.75)과 신청 화면(0.39 → 0.89)이 그렇게 고친 것이다.

여러 장을 나란히 비교하는 **띠(`.strip`)**에만 틀 높이를 맞춘다. 이것은 자르는 것이 아니라
`object-fit:contain` 레터박스이며, 캡션 줄이 어긋나는 것을 막기 위함이다.

**쪽을 억지로 채우지 않는다.** 절 끝에 여백이 남는 것은 정상이다. 채우려고 상자를 옮기기
시작하면 위의 규칙이 다시 무너진다.
