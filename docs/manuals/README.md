## 원본과 다시 만드는 법

`src/`에 HTML·CSS·화면 캡처가 들어 있다. PDF는 **크롬 헤드리스 인쇄**로 만들었다
(A4, 여백 18/16/16mm, 머리말 없음, 꼬리말에 「읽기 선별검사 · 문서명 · 2026년 9월 판」과
쪽번호). **판 표기는 표지와 꼬리말 두 곳에 있다** — 내용을 고쳐 다시 뽑을 때 둘을 함께 올릴 것.

```
src/
  style.css      두 문서가 공유하는 판면
  manual.html    관리자용
  teacher.html   선생님용
  shots/         실제 화면 캡처 34장(2배 해상도) — 설명서에 실제로 쓰는 것만 둔다
```

캡처는 **로컬 개발 서버를 띄우고 실제로 검사를 한 건 끝까지 진행하며** 찍은 것이다
(가짜 마이크 입력으로 마이크 확인을 통과시켰다). 화면이 바뀌면 그 화면만 다시 찍어
같은 파일명으로 덮으면 된다.

2026-09-28에 12장을 다시 찍으며 지킨 것(다음에 찍을 때도 같게):
- **실제 메일 주소·전화번호는 예시 값으로 바꿔 찍는다**(`teacher1@school.example.kr`, `01000000000`) —
  개발 서버는 운영 DB를 보므로 학급 코드 목록에 실제 주소가 뜬다. 화면 글자만 바꾸고 데이터는 건드리지 않는다.
- Next 개발 표시기(왼쪽 아래 「N」)를 지우고, 자동 포커스 테두리를 풀고, `scrollbar-gutter`를 끈 상태로 찍는다 —
  안 끄면 모달이 뜬 화면 오른쪽에 흰 띠가 남는다.
- 검사 화면은 **이미 있는 테스트 세션**을 로컬 키로 열어 찍고, 녹음 중 화면은 멈추지 않고 닫는다 —
  멈추면 녹음이 업로드돼 운영 DB에 기록이 생긴다.
- **시험용 이름도 예시 값으로 바꾼다**(「테스트」→「윤하준」, 99번→9번, 「신청승인테스트」→「김서연」) —
  메일 주소와 같은 방식이다. 검사 진행 화면의 아이 이름은 8/28 캡처와 같은 「강하늘」로 맞춘다.
- 2026-09-29에 6장을 다시 찍었다 — 결과지 `fig-sheet-head`·`fig-sheet-word`(위쪽에 총평 밴드가 함께 찍혀 있다)·
  `fig-sheet-legend`, 새 `fig-sheet-sentence`, 교사 결과지 `t-26`·`t-27`. 문장 읽기유창성이 어절/초가 됐고,
  `fig-sheet-legend`·`t-26`·`t-27`에는 결과보고서 전환(2026-09-28) 전 문구(「검사지 PDF」)가 남아 있었다. 예시 총점을 보이려고 두 검사(김지우·정도윤)에 읽은 시간을 **잠깐 넣고
  찍은 뒤 지웠다**(개발 서버는 운영 DB를 본다 — 넣은 값은 반드시 되돌릴 것). 헤드리스 크롬 2배 캡처, 관리자 화면은
  로컬 키로 만든 관리자 쿠키, 교사 화면은 로컬 키로 만든 결과지 링크로 열었다.
- 2026-09-30에 검사 진행 화면 4장(`t-10`·`t-14`·`t-15`·`t-16`)을 다시 찍었다 — 읽기판 안내 문장이 카드 밖으로
  나갔다. **운영 DB를 건드리지 않고** 찍었다: 실제 검사 화면 컴포넌트를 가짜 세션 상태와 가짜 양식 응답으로 띄우는
  임시 페이지를 만들어 찍고 지웠다(녹음 중 화면은 브라우저의 가짜 마이크 입력). PDF는 크롬 DevTools의 인쇄
  (`Page.printToPDF`, 꼬리말 템플릿)로 다시 뽑았고, 19쪽 글자는 이전 판과 같다.
- 검사 진행 화면은 **데스크톱 폭(뷰포트 1024 이상)**에서 찍는다. 그보다 좁으면 좁은 화면 배치로 바뀌어
  앞뒤 캡처와 모양이 달라진다(`t-15`를 880으로 찍었다가 다시 찍었다). 자르는 틀은 `t-14`·`t-16`과 같은 880×884다.

## 그림 규칙 — 자르지 말 것

**화면 캡처를 잘라서 지면에 맞추지 않는다.** 앱 화면은 세로로 긴 형태(마이크 확인 0.77 ·
낱말 읽기 1.16)라, 넓은 단에 맞추려고 높이를 지정하고 `object-position`으로 밀면
그림마다 규칙이 달라져 억지스러워진다(실제로 그렇게 만들었다가 전면 수정했다).

지켜야 할 것은 셋이다.

1. **자연 비율 그대로 둔다.** `height`·`object-position`·`overflow:hidden`을 새로 쓰지 않는다.
2. 세로로 긴 화면은 **62mm 그림단(`.figcol`)**에 넣고 본문을 옆에 흘린다.
   가로로 넓은 화면(관리자 화면 대부분, 1.7~4.7)은 본문 폭에 그대로 놓는다.
3. 캡처가 지면에 안 맞으면 **CSS가 아니라 캡처를 고친다** — 뷰포트를 조절해 다시 찍는다.
   시작 화면(0.50 → 0.75)과 신청 화면(0.39 → 0.89)이 그렇게 고친 것이다.

여러 장을 나란히 비교하는 **띠(`.strip`)**에만 틀 높이를 맞춘다. 이것은 자르는 것이 아니라
`object-fit:contain` 레터박스이며, 캡션 줄이 어긋나는 것을 막기 위함이다.

**쪽을 억지로 채우지 않는다.** 절 끝에 여백이 남는 것은 정상이다. 채우려고 상자를 옮기기
시작하면 위의 규칙이 다시 무너진다.

## 설명서에 넣지 않는 것

설명서는 **화면 사용법만** 다룬다(사용자 확정 2026-09-28). 운영 주체가 정할 것(Pass 기준 · 보존 기한 ·
3~6학년 검사지 · 도메인과 발신 메일)과 넘겨받을 계정(GitHub·Vercel·Supabase·Resend)은 관리자용 8장에
있었으나 뺐다 — 설명서에 다시 넣지 말 것. 화면에 드러나는 결과(「임시 기준 · 확정 전」 표시, 3~6학년이
1학년 양식으로 나가는 것)만 해당 장에서 설명한다.
(문의처는 사용자 확정 2026-09-22로 종결됐다 — 「담당자에게 문의」로만 안내하고 연락처 값은
앱에 두지 않는다. `lib/mail.ts` 참고.)
